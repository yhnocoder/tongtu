# 译文编译修复会话

你在一棵一次性编译树里（当前目录），内容是一篇 arXiv 论文的源码拷贝，主文件是 `zh.tex`：它是这篇论文的中文译文，由翻译后的正文回填公式、图表、参考文献等原文块得到，导言区带有 tongtu 在 precompile 阶段注入的 xeCJK 中文排版设置（标记注释 `% ---- injected by tongtu (precompile) ----` 与 `% ---- end tongtu (precompile) ----` 之间）。同一份导言区与同一批原文块在 precompile 阶段已经编译通过，所以这次失败几乎只可能出在译文正文。它在 xelatex 下编译失败，日志在树内的 `zh.log`。

你的任务：把这棵树修到 `latexmk -xelatex -interaction=nonstopmode zh.tex` 编译通过。

**你负责判断，脚本负责验证。** 会话结束后驱动器会清理编译产物并自己重新编译一次，那次编译才是唯一裁决。改完自己编一遍确认即可，不要写长总结论证自己是对的。

## 边界

1. 只在当前目录（编译树）内读写，不碰目录外的任何文件。
2. **不改动译文文字**：不删正文、不删章节、不删图表、不删段落，不改写任何句子，不把中文回译成英文。你修的是「能不能编译」，不是「译得好不好」。「编过了但内容少了」比编不过更糟。
3. **控制序列集合与原文一致是脚本硬判据**：驱动器会把 `zh.tex` 里全部 `\命令` 的名称与次数同原文逐一比对，删掉一个命令、多加一个命令都会整体判失败。因此注释掉一行优于删除一行，而且优先改命令的参数或位置，不改命令本身；确实需要去掉某条命令时，把它放进注释里而不是删除。
4. **不删除注入的 xeCJK 配置块**：它是中文排版的前提。宏包冲突时优先调整块的位置或加载顺序、修改冲突的另一方；确有必要时可以调整块内的个别命令，但中文字体设置必须保持有效。
5. 优先只改 `zh.tex`。确有必要才改树内其他文件（如 `.sty`），并在结束时单独说明。
6. 最小改动：一次改一处，编一次，看日志变化。
7. 引擎固定 xelatex，不许改用 pdflatex，也不许改动编译命令来绕过问题。
8. **Bash 跑不起来就不修**：第一条 Bash 命令若报沙箱错误、命令找不到一类与译文无关的失败，不要凭猜测改文件。立刻结束会话，说明「无法编译验证」，写出你判断的原因与建议改法，不落任何编辑。

## 诊断顺序

1. 读 `zh.log` 里第一个 `!` 开头的错误——后面的错误多半是它的连锁反应；
2. 看紧随其后的 `l.<行号>`，定位到 `zh.tex` 的对应位置；
3. 对照下面的已知模式；都不匹配就按日志现场判断。

## 已知失败模式

1. **中文标点或全角字符落进数学模式或命令参数**：译文把英文标点换成了中文标点（`，` `：` `（` `）` 等），或把 ASCII 字符换成了全角字符，而这个位置在 `$…$`、`\[…\]`、`\label{}`、`\ref{}`、`\cite{}`、`\begin{}` 一类不接受中文字符的地方，报 `Missing $ inserted`、`Undefined control sequence`、引用找不到或字体缺字。处置：把该处改回原文的 ASCII 字符，不删掉这段内容。
2. **`\pdfoutput=1`（pdftex 专有原语）**：xelatex 未定义该命令，报 `Undefined control sequence`。处置：把该行注释掉（行首加 `%`）。
3. **图引用带显式扩展名但文件缺失**：如 `\includegraphics{fig.eps}` 而树里只有 `fig.pdf`，报 `File 'fig.eps' not found`。处置：确认同主干、其他扩展名的图文件确实存在，然后把引用改成存在的扩展名（或去掉扩展名交给 LaTeX 按默认顺序找）。
4. **宏包与 xeCJK / fontspec 冲突**：如重复定义字体命令、`inputenc`/`fontenc` 与 XeTeX 引擎不兼容。处置：注释掉 `\usepackage[utf8]{inputenc}` 一类在 xelatex 下多余的行；其余冲突按日志逐个处理。

## 结束时

用一段话说清楚：改了哪些文件的哪几处、为什么、你自己最后一次编译的结论。改了 `zh.tex` 之外的文件要单独点名。不要粘贴命令输出，transcript 已由驱动器落盘。
