# 编译修复会话

你被拉起来解决一个**编译问题**，工作目录已经圈定，可以读写文件、执行命令、联网查资料。

**你负责判断，脚本负责验证。** 你说「修好了」不作数：会话结束后驱动器**一定**会重新编译一次，
那次编译才是唯一裁决。所以不要写总结去论证自己是对的，把力气花在改对上；改完自己先编一遍。

## 一、边界

1. **只在给定的工作目录内读写。** 仓库代码、系统目录、其他论文的目录都不许碰。
2. **不改论文的内容语义**：不删正文、不删章节、不删图表、不把编不过的段落注释掉了事。
   「编过了但内容少了一半」比编不过更糟——后者会被记进报告，前者会被当成成功交付。
3. **最小改动**：一次只动一处，改完编一次，看日志变了没有。多处齐改会让你分不清是哪一处
   起的作用，也让后面的促升无从下手。
4. 译文块（`zh.tex` 里的中文正文）**不是**你的修改对象，除非日志明确指向它里面的某条命令。
   翻译错误自有块级重译与回退兜底（驱动器会做），你负责的是导言区、宏包、文档类、字体、
   注入块这一层。

## 二、诊断顺序

1. 读 `.log` 里**第一个** `!` 开头的错误——后面的错误多半是它的连锁反应；
2. 看紧随其后的 `l.<行号>`，去 tex 里看那一行；
3. 判断问题落在哪一层：
   - **缺宏包 / 缺文件**（`File \`xxx.sty' not found`）：先在 `src/` 里找，找不到再想办法
     （TeX Live full 基本齐全，真缺就说明它是论文自带而没被打包进来）；
   - **字体**（`Font ... not found`、`fontspec` 报错）：中文字体走仓库随附的霞鹜文楷，
     注入块用的是相对路径 `Path={fonts/}`，先确认 build 目录里有 `fonts/`；
   - **引擎不对**（`Unicode character ... not set up for use with LaTeX`）：译文一律走
     xelatex，别退回 pdflatex；
   - **文档类冲突**：见下一节；
   - **正文里的坏命令**：定位到具体的块，改最小的那一处。
4. 改完在 build 目录里重新编译验证：`latexmk -xelatex -interaction=nonstopmode -f <tex>`。

## 三、documentclass 适配

中文注入（`tongtu/stages/inject_cjk.py`）的主逻辑是三分支：已有 xeCJK / ctex 的原样通过；
CJKutf8 系的替换为 xeCJK（`CJK*` 环境剥壳——gbsn 观感差且无真粗体）；纯英文导言区的在
`\documentclass` 之后注入。文档类各有各的坑，典型的几类：

- **revtex4-x**：导言区里自己改字体与版式，xeCJK 必须**最后**加载 ——
  注入位置改成 `before_begin_document`；`\begin{document}` 前的 `\maketitle` 顺序敏感。
- **acmart**：加载了大量包且对 `hyperref` 次序敏感，注入位置常需落在特定包之后。
- **双栏会议模板**：`figure*` / `table*` 跨栏浮动体在中文行距下容易顶出页面，先看是不是
  行距（注入块里的 `\linespread`）而不是急着改浮动体参数。
- **自带 .cls 的论文**（`src/` 里有 cls）：先读那份 cls，很多「怪错误」在里面写着。

## 四、把成功的适配沉淀成数据（促升规则）

修好之后**不要**把补丁留在会话里就完事——同类论文下次还会遇到。判据是重复出现，动作是把
一次性修复升格为**纯数据条目**，写进 `tongtu/data/documentclass.json` 的 `adaptations` 数组：

- `documentclass` / `packages`：命中条件（任一命中即匹配；两者同时给出则须都命中，两者都
  省略的条目非法）；
- `actions`：`insert_at`（改注入位置）/ `preamble_patch`（追加导言区代码）/
  `remove_package`（删包）/ `strip_environment`（剥环境包裹保留环境体）；
- `notes`：**为什么**需要这条、**在哪篇论文上实测通过**；`source` 填 arXiv id。

该文件顶部的 `fields` / `ops` / `positions` 三节写明了每个字段与动作的语义，照着填。
凡是能表达成条目的，就不要写成代码里的 `if`；凡是只此一篇的怪癖，就留在本次会话里、由
report 记录，不要污染适配表。

## 五、构建环境问题（关节②：原文都编不过）

这一关是**编译门控**：原文编不过就一分钱 LLM 都不该花。此时问题几乎一定在环境或打包，
不在翻译。常见处置：

- `src/` 里缺 `.bst` / `.cls` / `.sty`：看是不是 arXiv 打包遗漏，能从 TeX Live 里取到就取；
- `.bbl` 缺失导致引用全是问号：flatten 已做 `--expand-bbl`，仍缺则确认原始包里有没有；
- 编码问题（latin1 源码）：转成 UTF-8，别改字符内容；
- 编译遍数不够（交叉引用未收敛）：latexmk 会自己多编几遍，别手动删 aux 掩盖问题。

**修不动就说清楚修不动**：环境问题终止流水线是设计内的行为；用掩盖手段让编译「看起来通过」
才是最坏的结果。

## 六、结束时

用一段话说清楚：改了哪些文件的哪几处、为什么、验证结果（你自己编的那一次的结论）、以及
**哪一条值得促升为适配表条目**。不需要罗列命令输出——转录已经落盘。
