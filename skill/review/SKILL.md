# 全文审校会话

你在一棵隔离现场里（当前目录），内容是一篇 arXiv 论文的英文原文与它的中文译文，按 chunk 逐文件对应：

- `chunks/cNNN.tex`：英文原文（已掩码，`⟦BLK-n⟧` / `⟦CAP-n⟧` 是占位符）。只读参考，不要改。
- `reviewed/cNNN.tex`：对应的中文译文。你要改的就是这些文件。
- `brief.json`：本篇的摘要、术语表、章节标题树，以及每个 chunk 的统计（`chunks` 数组里按 `id` 索引）。只读参考。

全文是逐块并行翻译出来的，每块翻译时看不到别块的译文。你是第一个通读全篇的人，任务也由此而来。

**Bash 可以自由使用**（会话在沙箱里，写范围就是当前目录，也没有网络）。文件对逐个 Read 来读；机械的比对与批量检查交给命令，例如找内容相同的文件：

```
for f in chunks/*.tex; do cmp -s "$f" "reviewed/$(basename "$f")" && echo "内容相同：$(basename "$f")"; done
```

## 任务顺序

**第一步：补翻回退件。** 有的 chunk 翻译失败，退回了英文原文。识别方式：`reviewed/cNNN.tex` 与 `chunks/cNNN.tex` 内容完全相同（上面的 `cmp` 一条命令就能列出来），且 `brief.json` 里该 chunk 的 `translatable_chars` 大于 0。把这些块按下面的翻译规则译成中文，术语依 `brief.json` 的术语表，语气与相邻 chunk 的既有译文保持一致。

（`translatable_chars` 为 0 的 chunk 整块都是占位符与命令，没有可译文本，原样相同是正常的，不要动。）

**第二步：通读修订。** 通读全部 `chunks/` 与 `reviewed/`，只改这四类问题：

1. 术语与 `brief.json` 的术语表不一致。**术语表怎么写就怎么用，包括中英文之间有没有空格**：术语表写的是「多token预测」，译文写成「多 token 预测」也算不一致，要改回「多token预测」，即使你觉得该有空格；反过来，术语表写「多 token 预测」而译文写「多token预测」，同样要改回术语表的写法。领域惯用英文（`token`、`kernel`、`KV cache` 一类）被译成中文（「令牌」「核」）也算术语不一致，改回英文。
2. 同一概念在不同 chunk 里译法不同；
3. 记号、人称与称呼不统一（例如同一符号一处译名一处原文，或「我们」与「本文」混用）；
4. 明显误译：与原文意思不符、数值或方向弄反、否定丢失；以及漏译：原文里的全称、修饰语、从句在译文里没有对应（`rectified-linear (ReLU)` 只译成 `ReLU`、`Stanford Question-Answering Dataset (SQuAD)` 只剩 `SQuAD`），要补回。

**不重写已经通顺的句子，不做风格性改写。** 只是「换个说法更好听」不是修订理由；改一处要能说出它属于上面哪一类。

## 规则

1. 只改 `reviewed/` 下的文件。不新建文件、不删除文件、不改文件名，不改 `chunks/` 与 `brief.json`。
2. 每改完一个文件，立即跑

   ```
   python3 -I .claude/skills/review/validate.py chunks/cNNN.tex reviewed/cNNN.tex
   ```

   四层机械校验（占位符 multiset / 控制序列 multiset / 花括号与 `$` `%` / 段落数）任何一层不过就接着改这个文件，直到通过再看下一个文件。不要攒到最后一起校验：回退按整块算，错发现得越晚，越可能连着这一块的其他修订一起丢。
3. 校验是最终裁决：会话结束后驱动器对每个文件重跑同一份校验，不过的文件整个回退成你改动之前的版本，你在那一块做的修订会全部丢掉。
4. 块首尾的空白由驱动器保管，不必操心，也不要特意补空行。
5. 只在当前目录内读写，不碰目录外的任何文件。

## 翻译与修订时的格式规则

与逐块翻译时同一套，每条都对应一层机械校验：

1. **占位符**：`⟦BLK-n⟧` 是不透明占位符（被掩掉的公式、图表、代码、整段注释），原样保留、逐个保留、顺序不变，不翻译、不改写、不增删、不拆合。`⟦CAP-n⟧` 开头的行是图表标题 / 题目 / 摘要的可译文本槽位：保留行首 token，翻译其后的文本，结果仍是一行，行内的 ` \par ` 原样保留。`⟦` 与 `⟧` 除完整占位符外不许出现。
2. **不可变元素逐字保留**：行内公式 `$...$`、行间数学 `\[...\]` 与 `$$...$$`；`\cite/\citep/\citet{...}`、`\ref/\eqref/\Cref{...}`、`\label{...}`；一切 `\命令`（含星号变体与自定义宏）及其可选参数 `[...]`；不间断空格 `~`；转义字符 `\%` `\&` `\#` `\_` `\$`；连字符 `--` `---`。公式内部一个字符都不能改，`$k^{th}$` 照留。裸 `%` 一个都不许出现，要写百分号只能写 `\%`。
3. **只许保留，不许新增**：控制序列走 multiset 比对，凭空多一个与凭空少一个同样不过。原文写单词的不要改写成命令（`10 percent` 译「百分之十」，不是 `10\%`），原文写符号的照旧保留。
4. **命令参数**：命令本身保留，参数里的文本翻译，`\section{Introduction}` → `\section{引言}`。命令名、花括号数量、嵌套层级不变。
5. **段落结构**：原文几段，译文就几段。空行是段落边界，不合并、不拆分、不跳过、不新增；段内的单换行位置也照抄。
6. **术语**：`brief.json` 术语表里有的，**照它的写法原样使用**——包括其中英文之间有没有空格、用不用括号、大小写，一个字符都不要调整。表里没有覆盖的地方才按下一条的通用排版规则处理。**术语表的一条只约束这一整条术语，不要把其中的某个词拆出来当全篇规则**：术语表有「mixed RL training → 混合强化学习训练」，不等于单独出现的 `RL` 也要译成「强化学习」——`RL` 在 `do_not_translate` 里，单独出现时保留原文。单独出现的词以 `do_not_translate` 与「领域惯用英文保留原文」为准。模型 / 系统 / 基准 / 数据集 / 机构名、人名与领域惯用英文（token、kernel、KV cache 之类）保留原文；数字、单位、变量名不译；`70K`、`14.8T` 这类数量级后缀原样保留，不换算。
7. **中文是中文的句子**：被动句改主动，长定语拆开，冠词与代词该省则省，「对 X 进行 Y」改成「Y X」。正文用全角标点；术语表没写到的地方，中英文之间留一个空格（`~` 前不留）。不加译注，不擅自修正原文的错误，不增删信息。

## 结束时

用一段话说清楚：改了哪些文件、各属于上面四类问题里的哪一类、补翻了哪几块。不要粘贴命令输出，transcript 已由驱动器落盘。
