# 术语提议

给定一篇论文的摘要、章节标题树与全文掩码文本，挑出**本篇反复出现、译法需要全文统一**的词，
给出简体中文译法。论文随后被切成若干块分别翻译，你提的这份词表会进每一块的提示词，
用来保证同一个词在各块里译法一致。

## 挑什么

- **领域术语**：本篇讨论的方法、结构、指标、任务的名字，译法在中文文献里已有惯例的按惯例。
- **本文自造的名词**：作者为本文提出的方法、模块、数据集、指标命名的词。
- **模型名、方法名、系统名**：出现在正文里、承担固定含义的名字。

放进 `do_not_translate` 的是**应当保留原文**的词：专有名词、缩写、软件与库的名字、
模型与产品的名字，以及译成中文反而不便识别的记号。**本篇出现的领域惯用英文词也放进去**——
中文文献里通常直接写英文的那些词（`token`、`kernel`、`KV cache`、`logits`、`prompt` 一类），
即使它们在任何论文里都这么处理、不需要本篇专门统一：写进来，后面的阶段才能机械检查译文有没有把它们译成中文。正文里的 `Eq.`、`Fig.`、`Table`、`Sec.` 一类引用缩写**不要**放进去，它们在译文里要译成「式」「图」「表」「节」。

## 不挑什么

- 通用英文词与日常表达（`method`、`result`、`however`、`significant`）。
- 有惯用中文译法的常用词（`benchmark`、`baseline`、`bias`、`learning rate`）：它们在任何论文里都这么译，不需要本篇统一。惯用英文的常用词不在此列，按上一节放进 `do_not_translate`。
- 只出现一两次、译法不影响全篇一致性的词。
- 数学符号、公式与占位符 `⟦BLK-n⟧` / `⟦CAP-n⟧` 里的内容。

## 怎么写

- 每个词按**原文里的写法**给出，大小写照抄；缩写与它的全称是两条，各写各的。
- 复数不必单列：`LLM` 一条即可覆盖 `LLMs`。
- 译法写简体中文，一个词只给一个译法。
- 领域里惯用英文的词（`token`、`kernel`、`KV cache`、`logits` 一类）在译法里保留英文，不译成「令牌」「内核」；出现在复合术语里也一样：`fine-grained token selection` 译作「细粒度 token 选择」，不是「细粒度令牌选择」。
- 译法里夹英文或数字时，中文与英文、数字之间留一个空格：`细粒度 token 选择`、`混合 RL 训练`、`KL 散度`。
- 同一个词不要同时出现在 `terms` 与 `do_not_translate`。
- 放进 `do_not_translate` 的词若又出现在某条复合术语里，该术语的译法必须原样保留这个词：`RL` 不译，那么 `mixed RL training` 的译法写「混合 RL 训练」，不写「混合强化学习训练」。
- 只输出符合 schema 的 JSON，不写解释、不写 Markdown。
