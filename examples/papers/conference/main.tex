\begin{abstract}
We describe a scheduling framework that assigns synthetic tasks to synthetic
workers.  The framework has three components because three fits the column
width, and each component is described in one subsection.  We evaluate the
framework on a workload we invented and report an improvement over a baseline
we also invented.  The paper is a test fixture; it contains no measurements.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Scheduling papers are easy to write and hard to finish.  This one is easy to
finish because it schedules nothing.  We fix a set of tasks
$\tasks = \{\tau_{1}, \dots, \tau_{m}\}$ and a set of workers
$\workers$, and we write $\sched{\tau}$ for the worker to which the task
$\tau$ is assigned.

The problem is stated in Section~\ref{sec:framework}, the numbers are given in
Section~\ref{sec:evaluation}, and the bound is proved in
Appendix~\ref{app:bound}.  Prior work is cited in the usual quantity
\cite{sched2020,queue2018}, and about $10\%$ of it is relevant.

\section{Framework}
\label{sec:framework}

\subsection{Cost model}
\label{sec:cost}

Each task $\tau$ carries a weight $w(\tau) > 0$ and a deadline $d(\tau)$.  The
cost of an assignment $\sched{\cdot}$ is the largest load over workers,

\begin{equation}
  \label{eq:cost}
  C(\sched{\cdot}) = \max_{u \in \workers}
                     \sum_{\tau : \sched{\tau} = u} w(\tau) ,
\end{equation}

which is the definition everyone uses and which we adopt without discussion.

\subsection{Assignment rule}
\label{sec:rule}

The rule is greedy: sort the tasks by weight and place each on the currently
least loaded worker.  Two properties follow immediately, and neither is
surprising:

\begin{itemize}
  \item the rule is deterministic once ties are broken by index;
  \item its running time is dominated by the sort.
\end{itemize}

\begin{sidenote}
The rule above is the textbook one.  It appears here so that the fixture

\end{sidenote}

\subsection{Results}
\label{sec:results}

Against the baseline of \cite{queue2018} the greedy rule reduces the cost of
\eqref{eq:cost} by an amount we chose in advance.\footnote{Choosing the
improvement in advance saves a considerable amount of experimentation.}  The
improvement is stable under every perturbation we did not try.

\begin{enumerate}
  \item Interactive tasks meet their deadlines by construction.
  \item Batch tasks meet theirs on average, where the average is over the runs
        in which they do.
  \item Bulk tasks have no deadline and therefore never miss one.
\end{enumerate}

\section{Proof of the Scheduling Bound}
\label{app:bound}

Let $C^{\star}$ denote the optimal cost.  Because the greedy rule places each
task on a least loaded worker, the load of that worker before the placement is
at most the average load, and the bound

\begin{equation}
  \label{eq:bound}
  C(\sched{\cdot}) \le \left( 2 - \frac{1}{|\workers|} \right) C^{\star}
\end{equation}

follows by the standard argument, which we omit for reasons of space \& taste.
Note that \eqref{eq:bound} is tight for the instance labelled \#1 in
Table~\ref{tab:workload}, or would be if that table described instances.
