# 通途（Tongtu）架构文档

> 状态：草案 v0.7（2026-08-12）。本文是通途引擎的**工程级**权威文档。系统级设计（仓库边界、build/read 路径分离、产物契约的用途、分期计划）见文枢设计蓝图（内部工作区 `wenshu/docs/BLUEPRINT.md`，开源前其引擎相关部分将内化为本文自足内容）；冲突时蓝图优先，或先改蓝图。
>
> 产物契约由通途拥有：字段级定义以本文 §7 与 `docs/schemas/` 为准，蓝图 §4.3 是摘要。

## 1. 定位与范围

通途是基于 LaTeX 源码的 arXiv 论文英译中引擎：确定性流水线 + coding agent 翻译 + 机械校验 + 编译回环，产出保真排版的中文 PDF 与结构化索引。仓库结构见 [README](../README.md)（`scripts/` / `skill/` / `agent/` / `docker/` / `fallback/` / `docs/`）。

本文回答的问题：控制流归谁、返工与缓存怎么建模、接口签名长什么样、运行在哪、怎么测。

## 2. 设计原则

1. **agent 负责判断，脚本负责验证**（继承 v2）。翻译、修编译错、适配奇怪 documentclass 交给 agent；正确性只认校验脚本全绿与编译通过，agent 的「我检查过了」无效力。
2. **流水线是增量构建系统**。每阶段输出 = 输入（源码 + 配置 + 术语表 + prompt 版本 + 模型）的纯函数；输入未变不重算。「返工」不是控制流回跳，而是**失效 + 重算受影响子图**，粒度为块——阶段级返工这个概念被设计消灭。
3. **确定性骨架 + agent 关节**。控制流永远在脚本手里；agent 只在固定关节被拉起，关节内完全自由（多轮、跑命令、联网），出口判据永远是机械校验。一次性问题由 agent 关节内现场解决、只记入 report；复发问题**促升**为确定性代码或 SKILL 经验条目，判据是 report.json 的干预统计。编排器不积累一次性 hack。
4. **构建状态也是数据**（「会话 = 数据」的推广）。增量重翻所需状态（翻译记忆）随产物包走，可在任何新环境续跑；工作目录的 build 区随时可丢。
5. **不感知云**。通途只读写本地工作目录、stdout 与退出码；R2 上传、容器调度、任务队列全部是 wenshu 侧职责。接口形态永远是「文件 + CLI 约定」。

## 3. 流水线

**所有阶段都由脚本驱动，不存在「agent 驱动的阶段」。** 表中「agent 介入点」的含义是：该阶段的脚本在特定触发条件下拉起一次有界的 agent 调用（§9 两原语之一），拿回结果后仍由脚本校验与推进，控制流从不移交。「出口判据」一列是每个阶段「谁说了算」——凡有 agent 介入的阶段，出口判据依然是机械的。

| 阶段 | 确定性骨架 | agent 介入点（触发 → 授权） | 出口判据 |
|---|---|---|---|
| fetch | e-print 下载解包；PDF-only 检测 | — | 源码树落 `src/`（PDF-only → 报错标记降级路线） |
| flatten | latexpand 展开 | 主文件歧义 → 判定主文件 ① | 单文件 `flat.tex` |
| baseline | latexmk 原样编译原文，隔离环境问题 | 失败 → workdir 内修构建环境 ② | 原文 PDF 编译通过；仍失败 → 终止（环境问题，非翻译问题） |
| mask | LaTeX 词法解析 → 环境完备枚举 → 按分类表三级掩码 → **往返自检**（§3.1） | 未知环境 → 散文/重环境分类 ③；不确定 → 保守整块掩码 | `unmask(mask(x)) == x` 恒等；`blocks.json` 完整 |
| survey | 通读调度（输入 = masked.tex 的**选择性回填视图**：数学类块回填原文，表格/图/代码保持占位符，剔除附录与参考文献）；输入术语表三层合并；产物 JSON 结构校验 | 全文通读 → 纲要（brief）生成 + 术语预扫与新词译法决策 ④（`complete`） | `brief.json` 与结构化术语表通过 schema 校验 |
| chunk | 章节树优先分块：`\section` 为首选单元，小节聚合至软目标 token 数，超大节在小节/段落边界下分至硬上限；绝不切入环境或段落内部 | — | 块清单（每块 = 完整段落序列） |
| translate | 块循环、**上下文组装（brief + 命中术语 + 邻域原文）**、缓存查询、重试计数、validate 内环 | 单块翻译（`complete` 原语）⑤ | validate 全绿（占位符完整性 / 控制序列 multiset / 段落数） |
| compile | unmask 回填 → inject_cjk（xeCJK + 字体链，查 documentclass 适配表）→ latexmk -xelatex **回环**；失败分诊：坏段（块 → 段落两级二分）vs 全局问题；回退控制 | 坏段 → 重译一次（复用⑤）；未知 documentclass、导言区、宏冲突等全局问题 → 适配与修复会话 ⑥（可改注入配置与导言区，改完直接回环重编译） | `zh.pdf` 编译通过（坏段回退原文保底，记 report——保证永远出 PDF） |
| figures | 源码包内 EPS/PDF/位图 → PNG 预渲染；caption 与引用段落收集。**仅依赖 `src/`，与翻译轨并行** | — | `figures/*.png` + 元数据齐全 |
| export | 产物包组装；anchors 三来源合成；检验页生成；schema 自校验 | — | 契约 schema 校验通过 |

六个关节（主文件、构建环境、环境分类、通读与术语、翻译、适配与修复）覆盖论文多样性的全部长尾；**阶段图本身对所有论文不变**——连 PDF-only 也只是顶层分支到降级路线，不是动态重排。

survey 是掩码与分块的解毒剂：掩码 + 分块后模型只见「挖了洞的一小段」，跨章节不一致是结构性风险，须以全局上下文补偿。survey 一次通读产出两样——`brief.json`（原文 abstract 照录 + 章节结构树与每节摘要、记号与命名约定、文风基调；abstract 用**原文而非译文**，避免全部块对摘要译文形成级联依赖）与术语预扫决策。它的通读输入是 **masked.tex 的选择性回填视图**：blocks.json 记有每块类型，unmask 按类型参数化回填——数学类块（equation/align 等）回填原文，表格/图/tikz/算法/verbatim 保持占位符，再剔除附录与参考文献。取舍依据：行间公式是记号定义的所在地，brief 的「记号与命名约定」正需要它们；表格体/图体对通读是纯噪音且是 token 大头（行内公式与 caption 在 masked.tex 中本就可见）。正文规模因此可控，一次通读即可、不做 map-reduce；附录不进通读但仍正常翻译。survey 与 mask 的分类关节是流水线最早的 LLM 支出，均在 baseline 编译门控之后——编译不过的论文不花一分钱。**块间一致性靠稳定共享上下文，不靠链式传递译文**：每块翻译的上下文 = brief + 命中术语 + 邻域**原文**（章节级分块后即前节末段与后节首段），刻意不传入前块**译文**——否则缓存失效沿块链级联、并行翻译退化为串行；一致性损失由 brief 与术语表补偿。

chunk 的粒度哲学：**翻译单元要大，定位与回退单元要小，两者由段落数比对解耦**。翻译以章节为首选单元——节内衔接是翻译质量的主要来源，节间衔接在论文语篇中天然很弱（每节自起炉灶），节间真正要一致的只有术语与记号，那是 glossary 与 brief 的职责。粒度约束来自**输出**而非输入：译文长度 ≈ 原文，超长单次生成有漂移、偷懒与输出上限三重风险（「翻到第 20 节简译」在单次调用内同样成立），故设软目标（小节聚合）与硬上限（超大节下分）。而 validate 强制原译段落一一对应，任何块都可确定性拆回段落对——编译失败的二分下钻到段落、回退原文的单位是段落而非整节，**大块化不恶化退化粒度**。

figures 独立成阶段的原因是增量模型：它只依赖 `src/`，独立 manifest 意味着翻译侧任何返工都不触发图片重渲染。「PDF/EPS 图无法用于产物」是 v1 markdown 路线的遗留问题意识——对 xelatex 而言 PDF 图是原生输入，EPS 走 epstopdf 链自动转换，编译侧零处理；预渲染 PNG 只为 AI 读图（视觉模型吃位图）与检验页/索引服务。

### 3.1 mask 的确定性从哪来

mask 是最容易被质疑「放之四海而皆准」的阶段。它的可靠性不建立在解析规则完美上，而建立在四层机制上：

1. **解析而非正则**。LaTeX 的花括号嵌套与 verbatim 语义超出正则表达能力，mask 基于 LaTeX 词法解析器做环境与分组识别（解析器选型见附录 B；v2 实现迁移时审计）。
2. **枚举完备，分类保守**。文档中出现的全部 `\begin{X}` 环境名可被**完备枚举**——这一步不需要任何先验知识。分类（散文 / 重环境）查数据文件形式的分类表，`\newtheorem` 等声明经解析自动归类其定义的环境；表中没有的环境走关节③由 agent 判断，agent 不确定或不可用则默认**保守整块掩码**——代价只是该块不被翻译并记入 report，绝不损坏。agent 的分类结论按促升规则（§2.3）沉淀为分类表条目。
3. **运行时往返自检**。mask 完成后立即 unmask 并与原文 diff，恒等才放行——任何解析缺陷在花第一分钱 LLM 调用之前当场暴露。「四海皆准」的保证不是解析器无缺陷，而是**缺陷在每篇论文上都当场可测**。
4. **外层双保险**。即便有漏网，validate 的控制序列 multiset 比对与编译回环仍会拦截，最终兜底是回退原文。

**不设强制的「agent 复核掩码结果」步骤**：那是「自我验证不可信」的变体（复核通过的效力等同于「我检查过了」），且逐篇付费；agent 只在环境分类这个真判断点介入。

**开发者兜底**：流水线终止级的疑难杂症，零期的处理方式是开发者对着 workdir 开交互式 agent 会话排查——这是开发者回路，不做成产品功能。

## 4. 增量模型与缓存

**阶段级**：每阶段完成后在 `build/manifests/<stage>.json` 记录输入 hash 集与输出清单。重跑时输入未变 → 跳过。断点续跑 = 原样重跑同一条命令。

**块级**（唯一昂贵处，即翻译缓存）：

```
key = hash( norm(chunk_src)              # 空白规范化后的块源码
          + neighbor_src                # 提示词携带的邻域原文（前后各若干段，随源码固定）
          + relevant_terms(chunk)       # glossary 术语条目中在本块命中的子集（排序）
          + brief_hash                  # survey 产出的全文纲要内容 hash
          + style_version               # 全局文风规则版本号
          + prompt_version              # SKILL / prompt 资产版本
          + model_id )
```

术语表拆两半参与 key：**术语条目**按块内命中计入——改一个词只失效含它的块；**全局文风规则**单列 `style_version`——bump 即全量重翻，是显式有意的行为。

| 返工触发 | 失效范围 | 路径 |
|---|---|---|
| validate 失败 | 单块 | translate 内环重试 |
| 编译失败 | 块内段落级二分定位出的坏段 | 坏段重译一次 → 再失败仅该段回退原文 |
| 编辑某术语条目 | 命中该术语的块 | 增量重翻 → 重编译 |
| 改文风规则 / 升级 prompt / 换模型 | 全部块 | 显式全量重翻 |
| 重跑 survey 且 brief 内容变化 | 全部块 | 显式操作（survey 自身按 manifest 缓存，输入未变不重跑，brief 不会意外漂移） |
| 改流水线代码 | 对应阶段起的下游 | manifest 判定重算 |

**figures 逐图缓存**：以源图文件 hash 为 key，与翻译状态完全无关——翻译侧任何返工都不触发重渲染。

**不做跨论文全局缓存**：块源码跨论文几乎不复用，去重价值≈0。缓存住在该论文的工作目录；权威翻译记忆是产物包中的 `chunks.json`（见 §7），`build/` 整体删除不丢失任何昂贵成果。

## 5. 工作目录布局

```
~/.local/share/tongtu/<arxiv_id>/     # $TONGTU_HOME / --workdir 覆盖；云容器内为 /work
├── src/          # e-print 原始解包，只读不改
├── build/        # 流水线工作区，可整体删除（重建时从 out/chunks.json 命中缓存）
│   ├── flat.tex  baseline/  masked.tex  chunks/  zh/
│   └── manifests/
├── out/          # 产物包（§7 契约文件）
└── logs/         # agent 会话转录、编译日志（审计与促升判据的数据来源）
```

## 6. CLI 命令面（草案）

```
tongtu run <arxiv-id | dir>  [--glossary FILE]...  [--workdir DIR]  [--force]  [--json]
tongtu retranslate <id>  (--chunks c012,c045 | --term WORD | --all)
tongtu stage <name> <id>          # 单阶段入口，调试用
tongtu doctor                     # 检查 xelatex/latexmk/latexpand/字体，缺啥说啥
tongtu preview <id>               # 打开检验页
```

- `run` 幂等：重复执行按 manifest 与翻译缓存跳过已完成部分；`--force` 无视缓存全量重跑。
- `--json`：向 stdout 输出机器可读事件流（阶段起止、块进度、最终结果）——这是 wenshu 容器调度侧消费的 CLI 调用约定的一部分，schema 一期前冻结。
- 退出码：0 = 产物包完整产出（含有回退块的情形，详情在 report.json）；非 0 = 未能出包。

## 7. 产物契约（通途拥有，每篇论文一个产物包）

| 产物 | 说明 |
|---|---|
| `zh.tex` | 翻译后完整 LaTeX 源（自包含 pack） |
| `zh.pdf` | xelatex 编译产物，主阅读格式 |
| `blocks.json` | 每个重环境的类型、label、原始 TeX、源码位置 |
| `anchors.json` | 交互地图：公式/图/表/章节在 PDF 中的页码与矩形区域 |
| `chunks.json` | **翻译记忆**（新增）：每块 `源码hash → 译文 + 模型/prompt 版本/相关术语快照/状态(translated\|fallback)`，增量重翻的全部状态 |
| `brief.json` | **全文纲要**（新增）：论文原文 abstract **照录**（不生成）+ 章节结构树与每节摘要、记号与命名约定、文风基调。首要用途是逐块翻译的全局上下文；随包分发后 read path 的 AI 摘要与会话预热可直接复用 |
| `figures/*.png` + 元数据 | 源码包内图源（EPS/PDF/位图）预渲染 PNG：长边按视觉模型有效上限（≈1568px）逐图定 DPI，位图源只缩不放大；元数据含 caption、全文引用段落清单与 `format` 字段（预留 WebP 等扩展） |
| `glossary.json` | 本篇术语**决策表**（含 agent 新决策） |
| `report.json` | 回退块、校验统计、编译警告、agent 关节干预记录、契约版本号 |
| `report.html` | **静态检验页**（新增，见 §11） |
| `zh.synctex.gz` | 源码行 ↔ PDF 坐标映射 |

各 JSON 产物以 `docs/schemas/*.schema.json` 为字段级权威定义，CI 对产物做 schema 校验。契约变更需先改 schema 并 bump `contract_version`。

## 8. 术语表

- **预扫、合并与新词决策统一发生在 survey 阶段**（§3），与全文纲要在同一次通读中完成。
- **三层合并**，后者覆盖前者：全局 `~/.config/tongtu/glossary.json`（XDG，`$XDG_CONFIG_HOME` 覆盖）→ 论文目录内输入表 `<workdir>/glossary.json`（与 `src/`/`build/`/`out/`/`logs/` 同级，**不放进 `src/`**——那是只读的 e-print 树，混入会污染 fetch 的树 hash）→ `--glossary` 命令行（可多次，靠后的优先）。合并语义：`terms` 条目级覆盖（同名后者胜）、`do_not_translate` 取并集、`style` 逐字段覆盖。
- **输入表**（用户可编辑）与**决策表**（产物 `glossary.json`，本篇实际生效决策）分离；用户条目优先于 agent 决策。
- 结构三段：不译清单 / 术语唯一译法 / 文风约定（`style_version` 所在，含译者注开关）。
- 云上传入：wenshu 把 R2 中的表落成文件递给容器——仍是「文件 + CLI」，不新增接口形态。

## 9. agent 适配层（`agent/`）

两个原语，运行时可插拔（选型未定，见蓝图 §4.4）：

```
complete(prompt, text, model) -> text
    # 无状态判断：逐块翻译、术语决策。可由纯 API 调用或 agent 运行时实现。

session(prompt, workdir, model, budget) -> {done, transcript_path}
    # 有状态修复：修构建环境、修编译错、documentclass 适配。
    # 要求：headless 拉起、读写 workdir、执行命令、联网、可指定模型。
```

- `session` 的 `done` 只表示会话结束；**裁决权在事后的校验脚本与编译**，永不信 agent 自述。
- 所有会话转录落 `logs/`——既是审计，也是促升规则（§2.3）的数据来源。
- **MockAgent**：`complete` 恒等返回、`session` 为 no-op——CI 编译层（§12）的钥匙。

## 10. 运行环境

**本地原生是主形态**：CLI 只要求 PATH 中有 xelatex / latexmk / latexpand 及字体（探测链 Hiragino → Noto Sans CJK → 霞鹜文楷）。macOS 上 docker 经由虚拟机、bind mount IO 慢，开发迭代原生显著更快；`tongtu doctor` 弥补环境差异。

**docker 承担三个角色，均不是 CLI 运行前提**：

1. **云部署单元**：Cloudflare Containers 只认镜像；
2. **CI 环境**：TeX 发行版差异是真实的坑，CI 一律用镜像；
3. **参考环境**：「编译通过」的权威裁决环境——bug 报告与产物合规以镜像内复现为准。

镜像双层构建：TeX Live full 基底层（几乎不变，CI 层缓存常年命中）+ 通途代码层；GHCR 发布，git tag 即版本，wenshu 按 tag 引用。

已知 trade-off：本地原生运行没有容器对持 bash 修复 agent 的沙箱隔离，与本地日常运行 coding agent 同一信任姿态，文档言明；将来可为修复 agent 增加受限权限选项。

## 11. 静态检验页（`report.html`）

- **内容**：PDF.js 渲染 `zh.pdf`；anchors 热区画为半透明覆盖层，点击显示 `blocks.json` 中的原始 TeX；侧栏列 `report.json` 回退块与校验统计；figures PNG 索引。
- **完全静态自包含**：只消费产物包内文件，PDF.js vendor 随包，无网络可开（双击或 `tongtu preview`）。
- **三重角色**：产物契约的第一个消费者（文枢动工前先在此暴露契约缺陷）；零期验收工具（anchors 热区不画出来无法验收）；开源 README 的 demo。
- **红线**：凡需要服务端或 LLM 调用的功能一律归文枢，本页永不添加。

## 12. 测试与 CI/CD

测试金字塔，按成本分三层：

1. **文本层**（秒级；无 TeX、无 LLM）：mask / unmask / validate / chunk 皆为纯文本变换，golden-file 测试打底；外加 mask/unmask 往返恒等的性质测试——同一自检在生产环境对每篇论文运行时也会执行（§3.1）。正确性的大头在这层。**PR 门禁。**
2. **编译层**（分钟级；有 TeX、无 LLM）：**恒等翻译 e2e**——MockAgent 原样返回源文，三篇 fixture 论文全流水线跑到底，产出 PDF + anchors 并通过 schema 校验。零 LLM 成本覆盖掩码/注入/编译回环/导出/索引全链路。**PR 门禁。**
   注意：恒等译文不含中文，xeCJK 断行等中文路径盖不到——需补「伪翻译」变体（每块注入固定中文句）或一篇中文 fixture（见附录 B）。
3. **LLM 层**（**手动触发**；限预算）：真模型跑 1–3 篇，report.json 统计入质量看板。**是质量监控，不是门禁**——模型抖动不得卡 PR。暂不设 nightly（纯烧钱）；待朝晖（hot-paper 自动发现）接入后，挂在其自动入队流上用真实论文流做质量回归。

fixtures：自造最小模板论文（article / revtex / 双栏会议，各数页）入仓库；真实 arXiv 论文仅 nightly 拉取、不入库（license 干净）。

环境一致性：本地 = CI = 云，同一镜像（§10）；镜像 CI 按层缓存，tag 触发 GHCR 发布。

## 附录 A：决策记录

每条：**决策 / 曾考虑的替代 / 依据**。

1. **脚本编排，agent 关节化。** 曾考虑：agent 为主体、SKILL 驱动流程（v2 形态）。依据：论文多样性集中在阶段内部而非阶段图——任何论文都走同一个阶段序，需要动态适应的是「怎么修这个编译错」而非「要不要重排流水线」；确定性控制流是缓存、断点续跑、CI、可调试性（同一输入同一路径）的共同前提；流程固化到能写进 SKILL.md，就固化到能写成代码，且代码不偷懒；freestyle 三失败模式（重新发明轮子 / 偷懒不可检测 / 自我验证不可信）在编排层同样成立。SKILL 降级为 prompt 资产，不再承担编排。
2. **返工 = 块级失效重算，不存在阶段级回跳。** 曾考虑：显式的阶段回退控制流。依据：全部返工场景（校验失败、编译失败、改术语表、改文风）都归结为「失效受影响块 + 重算子图」；增量构建模型使阶段回跳概念不需要存在。
3. **翻译记忆入产物契约（`chunks.json`）。** 曾考虑：中间产物全存 R2；全丢弃。依据：区分「可丢弃缓存」与「增量重翻所需状态」，后者随产物包走——云上编辑术语表触发增量重翻 = 拉包 → 失效 → 只重翻受影响块 → 回传，容器保持一次性。「会话 = 数据」推广为「构建状态也是数据」。
4. **通途不感知 R2 / Cloudflare。** 依据：开源 CLI 不能依赖特定云；上传与调度是 wenshu 侧职责；两仓库接口保持「文件 + CLI 约定」单一形态。
5. **缓存 key 构成与术语表两半制。** 依据：术语条目按块内命中参与 key，改一词只失效含它的块，增量重翻语义精确；全局文风规则单列版本号，全量重翻成为显式操作而非意外副作用。
6. **docker 为三角色（云部署 / CI / 参考环境），非运行前提；本地原生为主形态。** 曾考虑：强制 docker 运行。依据：CLI 对环境的全部要求是 TeX 在 PATH；macOS 上 docker 虚拟机 IO 显著拖慢编译迭代；「编译通过」的裁决权固定在参考镜像即可兼得环境确定性；`doctor` 命令弥补环境差异；TeX Live 体积原生与镜像相当，无一方更省。
7. **测试金字塔 + 恒等翻译门禁。** 依据：正确性大头在纯文本变换层，秒级可测；MockAgent 恒等翻译以零 LLM 成本覆盖编译全链路，是零期交付判据的 CI 化身；LLM 层设为监控而非门禁，避免模型抖动阻塞开发。
8. **静态检验页入产物包，通途不做前后端。** 曾考虑：给通途做独立前后端架构（展示 + 文枢完成前自用）。依据：backend 必然复制文枢信箱职责且侵蚀「产物契约 + CLI」的仓库边界；零期真实需求（anchors 可视化验收、契约 dogfooding、开源 demo）静态页全部满足；交互阅读器若要提前，提前动工文枢 web 端读本地产物包，不在通途另起炉灶。红线：需 server 或 LLM 的功能永不进检验页。
9. **figures 预渲染独立成阶段，仅依赖 `src/`。** 曾考虑：并入 export。依据：「PDF/EPS 图无法使用」是 v1 markdown 路线的遗留问题意识——xelatex 原生吃 PDF 图、EPS 走 epstopdf 链，编译侧零处理；预渲染只服务 AI 读图与检验页/索引。独立阶段 + 逐图 hash 缓存使翻译返工永不触发图片重渲染。
10. **mask = 解析器 + 分类表 + 保守默认 + 往返自检，不设强制 agent 复核。** 曾考虑：正则匹配；agent 复核掩码结果。依据：LaTeX 非正则语言，正则方案先天不成立；环境名枚举可完备而分类知识不必完备，未知环境经关节③分类或保守整块掩码（不损坏，只降覆盖）；运行时往返自检使解析缺陷在任何 LLM 调用前当场暴露——「四海皆准」的保证是缺陷当场可测而非解析器完美；agent 复核是「自我验证不可信」的变体且逐篇付费。
11. **survey 阶段：一次通读产出 brief + 术语，一致性靠稳定共享上下文。** 曾考虑：无全局上下文逐块直译；glossary 独立成阶段；前块译文链式传入后块提示词。依据：掩码 + 分块后模型只见局部，跨章节不一致（记号约定、指称方式、语体）是结构性风险，术语表只管得住词这类硬约束；纲要与术语预扫同属「通读全文一次」的产物，合并为一个阶段只付一次全文 token；链式传入译文会使缓存失效沿块链级联、并行退化为串行，故邻域上下文只用原文；通读输入 = masked.tex 的选择性回填视图（数学类块回填——记号约定住在行间公式里；表格/图/代码保持占位符；剔除附录与参考文献但附录仍翻译；由 blocks.json 类型字段驱动，unmask 参数化即得，不为 survey 另造机制；正文规模可控故不做 map-reduce）；置于 mask 之后、baseline 编译门控之内 = 编译不过的论文不产生 LLM 支出；brief 入产物契约使 read path 的 AI 摘要近乎免费。
12. **章节优先大块分块，翻译粒度与回退粒度解耦。** 曾考虑：段落级小块；固定 token 窗口切割。依据：节内衔接是翻译质量的主要来源，节间衔接在论文语篇中天然弱，节间一致性由 glossary + brief 承担而非切块方式；粒度约束来自输出而非输入——译文等长于原文，超长单次生成有漂移/偷懒/输出上限风险，故软目标（小节聚合）+ 硬上限（超大节在小节/段落边界下分）；段落数比对保证原译可逐段对齐，编译失败定位与回退细化到段落，「整节回退」的粗暴退化不存在；块变大同时降低调用开销与边界效应，代价仅是术语编辑失效整节（token 成本可接受）。
13. **assemble 并入 compile，关节「documentclass 适配」与「编译修复」合一。** 曾考虑：独立 assemble 阶段（unmask + inject_cjk）。依据：注入与适配的裁决者本来就是编译——原 assemble 的出口判据一栏写的是「裁决权在 compile」，没有自身出口判据的阶段按本模型不是真阶段；修复会话的常见动作即「改注入配置/导言区 → 重编译」，回环天然跨越两者，合并后 loop 在单一阶段驱动器内闭合；unmask + inject 为廉价文本操作，无独立缓存价值，中间产物 `zh-raw.tex` 仍落 `build/` 供调试；适配与修复是同一活动（让这个 documentclass 编译通过）、同一裁决（回环），并为一个 session 关节，成功适配仍按促升规则沉淀入适配表。
14. **figures 单格式 PNG + 视觉模型定长边，暂不做 WebP/GIF/SVG。** 曾考虑：多格式兼容（webp/gif/svg）。依据：「清晰则大、小则糊」是分辨率策略问题而非格式问题——独立位图的唯一硬消费者是视觉模型，长边超过 ≈1568px 即被 API 降采样，更高分辨率纯属浪费，按此上限逐图定 DPI 后 PNG 体积自然可控；人看高清走 zh.pdf 内嵌矢量原图（anchors 即定位），不需要独立高清位图；GIF 色深全面劣于 PNG；SVG 视觉 API 不接受、PDF→SVG 转换保真坑多，矢量需求已由 zh.pdf 承担；WebP 收益仅在存储/传输体积，留作后续优化，元数据 `format` 字段已预留。
