重跑语义一条规则，没有 hash 步骤 2 完成（PR #30）

tongtu run <paper> [--from <stage>]
  1. 给了 --from X：删掉 X 及其下游的全部产物，从 X 起按序全部执行
  2. 没给：从第一个「产物不在」的阶段开始，之前的全部视为完成；一个产物都没有就从 fetch 开始
  3. 中途某阶段失败：停下，写它的 manifest，退出码非 0；下次 run 自然从它重来（它的产物不在）
  4. tongtu stage X <paper> 只跑 X 一个阶段，上游产物不在就直接报错退出，不写 manifest

改了 SKILL 就 --from translate，改了环境分类表就 --from mask，改了术语表就 --from survey，手改了 src/ 里的源码就 --from precompile。忘了给 --from 的后果是用旧产物，这在只有一个用户的阶段是可接受的。manifest 从此只记「这次跑出了什么」，不再背「下次要不要跑」的判断。

骨架从六步减到四步

① 清旧产物删本阶段上次的产物
② 执行本阶段的实际工作
③ 自检机械判据，全部成立才是 ok
④ 写 manifest状态、观察值、warnings、message

去掉的两步：前置条件检查（由 run 的顺序保证，stage 直接报错，退出码 2）与跳过判定（由 --from 替代）。各 manifest 的共用字段是 status / warnings / message；类 Manifest（tongtu/artifacts/common.py）只是命令行读这三个字段的读取器，各阶段 manifest 按本页卡片的字段序自定义，不继承它（步骤 2 拍板）。

precompile把原文变成一份带中文排版设置、能编译通过的单文件 LaTeX，产出基线吸收 flatten失败时拉 agent work
任务
  1. 判定主文件：含 \documentclass → 含 \begin{document} → main.tex；仍不唯一 → main_ambiguous（将来可改为逐个试编译）
  2. 展开：latexpand --keep-comments --fatal，同名 .bbl 存在且恰一处 \bibliography{} 时内联；出口：非空、含 \begin{document} 与 \end{document}
  3. 注入中文排版设置：在前导区加 xeCJK / ctex 宏包与字体设置（V2 的 inject_cjk）。在这里而不在 compile 注入，是为了让宏包冲突在翻译之前、在这一步的修复会话里暴露并修掉；compile 与 precompile 的差别因此只剩正文文字，编译再出错就只可能是译文引起的
  4. 搭编译树：src/ 拷进 build/precompile/，注入后的展开结果写为树内 flat.tex
  5. 编译：latexmk -xelatex 一次
  6. 失败 → 拉一次 agent work 修复会话：skill/precompile_fix/ 拷进编译树，agent 自己读 skill 与 flat.log；现场就是编译树
  7. 终审：latexmk -C 后再编一遍；退出码 0、pdf 非空、页数 > 0
  8. 从 flat.log 解析五个基线计数；拷出（可能已修过的）flat.tex 为 build/precompile.tex

survey通览全文，产出翻译任务单吸收 chunk可选一次 ask
任务
  1. 切 chunk：扫标题结构选首选层级 → 按章节切 → 大于 SPLIT_ABOVE 下分、小于 MERGE_BELOW 合并 → 定区 front / body / appendix → 自检拼接恒等。token 数用 tiktoken（o200k_base）实数，不再按字符数除 4 估
  2. 模型提议术语表（可选，角色 survey_terms，--no-terms 或角色未配置时跳过）：一次 ask，输入摘要 + 标题树 + 全文掩码文本，schema 约束输出 {terms, do_not_translate}；模型不可用降级为空提议并记 warning，不是失败
  3. 合并四层术语表：模型提议（最低层 survey）→ 全局配置目录 → 论文工作目录 → 命令行 --glossary，后者覆盖前者；按全文命中过滤，未命中记 filtered；用户 style 段原样转录。terms 与 do_not_translate 的区别就是词写在了输入文件的哪一段。命中规则：词边界匹配，允许尾缀 s / es；全大写的词（缩写）区分大小写，其余不区分——LLM 命中 LLM / LLMs，不命中 vLLM / llm；large language model 命中 Large Language Models。现状是大小写不敏感的子串查找，LLM 会命中 vLLM，要改
  4. 取全局语境：照录摘要（blocks.json 的 abstract 槽位或 masked.tex 的 abstract 环境）；章节标题树
  5. 写 brief.json（上面三样合一）与 chunks/

术语提议是跨 chunk 一致性的预防手段：所有 chunk 的 system 里从一开始就是同一份词；而且它是产物（brief.json），翻译前可以打开改两条再跑。治疗手段是 review 阶段。

# ===== build/brief.json —— translate 只读这一个文件加 chunks/ =====
class BriefFile(BaseModel):
    abstract: str | None                   # 论文原文摘要照录；两条来路都落空为 null（不是失败，记一条 warning）
    heading_tree: list[Heading]             # 全文章节标题树，按文档序；一个标题都没有为空列表
    terms: list[TermEntry]
    do_not_translate: list[DoNotTranslateEntry]
    style: str | None                      # 用户写给译者的额外要求；三层都没写为 null
    chunks: list[ChunkRecord]

# 一条标题。全文树与 chunk 内清单用同一个类（现状分 DocumentHeading / BriefHeading 与 Heading 两个，
# 区别只是前者多一个 depth；合并成一个，chunk 内的 depth 也如实填）。
class Heading(BaseModel):
    command: str                  # 标题命令名：section / subsection / …（星号变体等同无星）
    argument: str                 # 标题参数原文，未翻译
    depth: int                    # 相对深度：全文最浅层级记 1，往深一级加一

class TermEntry(BaseModel):
    word: str                     # 原写法，取胜出层的
    translation: str              # 本篇译法，translate 按它约束用词
    decided_by: "survey" | "global" | "paper" | "cli"   # 胜出层，survey 是模型提议的最低层

class DoNotTranslateEntry(BaseModel):
    word: str
    decided_by: "survey" | "global" | "paper" | "cli"

class ChunkRecord(BaseModel):
    id: str                       # c012
    start: int; end: int           # 在 masked.tex 字符序列上的区间，文件内容即该切片
    part: "front"|"body"|"appendix"
    tokens: int                   # tiktoken 实数，只用于分块决策（现状 token_estimate = 字符数 / 4）
    paragraphs: int
    headings: list[Heading]       # chunk 内有效深度 0 的标题，按文档序
    translatable_chars: int       # 剥除 placeholder 后的非空白字符数；0 即纯 placeholder，不调模型
# 去掉：sha256；internal_cuts（聚合进本 chunk 的各单元起点，本意是给「按更细边界拆分重试」用，
# 那条重试从未实现、全仓库没有读它的地方，随复用精细化一起放下）

# ===== build/manifests/survey.json =====
class SurveyManifest(BaseModel):
    status: "ok" | "glossary_invalid" | "chunk_failed"
    chunks_total: int
    transparent_environments: list[str]   # 体内出现首选层级标题、不计入深度的环境名（如 CJK*）；本篇的事实，留
    terms_total: int
    do_not_translate_total: int

{
  "terms": { "attention head": "注意力头", "LLM": "大语言模型", "large language model": "大语言模型" },
  "do_not_translate": ["Transformer", "softmax", "vLLM"],
  "style": "术语首次出现时附英文原文。"

# 合并：同一个词（大小写不敏感）后一层整条覆盖前一层，跨段也覆盖；同一份文件内同一个词出现在两段是配置错误。
# 变种：LLM 与 large language model 是两条，各写各的；LLM 的 s 尾缀自动覆盖，不必再写 LLMs。
# 全大写的词区分大小写，是因为短缩写小写后会撞上普通英文词：MAP / ART / SAM / CAT 小写就是 map / art / sam / cat。
# 命中只决定「这条要不要进本 chunk 的提示词」，翻译仍由模型做，不是查找替换；误命中是噪声，漏命中是模型自己选译法。
translate逐 chunk 调模型翻译，脚本驱动校验与重试调 askuser 只放待译正文；重试是多轮续写，至多 1 次
任务（每个 chunk，线程池并发，结果按文档序落盘）
  1. translatable_chars 为 0 → skipped，原文即译文，不调模型。这种 chunk 只有 placeholder 与空白（比如整段都是公式、图表的区域，或只有 \maketitle 一类命令）
  2. 组装 system（稳定部分在前、本 chunk 特有部分在后，见右）与 user（只有待译正文）
  3. ask，拿回译文；整段包在代码围栏里时剥掉围栏
  4. 四层 validate（见下），全过 → translated
  5. 不过 → 在同一段对话后续两轮（assistant = 上一次译文，user = 差异说明 + 请重新输出完整译文）再 ask 一次（MAX_RETRIES = 1）；ask 报错或返回空不消耗这一次
  6. 仍不过 → fallback，译文文件写原文，记最后一次未通过的层
  7. 全部跑完后，fallback 占比 > 0.2 → 整体 translate_failed，不进 compile；不提前中断（中断只会丢掉已付费的译文）
四层 validate —— 全是机械比对，不含判断；失败信息写成人读的差异说明，原样回灌给模型
层比什么差异说明长什么样
placeholders⟦BLK-n⟧ / ⟦CAP-n⟧ 的 multiset 相等；另查 ⟦ ⟧ 数量与完整 placeholder 数吻合（拦 ⟦BLK-3⟧⟧ 这类碎片）「译文缺少 ⟦BLK-12⟧；多出 ⟦BLK-21⟧」
control_sequences控制序列 multiset 相等：取 \cmd 的命令名，带紧随的星号（\section* ≠ \section）；\% 一类符号控制序列取符号本身「\cite 原文 3 次、译文 2 次；\emph 原文 0 次、译文 1 次」
braces_and_math未转义的 { } 配对平衡（深度不转负、结尾归零）；未转义的 $ 偶数且不少于原文。现状是三者计数分别相等，本地 5 个失败案例里它抓的全是化妆品级漂移（多个 \textit、数字包进 $、去掉 \dsviii{} 的空括号），却让一个 chunk 回退成英文——放宽后那个 chunk 第二次就过，其余四个仍被别的层拦住「{ } 在第 312 字符处不平衡」「$ 原文 14 个、译文 12 个」
paragraph_count含可译文本的段落数相等。一段剥除 placeholder、\begin{X} / \end{X}、其余命令名之后仍有非空白字符才计入——模型合并只含 placeholder 或只含 \maketitle 的空行不算错「原文 9 段、译文 8 段」

同一份实现三处用：translate 的出口终审、tongtu validate、compile 对正文控制序列的比对（只用第 2 层）。

system —— 稳定的在前、逐 chunk 变化的在后；缓存按 token 前缀命中，与 system / user 边界无关

class ChunkTranslateRecord(BaseModel):
    status: "translated" | "fallback" | "skipped"
    attempts: int                        # ask 调用次数：1 即一次通过，2 即重试后通过或回退；skipped 为 0
    failures: list[str]                 # fallback 时最后一次的各层差异说明（「层名：说明」），或 ask 的失败现场

任务
  1. 搭隔离现场 build/review/，只放：chunks/（原文，只读）、reviewed/（译文，可改）、brief.json，加 skill 目录（SKILL.md + validate.py）。manifest、blocks.json、masked.tex 都不在这棵树里，agent 碰不到
  2. 拉一次 agent work（角色 review）：通读全部原文与译文，把 translate 回退成英文的 chunk 翻出来，修订术语不一致、同一概念前后译法不同、记号与称呼不统一、明显误译；只许改 reviewed/ 下的文件，不许增删文件。SKILL 要求它每改完一个文件就跑 python3 -I validate.py chunks/cNNN.tex reviewed/cNNN.tex，不过接着改——与脚本终审同一份实现；Bash 只放行这一条
  3. 脚本终审：先查 reviewed/ 的文件名集合与 chunks/ 完全一致（多的忽略，少的视为回退；一个文件就是一个 chunk，边界改不了）；再对每个文件对着它的源 chunk 跑四层 validate——placeholder 那一层就是拦「多一个少一个 ⟦BLK-21⟧」的；不过的 chunk 整个回退到 translate 的版本，其他 chunk 的修订保留；通过的拷出到 build/reviewed/
  4. compile 读 reviewed/

agent 能造成的最大损害 = 某个 chunk 的修订被丢弃。它的改动全部经过与 translate 同一套机械校验；它只见隔离现场里的文本；--from review 可以反复跑而不重翻。

模型调用层tongtu/model/，原「agent 适配层」；流水线只认两个函数 步骤 1 完成（PR #24）

ask —— 单次问答，无状态 
ask(role, system, messages, *, schema=None, log_path, model=None, effort=None) -> AskOutcome
  role:     "translate" | "survey_terms" | …   # 角色名，在 models.toml 的 [roles] 查到服务商 / 模型 / 强度
  system:   系统提示词
  messages: [(role, content), …]               # 第一次只有一条 user；重试续上 assistant + user
  schema:   JSON Schema，要结构化输出时给            # 只有 chat 接口支持；另两个接口给了 schema 以 error 返回
  model:    "服务商/模型"，None 用角色配置          # --ask-model 的原字符串；effort 同理，None 用角色配置
  → AskOutcome(status: "ok"|"error", text, detail)
三种接口，各用官方 SDK
chat
OpenAI chat/completions：openai SDK；system → system message；强度 → reasoning_effort；schema → response_format
responses
OpenAI responses：openai SDK；system → instructions；强度 → reasoning.effort
messages
Anthropic Messages：anthropic SDK（现状是 httpx 手发，换掉）；system → system；强度 → thinking.budget_tokens 档位表

每次调用写一个 JSON 日志（请求要素、正文、usage、耗时）到 log_path；失败以值返回不抛异常。这些现状都保留。

work —— 在一棵目录树里拉起一次多轮会话 
work(role, workdir, *, trace_path, model=None, effort=None) -> WorkOutcome
  role:     "precompile_fix" | "compile_fix" | "review"
  workdir:  会话的 cwd，也是它能读写的全部范围
  model:    "运行时/模型"，None 用角色配置          # --work-model 的原字符串；effort 同理
  → WorkOutcome(stop_reason: "finished"|"timeout"|"error", detail)

skill 是文件，不是 prompt：work 先把仓库里 skill/<role>/ 整个目录拷进现场（Claude Code 放 .claude/skills/<role>/，路径模板在 runtime 配置里），再用一句固定的 prompt 拉起会话：「读 skill，按它做；现场是这棵树」。skill 目录里除了 SKILL.md 还放它要用的工具——review 的目录里带一个单文件 validate.py（从 tongtu 的实现生成，不入库），agent 跑的是它，不是 tongtu。

运行时 = 一条命令模板

Claude Code、Codex、opencode 的 headless 模式都是「cwd + stdin 进 prompt + 几个参数 + 退出码」，差别只在命令行怎么拼和 skill 放哪。所以运行时不写代码，写在配置里（见下）；work 本身只做：拷 skill → 拼命令 → 新进程组跑 → 超时杀组 → stdout 落 trace → 按退出码与超时给 stop_reason。

去掉 budget_exhausted：它要解析各运行时的 transcript 才能判，而调用方反正不信 stop_reason、会自己复验，轮数耗尽与其他错误在调用方眼里没有区别。max_turns 仍作为参数传给运行时，只是不再从结果里读回。

自建 agent 循环（用 ask + 工具调用自己写）是第三条路，CLI 运行时不够用再说。

命令行 --ask-model / --ask-effort 覆盖全部 ask 类角色，--work-model / --work-effort 覆盖全部 work 类角色；没有 tongtu config 子命令，文件手改。密钥写在服务商条目的 api_key（文件 0600），留空则用 api_key_env 指的环境变量；credentials.json 与 opencode 登录态两级来源去掉。messages 接口的推理强度按档位表换算成 thinking.budget_tokens（low 1024 / medium 2048 / high 4096），max_tokens 32768。tongtu doctor 只检查 [roles] 引用到的服务商与运行时。

会话的约束——四件事，各管一件issue #20 实测结论，2026-08-20
  1. 命令放行规则：运行时自带，按子命令逐个判定，复合命令与命令替换绕不过。review 只给 python3 -I validate.py（-I 不把脚本目录放进 sys.path）；precompile_fix / compile_fix 只给 latexmk、xelatex、kpsewhich。同时 deny 对 skill 目录的编辑：agent 改不了 validate.py，也不能用 > 重定向覆盖它。
  2. 操作系统沙箱：运行时自带，不自己写。latexmk -e、xelatex -shell-escape、.latexmkrc 在放行之后仍能执行任意代码，靠沙箱把写范围限制在会话 cwd、断网。
  3. 嵌套检查：子进程环境加 TONGTU_DISABLE=1，tongtu 入口看到它立刻退出码 2。给会话里的 tongtu run 一个明确失败，不防有意绕过——有意绕过只能走第 2 条管住的那条路：嵌套的 run 要写 cwd 之外的工作目录根、要出网，第一个阶段就失败。
  4. 会话隔离：不加载用户的 hooks / MCP / 插件；子进程 PATH 收成固定清单（TeX bin + 系统 bin）。

运行时只认 Claude Code 与 Codex：Codex 的放行规则是 .codex/rules/<role>.rules（prefix_rule），沙箱是 -s workspace-write -c approval_policy="never"；opencode 没有沙箱，在它有之前不作为使用方案。

待验证讨论中记下、还没有答案的事

  • Bash 前缀放行的严密性——已验证（issue #20，2026-08-20）：Claude Code、Codex、opencode 都按子命令逐个判定，&& ; || | 换行、$()、反引号、子 shell 绕不过。真正的洞不在复合命令：agent 能改写 validate.py 再运行、在旁边放同名模块遮蔽标准库、latexmk -e / xelatex -shell-escape 本身就是任意代码。处理写进「模型调用层」的四件事。
