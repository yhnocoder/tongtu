命令行

tongtu 是通途的命令行入口：给它一个 arXiv 编号，它把论文源码取下来、翻译成中文、编译出与原版同样排版的 PDF。日常只用 tongtu run 一条命令；其余命令服务于它——status 查看一篇论文跑到哪了，stage 单独重跑某个阶段，validate 校验一对译文，doctor 检查环境，setup 生成配置。七个阶段各自做什么见 pipeline-v0.html，模型与服务商的配置见 model.html。

SYNOPSIS

tongtu run      PAPER [--from STAGE] [--no-review] [OPTIONS]
tongtu stage    [STAGE PAPER] [OPTIONS]
tongtu status   PAPER [--workdir DIR]
tongtu validate SRC DST
tongtu doctor
tongtu setup    [-i]
tongtu          --version

PAPER 是 arXiv 编号、arXiv 链接或本地源码目录。STAGE 取 fetch、precompile、mask、survey、translate、review、compile 之一。终端输出、manifest 的 message 与 warnings 一律英文；发给模型的素材与 models.toml 模板注释不在此列。

COMMANDS 示例输出为示意，待实跑替换

run PAPER [--from STAGE] [--no-review]
翻译一篇论文，生成与原版同样排版的中文 PDF。终端逐阶段打一行结果（✓/✗ 阶段 状态 摘要 耗时），translate、review 显示进度条。依次跑完 fetch → precompile → mask → survey → translate → review → compile。
失败了停在出错的阶段，退出 1，终端打出原因与 manifest 路径。修好后再执行一次同样的命令，就从这个阶段接着跑，前面的阶段不会重做。
被打断了同上：再执行一次，从中断的阶段接着跑。
已经跑完了什么也不做，退出 0，提示用 --from。
改了东西想重来加 --from STAGE，从该阶段起重跑，它及其下游的旧产物会被删掉。改了什么就从哪起：src/ 里的源码 → precompile；tongtu/data/environments.json → mask；任一层术语表 → survey；skill/translate/SKILL.md → translate；skill/review/ → review。tongtu 不检测输入有没有变，忘了给 --from 就会沿用旧产物。

进度显示。每个阶段运行时占一行 live 行（单行刷新，不是 tty 时不画），结束后被结果行替换。precompile、review、compile 显示当前动作（状态 + 摘要，如 fix session running）；survey 显示术语提议调用的模型与结果；translate 是并行翻译，显示一条 chunk 线：每个 chunk 按 token 数占一段，长度与 token 成比例，最少一格，线宽取终端剩余宽度。四种状态：未开始 ─（暗），正在翻 ┅，完成 ━，有 warning（回退或重试过）━ 黄色。线后跟 已完成/总数、token 计数、耗时、eta。chunk 比格数多时相邻 chunk 共享一格，取最差状态（warning > 正在翻 > 未开始 > 完成）；剩余宽度不足 20 格时不画线，只保留计数。终端不支持这些字符（rich 判定 ascii_only 或 legacy_windows）时换成 - ~ = !。 阶段模块不直接向终端打印，通过 report 回调把状态交给命令行层渲染；成功的 chunk 不单独打行，回退或重试过的 chunk 各打一行持久 warning，留在 live 行上方。

stage STAGE PAPER
只跑一个阶段，用来反复调某一步——比如改了 translate 的 SKILL.md，想只看译文变没变，不想把 review、compile 也跑一遍。它不会动其他阶段的产物，跑完后想继续往下就 run。上游产物还不在时拒绝执行（退出 2）。选项与 run 相同，只是没有 --from（本来就只跑这一个阶段）。不确定阶段名怎么拼，运行不带参数的 tongtu stage，它按顺序列出七个阶段名。

OPTIONS run 与 stage 共用；stage 不含 --from

--from STAGE
从哪个阶段起重跑，见 run。
--ask-model PROVIDER/MODEL，--ask-effort LEVEL
这一次换个模型翻译：覆盖所有 API 直调（ask）类角色（survey_terms、translate）。PROVIDER 是 models.toml 里 [provider.*] 的名字。想长期换或只换一个角色，改 models.toml。
--work-model RUNTIME/MODEL，--work-effort LEVEL
这一次换个模型做 agent 工作：覆盖所有 agent 会话（work）类角色（review、precompile_fix、compile_fix）。RUNTIME 是 [runtime.*] 的名字，例 claude_code/claude-sonnet-5。
--glossary FILE
给这篇论文额外指定术语表，可多次给，靠后的优先。与全局、论文层术语表叠加。
--no-terms
不让模型提议术语，只用自己给的术语表。
--no-review
只 run 有。跳过审校会话：不拉 agent、不搭现场，translate 的译文原样拷成 build/reviewed/ 进 compile。
--jobs N
translate 同时翻几个 chunk。
--workdir DIR
把这篇论文的工作目录放到指定位置。默认 $TONGTU_HOME/<编号>，再默认 ~/.local/share/tongtu/<编号>。

EXIT STATUS

0
成功。run：PDF 已写出，或七个阶段的产物都在；validate：四层全过；doctor：工具链与字体齐全。
1
某阶段失败，manifest 里有原因；validate 某层不过；doctor 工具链或字体缺失。
2
用法错误；stage 的上游产物不在；setup -i 一个服务商都没选；TONGTU_DISABLE 已设。

FILES

~/.config/tongtu/models.toml
服务商、模型清单、各角色默认模型，见 模型调用层。
~/.config/tongtu/glossary.json
全局层术语表。
<工作目录>/glossary.json
论文层术语表。
<工作目录>/src/ build/ logs/ out/
各阶段的输入与产物，见各阶段卡；manifest 在 build/manifests/<stage>.json。

取值优先级，右压左：模型与强度 = models.toml [roles] → --ask-* / --work-*；术语表 = 模型提议 → 全局层 → 论文层 → --glossary；工作目录 = ~/.local/share/tongtu/ → $TONGTU_HOME → --workdir。

ENVIRONMENT

TONGTU_HOME
工作目录根。
XDG_CONFIG_HOME
配置目录根，默认 ~/.config。
服务商密钥
服务商条目 api_key 留空时，用其 api_key_env 指的变量。
TONGTU_DISABLE
已设时入口立刻退出 2。work 会话的子进程环境里设置它，让会话内的 tongtu run 明确失败。
