模型调用层

tongtu/model/。流水线里每一处调模型都经这一层，只认两个函数：ask 单次问答（survey 提议术语、translate 逐 chunk 翻译），work 在一棵目录树里拉起一次 agent 会话（precompile / compile 的修复、review）。服务商、运行时与各角色的默认模型都在 models.toml。各阶段见 pipeline.html，命令行见 cli.html。

ask —— 单次问答，无状态 
ask(role, system, messages, *, schema=None, log_path, model=None, effort=None) -> AskOutcome
  role:     "translate" | "survey_terms" | …   # 角色名，在 models.toml 的 [roles] 查到服务商 / 模型 / 强度
  system:   系统提示词
  messages: [(role, content), …]               # 第一次只有一条 user；重试续上 assistant + user
  schema:   JSON Schema，要结构化输出时给            # 只有 chat 接口支持；另两个接口给了 schema 以 error 返回
  model:    "服务商/模型"，None 用角色配置          # --ask-model 的原字符串；effort 同理，None 用角色配置
  → AskOutcome(status: "ok"|"error", text, detail, model)   # model = 实际解析的「服务商/模型」；解析失败时为空串
三种接口，各用官方 SDK
chat
OpenAI chat/completions：openai SDK；system → system message；强度 → reasoning_effort；schema → response_format
responses
OpenAI responses：openai SDK；system → instructions；强度 → reasoning.effort
messages
Anthropic Messages：anthropic SDK；system → system；强度 → thinking.budget_tokens 档位表

每次调用写一个 JSON 日志（请求要素、正文、usage、耗时）到 log_path；失败以值返回不抛异常。

work —— 在一棵目录树里拉起一次多轮会话 
work(role, workdir, *, trace_path, model=None, effort=None, report=None) -> WorkOutcome
  role:     "precompile_fix" | "compile_fix" | "review"
  workdir:  会话的 cwd，也是它能读写的全部范围
  model:    "运行时/模型"，None 用角色配置          # --work-model 的原字符串；effort 同理
  report:   每解析出一条动作调一次，参数是一行文本    # None 不回报；见下「运行时 = 一条命令模板」
  → WorkOutcome(stop_reason: "finished"|"timeout"|"error", detail, model)   # model = 实际解析的「运行时/模型」；解析失败时为空串

skill 是文件，不是 prompt：work 先把仓库里 skill/<role>/ 整个目录拷进现场（Claude Code 放 .claude/skills/<role>/，路径模板在 runtime 配置里），再用一句固定的 prompt 拉起会话：「读 skill，按它做；现场是这棵树」。skill 目录里除了 SKILL.md 还放它要用的工具——review 的目录里带一个单文件 validate.py，它就是 tongtu/validation.py 本身（只依赖标准库，带 main），由 review 阶段拷进现场，agent 跑的是它，不是 tongtu。work 拷 skill 时用 dirs_exist_ok 叠加，不清空目的地。

运行时 = 一条命令模板

Claude Code、Codex、opencode 的 headless 模式都是「cwd + stdin 进 prompt + 几个参数 + 退出码」，差别只在命令行怎么拼和 skill 放哪。所以运行时不写代码，写在配置里（见下）；work 本身只做：拷 skill → 拼命令 → 新进程组跑 → 超时杀组 → stdout 逐行落 trace → 按退出码与超时给 stop_reason。

live 行显示当前动作 （issue #56，2026-08-27）：运行时条目可写 events 声明 stdout 事件流的格式（stream-json / codex-json，取值即解析器名），work 在落 trace 的同时按它逐行解析出当前动作——工具名 + 首要参数，如 Bash: latexmk -xelatex flat.tex——经 report 回调交给调用方，阶段透传给命令行，live 行滚动显示最近一条（对齐结果表的 status / summary 两列，截断与对齐由显示层做）。不写 events 或某行解析不出就不回报，live 行保持阶段的静态文案；events 取了未知值在配置加载时报错。解析永不影响会话本身。

一个运行时条目 = 一个「工具 × 服务商」组合 （issue #26，2026-08-22）：条目可选写 provider 指向 [provider.*]，work 据此把 {base_url} 与 {api_key} 填进命令模板与 env 表，密钥经 env 表进子进程环境，不出现在命令行参数里。角色表、resolve_role、--work-model 运行时/模型 的语义都不变。

stop_reason 不含 budget_exhausted：它要解析各运行时的 transcript 才能判，而调用方反正不信 stop_reason、会自己复验，轮数耗尽与其他错误在调用方眼里没有区别。max_turns 仍作为参数传给运行时，只是不再从结果里读回。

自建 agent 循环（用 ask + 工具调用自己写）是第三条路，CLI 运行时不够用再说。

models.toml（配置目录） 
# 服务商：一个 API 前缀 + 一个密钥 + 哪个模型走哪种接口（api 取 chat / responses / messages）
[provider.opencode]
base_url    = "https://opencode.ai/zen/go"   # 接口前缀的根，chat / responses / messages 都在它下面的 /v1/...
api_key     = ""                  # 直接写密钥，或留空改用下面的环境变量；setup -i 填的是这里
api_key_env = "OPENCODE_API_KEY"

[provider.opencode.models]          # 逐模型写接口；setup 生成的模板列全 opencode 当前可用的模型，这里只举三种接口各一例
"deepseek-v4-pro" = "chat"
"gpt-5.6-luna"    = "responses"
"minimax-m3"      = "messages"

[provider.deepseek]
base_url    = "https://api.deepseek.com"
api_key     = ""
api_key_env = "DEEPSEEK_API_KEY"
api         = "chat"              # OpenAI 兼容；模型 deepseek-v4-flash / deepseek-v4-pro

[provider.anthropic]
base_url    = "https://api.anthropic.com"
api_key     = ""
api_key_env = "ANTHROPIC_API_KEY"
api         = "messages"          # 整个服务商一种接口时不必逐模型列

# 会话运行时：一条命令模板，{model} {effort} {max_turns} {tmp_dir} 由 work 填入；{tmp_dir} 是 work 为本次会话建的临时目录，会话结束即删
[runtime.claude_code]
skill_path = ".claude/skills/{role}"     # skill 目录拷到现场的哪里
events     = "stream-json"               # stdout 事件流的格式，live 行据此解析当前动作；不写则不解析
command = ["claude", "-p", "--model", "{model}", "--effort", "{effort}", "--max-turns", "{max_turns}",
           "--output-format", "stream-json", "--verbose",
           "--setting-sources", "", "--strict-mcp-config",                       # 不加载用户 hooks / MCP / 插件；订阅登录照常（--bare 只认 API key，不用）
           "--allowedTools", "Read,Edit,Write,Glob,Grep,Bash", "--permission-mode", "acceptEdits",
           "--disallowedTools", "Edit(.claude/skills/**)",                       # agent 改不了 skill 目录（含 validate.py），重定向覆盖也按这条拦
           "--settings", "{settings}"]                                           # 下面 settings 表序列化成 JSON 填入
settings = { sandbox = { enabled = true, autoAllowBashIfSandboxed = true, allowUnsandboxedCommands = false, failIfUnavailable = true, network = { allowedDomains = [] } } }
env = { ANTHROPIC_API_KEY = "", ANTHROPIC_AUTH_TOKEN = "", ANTHROPIC_BASE_URL = "" }   # 空串 = 未设：钉死订阅登录；-p 模式下 shell 里导出的这些变量会不问直接压过登录
# 沙箱：macOS 零安装（Seatbelt），Linux 镜像装 bubblewrap 与 socat；写范围 = 会话 cwd，断网
# Bash 在沙箱内自由使用：写范围 = 现场，断网；agent 做得对不对由驱动器在现场外重跑校验终判。work 拉起子进程时环境加 TONGTU_DISABLE=1、PATH 收成固定清单。
# Codex 的运行时条目按同一套机制写在下面的 [runtime.codex_opencode]（issue #27）。
# .codex/rules 的 allow 是「沙箱外执行」，不用它做放行（issue #26 实测，2026-08-22）

# 同一个 Claude Code，模型换成 opencode 上的：一个运行时条目 = 一个「工具 × 服务商」组合
[runtime.claude_code_opencode]
provider = "opencode"                    # {base_url} 与 {api_key} 由 work 从 [provider.opencode] 填入
skill_path = ".claude/skills/{role}"     # skill 目录拷到现场的哪里
events     = "stream-json"
command = [同 runtime.claude_code 一字不差]
settings = { sandbox = { … 同 runtime.claude_code … } }
env = { ANTHROPIC_BASE_URL = "{base_url}", ANTHROPIC_API_KEY = "{api_key}", ANTHROPIC_DEFAULT_HAIKU_MODEL = "{model}", ANTHROPIC_DEFAULT_SONNET_MODEL = "{model}", ANTHROPIC_DEFAULT_OPUS_MODEL = "{model}", CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC = "1", DISABLE_TELEMETRY = "1" }
# opencode 的 messages 端点只认 x-api-key，所以密钥写进 ANTHROPIC_API_KEY；ANTHROPIC_AUTH_TOKEN 走 Bearer，会 401
# Claude Code 把 ANTHROPIC_BASE_URL 当根，自己拼 /v1/messages，所以这里填的是不带 /v1 的 base_url
# 三个 DEFAULT_*_MODEL 都指同一个模型，防止后台的小调用拿 claude 系列的名字去打 opencode
# 密钥经进程环境传入而不是写进命令行参数：命令行参数在 ps 里可见

# Codex + opencode：只靠 Codex 自带的沙箱（-s workspace-write + approval never），不写 .codex/rules——它的 allow 是「沙箱外执行」
[runtime.codex_opencode]
provider   = "opencode"
skill_path = ".codex/skills/{role}"
events     = "codex-json"
command = ["codex", "exec", "--json", "--skip-git-repo-check", "--ephemeral", "--ignore-user-config", "--ignore-rules",
           "-s", "workspace-write", "-c", 'approval_policy="never"',
           "-m", "{model}", "-c", 'model_reasoning_effort="{effort}"',
           "-c", 'model_provider="opencode"', "-c", 'model_providers.opencode.name="opencode"',
           "-c", 'model_providers.opencode.base_url="{base_url}/v1"',
           "-c", 'model_providers.opencode.env_key="OPENCODE_API_KEY"',
           "-c", 'model_providers.opencode.wire_api="responses"']
env = { OPENCODE_API_KEY = "{api_key}", CODEX_HOME = "{tmp_dir}" }
# prompt 不作为位置参数：codex exec 没给 prompt 参数时从 stdin 读，work 正是经 stdin 喂 PROMPT；cwd 由 work 设为现场，不加 -C
# CODEX_HOME 指向 work 为本次会话建的临时目录，会话结束整个删掉；~/.codex/ 不被读也不被写
# max_turns 对 Codex 不生效：沙箱只靠 -s workspace-write 与 approval_policy="never"，写范围 = 现场 + 临时目录，默认断网
# wire_api 只接受 responses，所以这个条目只能跑 opencode 的 responses 端点支持的模型：gpt-5.6-luna、grok-4.5、muse-spark-1.2-contributor、deepseek-v4-flash
# codex 须是原生二进制（brew cask 装的）：npm 装的是 node 启动脚本，work 把子进程 PATH 收成 TeX + 系统 bin 后找不到 node，退出码 127

# 角色：流水线里每一处调模型的地方一个名字，这里定它默认用什么
[roles]
survey_terms   = { provider = "opencode", model = "deepseek-v4-flash", effort = "low" }   # 可选；不配就不提议
translate      = { provider = "opencode", model = "deepseek-v4-pro", effort = "none" }
review         = { runtime = "claude_code", model = "claude-opus-5", effort = "medium", max_turns = 300, timeout_seconds = 3600 }
precompile_fix = { runtime = "claude_code", model = "claude-sonnet-5", effort = "xhigh", max_turns = 40, timeout_seconds = 1800 }
compile_fix    = { runtime = "claude_code", model = "claude-sonnet-5", effort = "xhigh", max_turns = 40, timeout_seconds = 1800 }

[fonts]

命令行 --ask-model / --ask-effort 覆盖全部 API 直调（ask）类角色，--work-model / --work-effort 覆盖全部 agent 会话（work）类角色；没有 tongtu config 子命令，文件手改。密钥写在服务商条目的 api_key（文件 0600），留空则用 api_key_env 指的环境变量。messages 接口的推理强度按档位表换算成 thinking.budget_tokens（low 1024 / medium 2048 / high 4096），max_tokens 32768。tongtu doctor 只检查 [roles] 引用到的服务商与运行时。

会话的约束——四件事，各管一件issue #20 实测结论，2026-08-20
  1. Bash 不做前缀放行：运行时的 autoAllowBashIfSandboxed 让沙箱内的命令一律放行，failIfUnavailable 又保证沙箱不可用时会话直接失败，角色级放行清单起不了作用，故去掉（issue #20 实测，2026-08-24）。约束交给第 2 条的沙箱，正确性交给驱动器在现场外重跑校验。仍 deny 对 skill 目录的编辑：agent 改不了 validate.py，也不能用 > 重定向覆盖它。
  2. 操作系统沙箱：运行时自带，不自己写。latexmk -e、xelatex -shell-escape、.latexmkrc 本来就能执行任意代码，前缀放行拦不住，靠沙箱把写范围限制在会话 cwd、断网。
  3. 嵌套检查：子进程环境加 TONGTU_DISABLE=1，tongtu 入口看到它立刻退出码 2。给会话里的 tongtu run 一个明确失败，不防有意绕过——有意绕过只能走第 2 条管住的那条路：嵌套的 run 要写 cwd 之外的工作目录根、要出网，第一个阶段就失败。
  4. 会话隔离：不加载用户的 hooks / MCP / 插件；子进程 PATH 收成固定清单（TeX bin + 系统 bin）。

运行时只认 Claude Code 与 Codex：Codex 不用 .codex/rules 做放行——decision="allow" 的规则是「沙箱外执行」（issue #26 实测，2026-08-22）——只靠沙箱 -s workspace-write -c approval_policy="never" 把写范围限制在现场；opencode 作为运行时没有沙箱，在它有之前不作为使用方案。
