# 各阶段 manifest 的共用基类（tongtu/artifacts/common.py）：status 在 JSON 里排第一，warnings / message 紧随其后，阶段自己的字段在后面。子类把 status 收窄成自己的状态枚举。
class Manifest(BaseModel):
    status: str
    warnings: list[str]
    message: str
    ok: bool                     # 只读属性 status == "ok"，不进 JSON，命令行判定用

class FetchManifest(Manifest):

precompile把原文变成一份带中文排版设置、能编译通过的单文件 LaTeX，产出基线work（失败时）
任务
  1. 选主文件：src/ 里带 \documentclass 的 .tex；选不出来 → main_not_found，选不唯一 → main_ambiguous
  2. 展开成单文件：用 latexpand 把 \input / \include 全部内联，有 .bbl 就一并内联进去；展开失败 → expand_failed
  3. 注入中文排版设置：在前导区加上 xeCJK 与中文字体（字体来自 fonts 配置）。放在这一步而不是 compile，是让宏包冲突在翻译之前暴露并修掉：之后 compile 与这里的差别只剩正文文字，再出错只可能是译文引起
  4. 编译：搭编译目录 build/sandbox/tex/（src/ 的完整拷贝，加上展开后的 flat.tex 与字体目录 fonts/，latexmk 就在这个目录里跑，不碰 src/），用 latexmk -xelatex 编译；通过就记下页数等基线计数。结束时 latexmk -C 清掉中间文件，这个目录留给 compile 直接使用
  5. 编译不通过 → 修复会话：拉一次 agent work（角色 precompile_fix）在编译目录里改 flat.tex，然后重新编译一次，结论只认这一次；仍不通过 → compile_failed。agent 改过的 flat.tex 就是本阶段输出的 build/precompile.tex；它对编译目录里其他文件（cls、sty）的改动留在 build/sandbox/tex/，compile 在同一个目录里编译，自然沿用

细节与常量
  • 主文件判定：候选是注释外含 \documentclass 或 \documentstyle 的 .tex；多个候选时取唯一含 \begin{document} 的，再不唯一取名为 main.tex 的；main_ambiguous 时 message 列出全部候选
  • 展开：latexpand --keep-comments --fatal，超时 10 秒；主文件旁有同名 .bbl 且全文恰有一处 \bibliography{} 时，把 .bbl 内容替换到该命令处。展开结果必须非空且含 \begin{document} 与 \end{document}；仍残留 \input 的行数记 warning
  • 注入块：\documentclass 之后插入 xeCJK 设置，Path 指向编译目录里的 fonts/，断行按中文规则，行距 \linespread{1.4}。文档已经用 xeCJK / ctex 一族则不注入；用旧式 CJK 宏包（CJK CJKutf8 CJKspace CJKpunct）时，先从 \usepackage 里删掉这些包名、删掉 \begin{CJK} / \end{CJK} 与 \CJKfamily{…}，再注入 xeCJK
  • 编译目录 build/sandbox/tex/：src/ 整体拷贝 + flat.tex + 仓库的 fonts/。命令 latexmk -xelatex -interaction=nonstopmode flat.tex，超时 600 秒；通过的判据是退出码 0、flat.pdf 非空、flat.log 解析出的页数 > 0；latexmk 跑不起来或超时 → compile_failed
  • 修复会话：现场就是编译目录，agent 自己读 skill 与 flat.log；会话结束 latexmk -C 清掉中间产物再校验编译；会话以 error / timeout 结束记 warning，判定仍由校验编译给出

mask不该翻译的部分换成 placeholder
任务
  1. 读取 precompile.tex，判定每个 LaTeX 环境该不该翻：文内自己定义的环境（\newtheorem 一类）算正文，其余查 environments.json，查不到的当作不翻
  2. 摘走不翻的部分：前导区与尾部、注释、行间公式、图表 / 代码 / 算法 / 参考文献等环境、标题作者等元数据，每块换成 ⟦BLK-n⟧，原文存进 blocks.json。正文类环境（theorem、abstract、center…）保留 \begin / \end，只摘里面的块
  3. 把要翻的文字从块里抽回来：图表的 caption、前导区里的 abstract，各换成 ⟦CAP-n⟧，压成单行放在正文里跟着一起送翻
  4. 往返自检：unmask(mask(tex)) == tex——用 blocks.json 把 masked.tex 还原，必须与 precompile.tex 逐字符相同；不同 → mask_failed
  5. 写 masked.tex 与 blocks.json

细节与常量
  • 读取按 UTF-8 严格解码。文中已经出现 ⟦ ⟧ 即 mask_failed，placeholder 靠这两个字符唯一
  • 环境判定按序查：文内 \newtheorem / \newenvironment / \renewenvironment 声明过 → text；environments.json 有条目（X* 查不到退回 X）→ 取表里的 class 与 category；都没有 → non_translatable / unknown。判定与来源记进 manifest 的 environments
  • 摘块的种类：preamble（文件头到 \begin{document}）、postamble（\end{document} 到文件尾）、comment（连续整行注释合成一块，行尾注释单独一块）、math（$$…$$、\[…\]；行内 $…$ 与 \(…\) 留在正文）、non_translatable 环境（category 为 math / table / figure / tikz / code / algorithm / bibliography / box / unknown，嵌套时整个外层一块）、metadata（\title \author \date \affiliation \email 的花括号参数）。\verb 跳过不摘。每块记 category、环境名、判定来源、内含的 \label、字符区间与行号
  • 抽 caption：块内的 \caption{…}、\captionof{…}{…}，以及前导区里的 abstract 环境正文（revtex 一类把摘要写在前导区，它属于 preamble 块 BLK-0）。块的原文里该位置换成 ⟦CAP-n⟧；masked.tex 里紧跟 ⟦BLK-n⟧ 另起一行放「⟦CAP-n⟧ 压成单行的 caption 原文」。code 类块不抽 caption
  • 往返自检失败时 message 给出第一处差异的位置与上下文。没遇到 \end{document} 记一条 warning，不算失败

# ===== build/blocks.json —— placeholder 与原文的映射；survey 取 abstract，compile 回填 =====
class BlocksFile(BaseModel):
    blocks: list[BlockRecord]
    captions: list[CaptionRecord]

class BlockRecord(BaseModel):
    id: str                          # BLK-n
    category: "math"|"table"|"figure"|"tikz"|"code"|"algorithm"|"bibliography"|"box"|"unknown"|"preamble"|"postamble"|"comment"|"metadata"
    environment: str                 # 环境名；前导区、注释等非环境 block 为空
    decided_by: "newtheorem"|"newenvironment"|"table"|"default" | None   # 环境 block 的判定来源；其余为 None
    labels: list[str]               # block 内的 \label
    tex: str                         # 原文，回填用
    start: int; end: int              # 在 precompile.tex 字符序列上的区间
    line: int

class CaptionRecord(BaseModel):
    id: str                          # CAP-n
    block_id: str                    # 所属 block；前导区 abstract 属于 preamble block（BLK-0）
    kind: "caption"|"abstract"
    tex: str                         # 原文整条命令 / 环境
    masked_text: str                 # tex 压成单行；masked.tex 里跟在 ⟦CAP-n⟧ 后面送翻的就是它
survey切 chunk，整理术语表与全文语境ask（可选）
任务
  1. 切 chunk：按章节把 masked.tex 切成大小适中的片段，每片一个文件放进 chunks/，按序拼回必须恒等于 masked.tex；切不出来 → chunk_failed
  2. 模型提议术语表（可选）：一次 ask（角色 survey_terms），给它摘要、标题树与全文，让它列出本篇的术语译名与不该翻的词；模型不可用就当没提议，记 warning
  3. 合并术语表：把模型提议与用户写的三层术语表合成一份（层次、命中与冲突规则见 术语表 卡），全文没出现的词过滤掉，用户写的 style（给译者的额外要求）原样带上。术语表文件格式不对 → glossary_invalid
  4. 取全局语境：原文摘要与章节标题树
  5. 写 brief.json：摘要、标题树、术语表、style、chunk 清单，translate 只读这一个文件加 chunks/

# ===== build/brief.json：translate 只读这一个文件加 chunks/ =====
class BriefFile(BaseModel):
    abstract: str | None                   # 论文原文摘要，原样抄录；两条来路都找不到时为 null，记一条 warning，不算失败
    heading_tree: list[Heading]             # 全文章节标题树，按文档顺序；一个标题都没有时为空列表
    terms: list[TermEntry]
    do_not_translate: list[DoNotTranslateEntry]
    style: str | None                      # 用户写给译者的额外要求；三层术语表都没写时为 null
    chunks: list[ChunkRecord]

# 一条标题。全文标题树与 chunk 内的标题清单用同一个类，chunk 内的 depth 也按全文的口径填。
class Heading(BaseModel):
    command: str                  # 标题命令名：section / subsection 等；星号变体记作无星号的名字
    argument: str                 # 标题参数的原文，未翻译
    depth: int                    # 相对深度：全文最浅的层级记 1，每深一级加一

class TermEntry(BaseModel):
    word: str                     # 原文写法，取胜出那一层的写法
    translation: str              # 本篇的译法，translate 按它约束用词
    decided_by: "survey" | "global" | "paper" | "cli"   # 胜出的层；survey 是模型提议，最低层

class DoNotTranslateEntry(BaseModel):
    word: str
    decided_by: "survey" | "global" | "paper" | "cli"

class ChunkRecord(BaseModel):
    id: str                       # 形如 c012
    start: int; end: int           # 在 masked.tex 字符序列上的区间，chunk 文件的内容就是这个切片
    part: "front"|"body"|"appendix"
    tokens: int                   # tiktoken 数出的实际 token 数，只用于分块决策
    paragraphs: int
    headings: list[Heading]       # chunk 内不在任何环境里的标题（可穿透的环境不算），按文档顺序
    translatable_chars: int       # 剥除 placeholder 后的非空白字符数；为 0 表示整个 chunk 只有 placeholder，translate 不调模型

# ===== build/manifests/survey.json =====
class SurveyManifest(Manifest):
    status: SurveyStatus
    chunks_total: int
    transparent_environments: list[str]   # 切 chunk 时当作可穿透（允许从中间切开）的环境名
    terms_total: int
    do_not_translate_total: int
    filtered: list[FilteredTerm]       # 全文未命中、被过滤掉的术语

class FilteredTerm(BaseModel):
    word: str
    decided_by: "survey" | "global" | "paper" | "cli"
translate调用大模型翻译，并进行脚本校验ask
任务（每个 chunk 各走一遍，线程池并发，结果按文档顺序落盘）
  1. 纯 placeholder 的 chunk 直接跳过（translatable_chars 为 0，比如整段都是公式、图表，或只有 \maketitle 一类命令）：原文即译文，不调模型，记 skipped
  2. 组装提示词：system = 翻译规则（skill/translate/SKILL.md）+ 论文语境（brief.json 里的摘要、术语表、style）+ 本 chunk 的相邻上下文；user = 「请翻译：」加围栏包住的待译正文。结构见下方「提示词」
  3. ask 一次，拿回译文
  4. 脚本校验：译文的 LaTeX 骨架必须与原文一致——占位符一个不少、命令一个不少、括号与 $ 没错配、段落数一样（见下方「校验」）。全过 → translated
  5. 不过 → 重试一次：在同一段对话里追加「上一次的译文 + 各层差异说明 + 请修正并重新输出完整译文」再 ask 一次。每个 chunk 至多 2 次 ask
  6. 仍不过 → fallback：译文文件写原文，manifest 记最后一次没通过的层，warnings 记一条。回退件是原样的合法 LaTeX，编译得过，由 review 补翻
  7. 全部跑完一次写出 build/translated/。回退多少都照常写出；translate_failed 只留给读不到输入、配置错这类跑不起来的情况，不因回退多而中断（中断只会丢掉已翻好的 chunk）

校验：译文的 LaTeX 骨架必须与原文完全一致，只有文字变了

模型翻译时会丢命令、吞掉公式占位符、合并段落，这些错误编译时才暴露，或者编译过了但内容缺了一块。所以每个 chunk 译完先按下面四条机械比对原文与译文，任何一条不过就把差异说明回灌给模型重译。四条都不含判断，只数东西。

检查怎么算过回灌给模型的差异说明
占位符一个不少
placeholders		原文里每个 ⟦BLK-n⟧ / ⟦CAP-n⟧ 译文里都在，没有多出来的，也没有残缺的（如 ⟦BLK-3⟧⟧）「译文缺少 ⟦BLK-12⟧；多出 ⟦BLK-21⟧」
LaTeX 命令一个不少
control_sequences		每个命令（\cite、\emph、\section*…）在原文与译文里出现的次数相同；带星号的算另一个命令「\cite 原文 3 次、译文 2 次（第 29 段，源文开头 "Results on…"，该段原文 1 次、译文 0 次）」
括号与数学符号没错配
braces_and_math		{ } 配对；$ 成对且不比原文少；裸 % 不比原文多（裸 % 会把那一行后半截整个注释掉）「{ } 在第 312 字符处不平衡」「$ 原文 14 个、译文 12 个（第 29 段…）」
段落数一样
paragraph_count		有正文的段落数相同。只含占位符、只含 \maketitle \cite{…} 一类命令的段不算，模型把它们合并进相邻段不算错「原文 9 段、译文 8 段」
  • 命令计数：取 \cmd 的命令名，带紧随的星号；\% 一类符号控制序列取符号本身。差异说明在原文与译文段数相等时按段定位，给出段号、该段源文开头与该段的两边计数
  • 括号：未转义的 { } 深度不转负、结尾归零；原文本身就不平衡时不查。$ 与 % 都只数未转义的
  • 段落数：比较前先把分节命令（\section 一族与 \paragraph 一族）后的空行两侧规范化——这类空行不改变渲染，2412.19437 的 c007 曾因此整块回退。一段剥除 placeholder、\begin{X} / \end{X}、不含正文的命令连同其参数（\label、\cite 一族、\vspace \hspace、\bibliography 等，清单在 NON_TEXT_COMMAND_RE）、其余命令名之后仍有非空白字符才计入
  • 同一份实现（tongtu/validation.py）三处用：translate 的出口校验、tongtu validate 命令、review 阶段对 agent 修订的校验；compile 对正文控制序列的比对只用第 2 条
细节与常量
  • 译文整段包在代码围栏里时剥掉围栏再校验
  • 重试的两种触发：校验不过 → 续写一轮（assistant = 上一次译文，user = 差异说明 + 请重新输出完整译文）；ask 报错或返回空 → 直接再 ask 一次，不带差异说明。无论哪种，每 chunk 至多 2 次 ask，第二次之后必定得出 translated 或 fallback
  • 并发数由 --jobs 给出，记进 manifest 的 jobs；结果按文档顺序写出，中途被杀不留半套产物
  • 每个回退的 chunk 在 warnings 记一条（chunk id + 最后一次未通过的层）。原先的 0.2 回退比例门与 fallback_ratio 字段已于 2026-08-25 去掉
  • translate_failed 的三个出口：读不到 brief.json / chunks/；读不到 SKILL.md 或它的 frontmatter 没有 version；角色配置解析失败

术语表用户控制译名的入口，survey 读取并合并，translate 与 review 按它用词

glossary告诉译者哪些词怎么译、哪些词不译
规则
  1. 写在哪：三层文件，后一层覆盖前一层——全局 $XDG_CONFIG_HOME/tongtu/glossary.json（所有论文共用）→ 论文工作目录根的 glossary.json（只对这篇）→ 命令行 --glossary FILE（可给多个，靠后的优先）。模型在 survey 阶段的提议算第零层，任何一层用户写的都盖过它
  2. 写什么：terms 是「原文写法 → 本篇译法」的映射；do_not_translate 是保留原文不译的词（缩写、产品名、代号）；style 是一段写给译者的额外要求（语气、称呼、译者注开关一类）。三段都可以省略
  3. 怎么算命中：按整词匹配，认单复数（LLM 命中 LLMs），全大写的词区分大小写、其余不区分。全文没命中的词不进 brief.json，记进 survey manifest 的 filtered，方便发现拼错的词
  4. 复合术语：一条术语的原词里含有某个不译词时，译法里必须原样保留它——mixed RL training 写作「混合 RL 训练」，不能写「混合强化学习训练」
  5. 冲突：同一个词在两层里写法不同是覆盖，不是冲突；同一层里既在 terms 又在 do_not_translate 是格式错误，survey 以 glossary_invalid 停下。模型提议与用户写的相冲突时丢模型的那条
  6. 改了之后：合并结果在 build/brief.json，翻译前可以打开检查；改术语表后 tongtu run --from survey 重新合并

字体配置models.toml 的 [fonts] 表，precompile 注入中文排版设置时读取

fonts切换译文 PDF 的中文字体，改 models.toml 即生效，无命令行选项
规则
  1. 四个槽位：main 正文、bold 粗体（BoldFont）、sans 无衬线、mono 等宽。sans 不写则按平台探测（Hiragino Sans GB → Noto Sans CJK SC → 霞鹜文楷），mono 不写则用 main
  2. 取值两类：字体文件——.ttf / .otf / .ttc，写仓库 fonts/ 里的文件名或一个文件路径（可用 ~），precompile 把文件拷进编译目录的 fonts/，以 Path={fonts/} 相对引用，编译目录保持自包含；系统字体名——不带扩展名即视为字体名，由 fontspec 按名字查找
  3. main / sans / mono 可写成列表按序回退（同 CSS 的 font-family）：每个字体名候选包一层 \IfFontExistsTF，存在就用，不存在试下一个；文件候选必然可用、终止链条，它之后的候选不会被用到（写 warning）；候选全是字体名时，末尾自动补默认霞鹜文楷作为最后一级回退。单个字体名不包检测，写错由编译失败暴露
  4. bold 是单值，与候选同类（文件配文件、字体名配字体名）才配对；默认的 bold 只与默认的 main 配对，不跟随换掉的字体；与所有候选都配不上时写 warning 并忽略
  5. 失败不抛异常：配置的字体文件不存在则跳过该候选并写进 manifest 的 warnings，候选全部不可用时用默认字体
