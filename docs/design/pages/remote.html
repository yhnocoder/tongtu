通途远程运行设计

服务器上常驻一个 tongtu server，为每篇论文启动一个容器运行整条流水线；打 tag 后自动部署。Mac 上原生开发，用 release 版 tongtu 与 Raycast 翻译论文，用同一份 compose 在本机起 server 做上云前的测试。同时合并配置与数据目录、打包全部字体、重做模型调用层。

01

四个场景

场景代码来源怎么启动数据更新
① Mac 原生开发工作树uv run tongtu run ID --dev~/.tongtu-dev改代码即生效
② Raycast 翻译论文uv tool install 装的 releaseRaycast 调用 tongtu；在哪跑看 hosts.toml 的默认值~/.tongtuRaycast 的「更新 tongtu」命令一键更新：查 GitHub 上最新的 release tag，执行 uv tool install --force git+…@<tag>
③ Mac 上的 Docker 测试工作树，构建在 release 的 env 层之上docker compose up -d --build，再 uv run tongtu run ID --dev --on local~/.tongtu-dev重新 up -d --build
④ 服务器release 镜像打 tag 后 Actions 自动部署/root/.tongtu自动，保留两个版本可回滚
  • ③ 与 ④ 用同一份 compose.yml，区别只在 .env。命令行与 server 都不管理 server 容器的生命周期。
  • Claude 云端环境里，会话中的 AI 直接执行 tongtu run，再把产物的下载链接给出来。
  • work 支持 codex、claude-code、pi；ask 支持任意服务商与三种接口。

不在这一期：网页与手机客户端本身（接口在这一期定好，前缀 /v1）、队列与并发上限。

02

运行环境

环境隔离边界可用运行时凭据来自
Mac 原生codex 与 claude-code 自带的沙箱（Seatbelt）；pi 没有三种Mac 上的常规登录
论文容器（Mac 测试 server 或服务器）容器三种从所在机器的登录派生
Claude 云端整台一次性虚拟机claude-code、pi会话自带的 Claude 登录；DeepSeek 的 key 在环境变量里

后两种是隔离环境：设置 TONGTU_ISOLATED=1（镜像里设好，云端 setup 脚本里 export）。运行时据此决定参数，见 10。云端环境是原生 Linux，不用 Docker；setup 脚本只需装 TeX Live、tongtu 与需要的 CLI，字体随包走，不再装 fonts-noto-cjk、bubblewrap、socat。

03

目录：一个 TONGTU_HOME

$TONGTU_HOME/                默认 ~/.tongtu；开发与本机测试用 ~/.tongtu-dev（--dev）
  config.toml                服务商、角色、分块、字体（原 models.toml）。不含 tongtu 自己的 token
  hosts.toml                 0600。默认位置、各 server 的 url 与 token；跑 server 的机器上另有 serve_token
  claude-code-token          0600。claude setup-token 生成，只在隔离环境里用
  glossary.json              全局术语表
  papers/<id>/               论文目录，内部结构与现在相同
  • 配置与数据放在一处，XDG_CONFIG_HOME 不再使用。新用户直接 uv run tongtu run ID，用的就是 ~/.tongtu。
  • tongtu 自己的 token 全在 hosts.toml，所以 config.toml 可以原样挂进论文容器。
  • codex 与 pi 的凭据留在它们的标准位置 ~/.codex、~/.pi/agent，每台机器上登录一次。开发版的 claude-code-token 可以软链到正式版那份。
  • 现有的 ~/.config/tongtu/models.toml 与 ~/.local/share/tongtu/* 手动移过去一次，不写迁移代码；旧路径存在时 doctor 提示。CLAUDE.md 基本原则第 4 条里的默认路径随之修改。

  • 命令行只有两条路径：原生运行，或调用某个 server 的 REST 接口。
  • 启动器只有 server 调用：为一篇论文派生凭据、按固定参数启动论文容器，镜像与 server 自己相同。
  • server 与论文容器相互独立：重启、升级、重建 server，不影响正在跑的论文。server 的状态全部从文件和 Docker 读出，没有自己的数据库。
  • Raycast 只调用 release 版命令行（status --json、run、pull），不直接访问 REST，也不再 uv run --directory 仓库。另有「更新 tongtu」命令，把 release 版更新到 GitHub 上最新的 tag。
05

镜像

  • 三层不变：base（TeX；ca-certificates 已在这一层）、env（Python 依赖、字体，以及新加的 node 22、codex、claude-code、pi，CLI 版本用 ARG 固定）、runtime（COPY 加 uv sync）。设 TONGTU_ISOLATED=1。字体全部随包打包（11），镜像不再装 fonts-noto-cjk，也不做 fontconfig 注册。
  • 镜像 tag 与分支：image.yml 只在 push main 与打 v* tag 时推送。
  • runtime 阶段写成 FROM ${ENV_IMAGE}：CI 里指本文件的 env 阶段；本机 compose 里指 ghcr.io/yhnocoder/tongtu:env，BuildKit 只构建用得到的阶段，所以本机只构建 runtime 层。改动涉及 base 或 env 层时，本机拿不到新的 env，先用 image.yml 推 :dev 再测。
  • 不改为只装 wheel：仓库除去字体（env 层已单独复制）只有约 1MB，省不下体积。.dockerignore 补上 raycast/node_modules。
  • server 与论文容器用同一个镜像，启动命令不同（tongtu serve 与 tongtu run）。
  • 只有 x86_64，Mac 上经 Rosetta 运行，实测编译慢 1.3 到 1.6 倍，每篇多几秒。
06

compose 与部署

仓库根目录一份 compose.yml，两个服务。默认值按 Mac 测试设定，服务器用 .env 覆盖。

服务要点
servercontainer_name: tongtu-server，restart: unless-stopped，platform: linux/amd64，命令 tongtu serve，端口 127.0.0.1:8787。挂 docker.sock、数据目录、~/.codex、~/.pi/agent（只读），一律 bind 且挂在与宿主相同的路径，容器内 HOME 设成宿主的 HOME
cloudflaredprofiles: [tunnel]，只在服务器上启动；network_mode: host
变量默认（Mac 测试）服务器 .env
TONGTU_IMAGEtongtu:local，由 --build 从工作树构建ghcr.io/yhnocoder/tongtu:<tag>
TONGTU_HOME_DIR~/.tongtu-dev/root/.tongtu
TONGTU_CODEX_REFRESH01
COMPOSE_PROFILES空tunnel
TUNNEL_TOKEN无部署时手写一次
  • 宿主目录挂在相同路径，是因为 server 通过 docker.sock 启动论文容器时挂载路径按宿主解析。挂 docker.sock 等于给 server 宿主的 root 权限，论文容器不挂它。
  • 对外暴露：服务器只经 Cloudflare Tunnel，不开端口；Mac 只监听 127.0.0.1。server 校验 Authorization: Bearer，与 hosts.toml 的 serve_token 比对。
  • codex 刷新：只有 TONGTU_CODEX_REFRESH=1 的 server 刷新，所以 Mac 上的测试 server 不会与 Mac 原生的 codex 抢同一个 refresh token。按需进行，没有定时任务：派生凭据前 access token 已过期，就在 server 容器里执行一次 codex exec，由 codex 自己刷新并写回 ~/.codex/auth.json，再派生。运行中途过期的，那次运行以 failed 结束，用 run --from 接着跑。Mac 测试 server 遇到过期 token 报错，提示在 Mac 上原生运行一次 codex。

自动部署

  1. 推 tag 后 image.yml 构建并推送镜像，之后的 deploy job 用 GitHub secret 里的部署密钥 ssh 到服务器，参数只有 tag。
  2. 这把密钥在服务器 authorized_keys 里绑定 command="/opt/tongtu-deploy/deploy.sh",no-pty,no-port-forwarding，只能执行部署脚本。
  3. deploy.sh：校验 tag 格式；从这个 tag 取 compose.yml；改写 .env 里的 TONGTU_IMAGE；docker compose pull 与 up -d --no-build；删掉 tongtu 镜像中当前与上一个版本以外的，正在被论文容器使用的删不掉就跳过。
  4. 回滚：在服务器上执行 /opt/tongtu-deploy/deploy.sh 0.1.9。两个版本共用 base 与 env 层，多保留一个版本只多占 runtime 层。
  5. /opt/tongtu-deploy/ 下的 deploy.sh、.env 与部署密钥第一次手动放好，见 T10。

进现场排查

没有专门的命令。原生运行直接进论文目录。容器里运行的，进 server 容器：

docker compose exec -w ~/.tongtu-dev/papers/ID server bash                    # Mac 测试 server
ssh remote_vps docker exec -it -w /root/.tongtu/papers/ID tongtu-server bash  # 服务器

server 容器里的 TeX 与论文容器相同，手动复现 latexmk 足够；那里能看到主凭据，HOME 也与论文容器不同。要重跑 agent 阶段，用 run --from。

07

REST 接口

前缀 /v1。网页端以后单独部署，与 server 不一定同时升级，接口变了靠前缀区分。

接口作用
POST /papers/{id}/runs启动一次运行。只接受 arXiv 编号。请求体：与 run 相同的选项，论文层术语表（JSON）。返回 202；已在运行返回 409
GET /papers?since=论文列表与运行状态，按更新时间倒序；默认最近两天
GET /papers/{id}一篇的阶段表与运行状态
GET /papers/{id}/files/{path}下载文件，支持 Range。path 是目录时返回 tar。跟随日志就是每 2 秒带 Range: bytes=N- 取一次 logs/run.log
POST /papers/{id}/stop停止运行
GET /health版本与 doctor 结果

09

运行状态与日志

  • 每次运行把输出追加写入 logs/run.log，开头一行记时间、版本、参数、镜像，结尾一行记退出码。原生运行也写。
  • 运行期间在论文目录写 run.pid（原生是进程号，容器方式是容器名），结束删除。
  • 跟随日志一律是「从字节偏移 N 往后读」：原生读本地文件，server 用 Range 请求。
状态条件
running有 run.pid，且对应的进程或容器还在
done不在运行，compile 的 manifest 为 ok
failed不在运行，某阶段 manifest 为失败状态
interrupted不在运行，其余情况（被打断、主机重启、OOM、stop）

11

字体

  • 打包全部中文字体：现有的霞鹜文楷 Light 与 Medium，加一套开源黑体（如思源黑体 SC）作无衬线字体，总计不到 100MB。任何环境生成的 PDF 用同一套字体。
  • [fonts] 有 main、sans、mono 三个键。main 与 sans 写一族字体：写一个文件表示只有常规字形，写成 { regular, bold } 同时给出粗体；mono 写一个文件，不写时用 main 的常规字体。取值只接受字体文件名、绝对路径或以 ~ 开头的路径，不接受系统字体名、回退列表与相对路径。
  • 一族里有文件找不到时，这一族整体改用自带字体并给出警告，不把用户的粗体和自带的正文拼在一起：混搭能通过编译检查，读者看到的却是另一字族的粗体。没有粗体文件的字族由 xeCJK 生成伪粗体，AutoFakeBold=2（xeCJK 默认 4，在霞鹜文楷上笔画发糊），让章节标题与 \textbf 里的中文保持粗体。
  • zh.tex 只按文件名引用字体，不写路径，不按机器挑选系统字体，不建软链接。编译时 tongtu 把包内字体目录经 TTFONTS、OPENTYPEFONTS 交给 XeTeX（本机已用最小 xeCJK 文档验证），修复会话的环境里也设置它们。
  • 论文目录因此可以在 Mac、服务器、容器之间直接搬动。
12

安全取舍

  • 隔离环境是唯一的边界。agent 能联网，能读到这次运行的派生凭据与服务商 key。最坏情况是这些凭据被滥用，宿主、主凭据与其他论文不受影响。
  • token 一律明文存文件：每种凭据只存一份，文件 0600、目录 0700，不进日志；进论文容器的只有派生或能力受限的凭据。
  • server 挂 docker.sock，接口必须认证。服务器上只经 Cloudflare Tunnel 暴露，Mac 上只监听 127.0.0.1。
  • 部署密钥只能执行 deploy.sh，泄漏后最多被用来部署一个已经公开的 tag。

已实测

2026-10-01 到 10-02 在本机 Mac（arm64）与服务器 remote_vps 上实测，实验产生的容器、镜像、临时文件都已清理。

主题结果用在
服务器环境Ubuntu 24.04.5，x86_64，Docker 29.8.1，docker compose v5.5.1，root，4 核 7GB 内存，可用磁盘 44G；80、443 已被其他服务占用。Mac 上 docker compose v5.1.206
