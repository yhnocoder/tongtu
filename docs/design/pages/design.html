通途设计

五个阶段

tongtu run 依次运行五个阶段。每个阶段读上一个阶段的产物，写出自己的产物和一份 manifest。只有 translate 每次都启动 agent 会话；precompile 与 compile 只在展开或编译失败时各启动一次修复会话。

  1. 1fetch查询版本与论文信息，下载并解包源码规则
  2. 2precompile展开成单文件，加入中文排版设置，确认原文能编译规则；失败时一次修复会话
  3. 3mask把公式、图表、代码等不翻译的部分换成占位符规则
  4. 4translate一次会话译出全文，会话外重跑校验agent 会话
  5. 5compile把占位符换回原文，编译中文 PDF规则；失败时一次修复会话

一次成功的运行在 out/ 下写出五个文件，文件名都带论文编号与版本号：

文件内容写出的阶段
<ID>.zh.pdf中文 PDFcompile
<ID>.zh.anchors.json译文每个块在 PDF 上的位置，供阅读器在原文与译文之间按块对照compile
<ID>.meta.json论文信息：题目、作者、摘要、分类、版本、日期fetch
<ID>.glossary.json本篇实际使用的术语表translate
<ID>.notes.json各次 agent 会话记下的问题、处理办法与预期的解决方法，供之后补充 skill 与规则启动过会话的阶段

设计遵守四条原则：

  • 翻译的依据是 arXiv 提供的 LaTeX 源码。编译能否通过由机器检查。
  • 翻译由 agent 完成，结果是否正确以校验脚本为准。脚本不对翻译过程做细粒度控制。要提高译文质量，就修改提供给模型的信息，即 skill 与术语表。
  • 能用规则处理的编译问题，由 precompile 的前导区改写规则在编译之前处理。修复会话只在按规则处理之后展开或编译仍然失败时启动，每个阶段最多一次。同一类修复在多篇论文的修复日志里重复出现时，把它写成规则。
  • 论文工作目录不在仓库内。

理由只支持 xelatex 一个引擎。中文排版用 xeCJK；precompile 与 compile 用同一个引擎、同一份前导区，两次编译的差别只剩正文文字，compile 出错时原因只可能在译文。

命令行

tongtu run      PAPER [--mode fast|smart] [--latest] [--from STAGE] [--glossary FILE]... [--workdir DIR] [--dev]
tongtu stage    STAGE PAPER [--mode fast|smart] [--glossary FILE]... [--workdir DIR] [--dev]
tongtu status   PAPER [--json] [--workdir DIR] [--dev]
tongtu validate SRC DST [--glossary FILE]...
tongtu doctor
tongtu config   [list | set KEY VALUE | open] [--dev]
tongtu          --version

PAPER 是 arXiv 编号、arXiv 链接或本地源码目录。STAGE 取 fetch、precompile、mask、translate、compile 之一。终端输出、manifest 的 message 与 warnings 一律用英文。

选项

选项适用命令作用
--mode fast|smartrun、stage本次运行的 agent 会话用哪个模式，不给时取 config.toml 的 [modes] default。见模式与 agent 会话。
--latestrun向 arXiv 查询最新版本并使用它。见论文编号与版本。
--from STAGErun从这个阶段起重跑，先删掉它及其下游的旧产物。
--glossary FILErun、stage、validate本次运行追加的术语表，可以给多个，靠后的优先。
--workdir DIRrun、stage、status直接指定论文工作目录，代替按 PAPER 推出的默认位置。目录里已有 fetch 的 manifest 时，PAPER 必须是同一篇论文：编号相同；或者 manifest 记的是本地源码目录，PAPER 是同一个目录，或者是这个目录的名字。PAPER 不带版本号时取 manifest 里的版本；PAPER 写明的版本或 --latest 查到的版本与 manifest 不同时，命令报用法错误，退出码 2。
--devrun、stage、status、config等于 TONGTU_HOME=~/.tongtu-dev。

run

每个阶段结束后终端输出一行结果，阶段的 message 与 warnings 各占一行，缩进在结果行下方。阶段运行时显示一行进度，只在终端是 tty 时刷新。translate 的进度行显示耗时和会话当前的动作，例如正在读原文、正在写哪个文件、正在运行检查。

示例输出为示意

$ tongtu run 2412.19437 workdir ~/.tongtu/papers/2412.19437v2 mode smart claude-code/claude-opus-5-5 medium stage status summary elapsed ✓ fetch ok v2, tar.gz, 14 tex files 0:00:03 ✓ precompile ok 66 pages 0:00:41 ✓ mask ok 183 blocks masked 0:00:00 ✓ translate ok 164 paragraphs, 31 new terms 0:09:55 ✓ compile ok 56 pages, baseline 66 0:00:47
情形行为退出码
全部阶段成功写出 out/ 下的五个文件。0
某个阶段失败停在出错的阶段，终端输出原因与 manifest 路径。处理后再执行一次同样的命令，从这个阶段接着跑，前面的阶段不重做。1
运行被打断再执行一次，从中断的阶段接着跑。非 0
五个阶段都已完成不做任何事，提示用 --from。0
参数不合法PAPER 无法识别，--latest 与带版本号的编号同时出现，或者 --workdir 里已有的论文与 PAPER 不一致。2

通途不检测输入是否变化。不给 --from 就沿用旧产物。改了输入之后，按下表选择起点：

改了什么从哪个阶段起重跑
src/ 里的源码，或 config.toml 的 [fonts]--from precompile
tongtu/data/environments.json--from mask
任何一层术语表、skill/translate/，或者想换一个模式重译--from translate
config.toml 的 [pdf]--from compile

其余命令

  • stage STAGE PAPER 只运行一个阶段。它先删掉本阶段的旧产物再运行，不改动其他阶段的产物。上游产物不存在时拒绝执行，退出 2。
  • status PAPER 只读，列出每个阶段的状态、产物是否存在和 manifest 路径。它不联网。--json 的格式见供其他程序读取的输出。
  • validate SRC DST 对一对掩码文件运行 translate 判定时使用的同一套校验，逐类输出问题，有问题时退出 1。给了 --glossary 才检查术语。手工修改译文后用它确认。
  • doctor 逐项检查环境：TeX 工具链（xelatex、latexmk、latexpand）、默认字体、config.toml、agentrun，以及每个模式引用的运行时与模型（对每个组合运行一次 agentrun doctor）。工具链或字体缺失时退出 1。config.toml 不存在不算缺失，这时检查默认的模式。工具链齐全时，退出 3 只在配置文件有错或运行时不可用时出现，这时 fetch、precompile、mask 仍然可以运行。
  • config 查看和修改 $TONGTU_HOME/config.toml，有四种用法：
    • tongtu config 打开选单，每行是一个配置项及其当前值，最后一行是 exit。选单只处理上、下方向键与回车。在布尔项或模式名（modes.default）上按回车，列出可选的值供选择；在其余项上按回车，提示输入新值，提示里显示旧值，直接回车表示不改。输入框里没有旧值的文本，不能在旧值上原地修改，只能输入完整的新值。标准输入不是终端时退出 2。
    • tongtu config list 每行列出一个配置项及其当前值。配置文件不存在时列出默认值，不写文件。
    • tongtu config set KEY VALUE 修改一项。KEY 是 list 列出的键，例如 modes.fast.model。VALUE 先按 TOML 的值解析，解析失败时当作字符串；空字符串表示清除这个可选字段。键不存在或值不合法时退出 2，不写文件。
    • tongtu config open 输出配置文件的路径并打开它。环境变量 EDITOR 非空时用它打开，否则用系统默认的程序。

    配置文件不存在时，tongtu config 与 open 先写出一份包含全部默认值的文件；set 在默认值上修改，修改成功时写出文件。校验失败时每条错误输出一行，格式是「键: 原因」。配置文件存在但加载失败时，config、list、set 输出错误并退出 1。config 与 set 每次修改都整份重写文件，文件里原有的注释不保留。

论文编号与版本

arXiv 的一篇论文有多个版本，各版本的源码可以不同。通途把「论文编号加版本号」当作一篇论文的标识，记作 <ID>，例如 2412.19437v2。工作目录名与 out/ 下的文件名都用它，所以同一篇论文的不同版本各有一个工作目录，互不覆盖。

命令里的写法使用哪个版本
2412.19437v2v2。
2412.19437本地已有这篇论文带版本号的工作目录时，用其中版本号最大的一个，不联网。本地没有时，run 与 stage fetch 向 arXiv 查询最新版本并使用它，其余命令报错，见下文。
2412.19437 --latest向 arXiv 查询最新版本。本地没有这个版本时新建工作目录从头运行；已有时沿用它。
2412.19437v2 --latest用法错误，退出 2。
arXiv 链接取链接里的编号，带版本号与不带版本号分别按上面的规则处理。
本地源码目录没有版本号，也不写论文信息。工作目录名取源码目录的名字。

版本要靠查询才能确定时，查询发生在建立工作目录之前，查询结果随后交给 fetch 写论文信息，一次运行只请求一次。这次查询失败时版本无法确定，run 把原因输出到终端并退出 1，不建立工作目录，也不写 manifest。版本已经确定时（命令里写明，或取自本地的目录名），API 请求由 fetch 发出，失败记为 fetch 的 download_failed。status 与 fetch 以外的 stage 不联网，遇到不带版本号的编号又没有 --workdir 时，只按本地已有的带版本号的工作目录解析。本地没有这样的目录时，命令把编号与 papers/ 的路径写到 stderr，提示先运行 tongtu run <编号>，退出 1。v0.1 留下的不带版本号的目录不被识别。

选定的版本没有 TeX 源码时，fetch 的状态是 pdf_only，运行停在 fetch。message 写明是哪个版本没有 TeX 源码，并提示其他版本可能有源码，要试的话在命令里写明版本号。通途不自动改用别的版本。

理由读者需要确切知道自己读的是哪个版本。版本只在两种情况下确定：命令里写明，或者由通途查询后写进目录名、文件名和论文信息。

[modes.fast]

model 的写法是「运行时/模型」，只在第一个 / 处切分。运行时是 agentrun 支持的名字，目前只使用 claude-code。每个模式可以另写 timeout_seconds，不写时为 3600 秒。配置里出现未知字段时，加载配置报错。文件可以不存在，这时使用本节列出的值；文件里没写的字段也取本节的值。文件由 tongtu config 写出和修改。

manifest

每个阶段结束时写 build/manifests/<阶段>.json。各阶段的 manifest 继承同一个基类，status 在 JSON 里排第一。run 与 status 只读 manifest 判断一个阶段是否完成。

class Manifest(BaseModel):
    status: str            # 子类限定为本阶段的状态值
    warnings: list[str]
    message: str           # 失败原因；成功时为空

各阶段的规格

状态不是 ok 时，run 停在这个阶段。

fetch

确定版本，取论文信息，把源码放进 src/

做什么
  1. 向 arXiv API 请求一次（https://export.arxiv.org/api/query?id_list=<编号>），得到版本号与论文信息，写出 out/<ID>.meta.json。
  2. 下载这个版本的源码包（https://export.arxiv.org/e-print/<ID>），原始字节写进 build/e-print.bin。
  3. 按文件头判断格式并解包到 src/。格式可以是 tar.gz、tar、gz、单个 tex 或 PDF。tar 里的链接与设备文件不解包。
  4. PAPER 是本地目录时不联网，把目录内容拷进 src/，不写论文信息。

任何非 ok 的状态都把 src/ 清空，只保留 build/e-print.bin 供排查。论文信息文件 out/<ID>.meta.json 在 API 请求成功后已经写出，也保留。

状态
ok源码已解包，其中有可用的 TeX 文件。
pdf_only这个版本没有 TeX 源码：下载到的是 PDF，或者全部 .tex 的字符数少于 1000（源码里有 \includepdf 时为 5000）。
empty下载成功但内容为空，或者包里没有任何 .tex 文件。
download_failed版本确定之后的 API 请求失败或超时，或者源码下载失败或超时。
unpack_failed源码包解不开，或者本地目录拷贝失败。
source_missing指定的本地目录不存在。
写

src/、build/e-print.bin、out/<ID>.meta.json、build/manifests/fetch.json。

常量

每次网络请求的超时是 60 秒。

产物类
class FetchManifest(Manifest):

    arxiv_id: str | None       # 不带版本号；本地目录时为 null
    version: int | None
    kind: "tar.gz" | "tar" | "gz" | "tex" | "pdf" | "local" | None

    rejected: list[str]        # 解包时没有解出的 tar 成员

PaperMeta 的定义见供其他程序读取的输出。

precompile

把原文变成一份带中文排版设置、能编译通过的单文件

做什么
  1. 选主文件：src/ 里带 \documentclass 的 .tex。
  2. 用 latexpand 把 \input 与 \include 展开成单文件，有 .bbl 时一并内联。写在其他命令花括号参数里的 \input（例如 \resizebox{…}{!}{\input{fig}}）不展开，原样留给 TeX 在编译时读文件，每处在 manifest 里记一条 warning；裸分组与环境体里的照常展开。

    理由参数里的 \input 不展开。TeX 在执行到这条命令时才读文件；把文件内容内联进参数之后，内容按参数的方式读入，换行变成空格，依赖换行的内容（例如 pgfplots 的内联表格）读不出来，standalone 子文档的导言区也会进入主文件。这类文件里的文字不进入翻译，实际出现的都是图。

  3. 处理注释：整行注释整行删掉；行尾注释删掉文字，只留 %，因为行尾的 % 决定换行处是否留空白。代码环境与 \verb 里的 % 是正文，不改动。
  4. 前导区里取值确定的条件开关只保留生效的分支。
  5. 按 tongtu/preamble.py 的规则改写前导区里只适用于 pdflatex 的写法，再加入 xeCJK 与中文字体设置。行距是 \linespread{1.4}。
  6. 搭编译目录 build/sandbox/tex/：src/ 的完整拷贝，主文件换成展开后的单文件，文件名不变。在其中用 latexmk 编译，通过后记下页数等计数作为基线，PDF 拷出为 build/precompile.pdf。
  7. 展开时缺文件，或者编译不通过时，启动一次修复会话（skill precompile_fix），然后重新展开或编译一次，以这次结果为准。整个阶段只启动一次修复会话。
状态
ok编译退出码为 0，PDF 非空，日志解析出的页数大于 0。
main_not_found没有带 \documentclass 的 .tex。
main_ambiguous候选不唯一。message 列出全部候选。
expand_failed展开失败，修复会话之后仍然失败。
compile_failed编译不通过，修复会话之后仍然不通过；或者 latexmk 无法运行、超时。
读

src/、config.toml 的 [fonts] 与模式、skill/precompile_fix/。

写

build/precompile.tex、build/precompile.pdf、build/sandbox/tex/、build/manifests/precompile.json；启动过修复会话时另有 logs/precompile-fix.jsonl 与 out/<ID>.notes.json 里的条目。

常量

编译命令是 latexmk -norc -xelatex -interaction=nonstopmode -synctex=1 <主文件>，与 compile 共用，超时 600 秒。latexpand 的超时是 10 秒。

理由中文排版设置在翻译之前加入。宏包与 xeCJK 的冲突在这一步暴露并修好，修复的结果留在编译目录里，compile 直接使用。

理由主文件在编译目录里不改名。jobname 因此不变，作者随源码上传、按 jobname 命名的文件在两次编译里都能找到。

产物类
class PrecompileManifest(Manifest):
    status: PrecompileStatus
    main_file: str                  # 判定出的主文件
    report: CompileReport | None    # 编译通过才有，是 compile 的页数基线
    fix_session: Session | None     # 启动过修复会话才有

class CompileReport(BaseModel):
    pages: int
    pdf_bytes: int
    overfull_hboxes: int
    undefined_references: int
    undefined_citations: int
    missing_characters: int
    duration_seconds: float

Session 的定义见模式与 agent 会话。

mask

把不翻译的部分换成占位符

做什么
  1. 判定每个 LaTeX 环境是否翻译：文内用 \newtheorem 一类命令定义的环境算正文，其余查 tongtu/data/environments.json，查不到的不翻译。
  2. 把不翻译的部分逐块换成 ⟦BLK-n⟧，原文存进 blocks.json。
  3. 把块里需要翻译的文字抽出来：图表的 caption 与写在前导区里的摘要，各换成 ⟦CAP-n⟧，压成单行放在正文里，和正文一起翻译。代码块的 caption 不抽。
  4. 往返自检：用 blocks.json 把 masked.tex 还原，结果必须与 precompile.tex 逐字符相同。
换成占位符，不翻译留在正文里，翻译
前导区与 \end{document} 之后的内容摘要
题目、作者、日期、单位、邮箱正文段落、列表、脚注
行间公式定理、证明一类正文环境里的文字

代码、算法附录

translate

一次会话译出全文，会话外重跑校验

做什么
  1. 合并术语表，取出本篇命中的条目。规则见术语表。
  2. 搭会话目录 build/sandbox/translate/。
  3. 经 agentrun 启动一次会话，模型与强度取自本次运行的模式。会话读 .skills/translate/SKILL.md，在目录里写出 zh.tex，并运行 check.py 自查。
  4. 会话结束后，通途在会话目录之外重跑校验：用仓库里的校验脚本，比对 build/masked.tex 与会话写出的 zh.tex。
  5. 校验通过时，把 zh.tex 拷为 build/translated.tex，写出 out/<ID>.glossary.json，把本篇新定的术语并入已学术语表。
会话目录
build/sandbox/translate/
├── en.tex                   build/masked.tex 的拷贝，末尾没有换行符时补一个，只读
├── glossary.fixed.json      用户术语表里本篇命中的条目与 style，只读，必须照用
├── glossary.json            开始时是已学术语表里本篇命中的条目；会话可以修改和追加
├── .skills/translate/
│   ├── SKILL.md             翻译规则与工作顺序
│   ├── check.py             比对 en.tex 与 zh.tex，报告问题
│   └── validate.py          tongtu/validation.py 的拷贝，check.py 调用
├── zh.tex                   译文，由会话写出，与 en.tex 逐段对应
├── parts/                   长论文的译文先按节存在这里，写完后合并成 zh.tex
└── notes.json               会话结束前写出的问题记录

长论文的译文由同一个会话按 \section 的顺序依次写进 parts/，每写完一节存一个文件，全部写完后合并成 zh.tex。这只是同一个会话存盘的方式：术语表和前面各节的译文一直在这个会话的上下文里。

会话在 agentrun 的沙箱里运行，写入范围是会话目录。启动时带 --no-subagents，全部译文由这一个会话写出。会话的 PATH 里有 python3，用来运行 check.py。会话的事件记录写进 logs/translate.jsonl。

译什么

masked.tex 里留下的文字都翻译，有两处例外：\section、\subsection、\subsubsection 的标题保留英文，一个字符都不改；术语表里列为不译的词保留原文。题目属于元数据，已经在 mask 阶段换成占位符，所以也保留英文。\paragraph{} 的段首小标题照常翻译。

have been undergoing rapid iteration~\citep{gpt4o}.

⟦BLK-12⟧
⟦CAP-3⟧ Overview of the pipeline. $F$ denotes a forward chunk.

\paragraph{Optimizer} We use Adafactor
with a dropout rate of $0.1$.
zh.tex

快速迭代~\citep{gpt4o}。

⟦BLK-12⟧
⟦CAP-3⟧ 流程概览。$F$ 表示一个前向块。

校验

校验脚本逐段比对原文与译文，报告五类问题。会话里的 check.py 与通途在会话外运行的是同一套比对。

类别检查什么
结构段落数相同；每段的占位符、控制序列的数量、花括号与 $ 的配对与原文一致。每个 ⟦CAP-n⟧ 位于行首，所在行没有其他占位符，含 CAP 的段落行数与原文相同：compile 换回图表标题时取走 CAP 所在的整行。不含 CAP 的段落不检查行数。
公式每段的行内公式与原文逐个相同。
章节名三级章节命令的标题与原文逐字相同。
未译一段译文不含中文，却有 6 个以上小写字母开头的英文单词。只含人名、机构名的段落因此不算未译。
术语原文命中某条术语的段落，译文里出现对应的译法；不译词按大小写原样保留。\label、\ref、\cite 一类命令参数里的词不计。章节标题不参加未译与术语两项检查。

会话外的校验使用 build/masked.tex、用户术语表的原始文件，以及会话结束时的 glossary.json。会话改动 en.tex、glossary.fixed.json 或 check.py 都不影响判定。

理由判定放在会话之外。会话目录整体可写，会话自己报告的「检查通过」无法核对；在会话外用原始输入重跑同一套比对，结果只取决于译文本身。

状态
ok会话外的校验没有报告问题。判定只看校验结果：会话超时或出错，但留下的 zh.tex 通过校验时，状态仍是 ok，另记一条 warning。
glossary_invalid某一层术语表文件读不出来或格式不对；或者用户术语表里本篇用到的术语与不译词冲突：一条术语的原词含有某个本篇用到的不译词（按大小写原样匹配），译法却没有原样保留这个词。不启动会话。
translate_failed会话没有写出 zh.tex，或者校验报告了问题。问题逐条记在 manifest 的 problems 里。不写 build/translated.tex，compile 不运行。

translate_failed 之后会话目录保留。再执行一次 run 时，translate 先对保留下来的 zh.tex 重跑校验：通过就直接采用，不启动会话，手工改好译文后走的就是这条路径；不通过就在同一个目录里再启动一次会话，会话从已有的译文接着做。通途不另写问题清单：skill 规定会话发现 zh.tex 或 parts/ 已经存在时先运行 check.py，它报告的就是上次校验的那些问题，没有写完的章节也由它报告为段落缺失。--from translate 与 stage translate 先清空会话目录，从头翻译。

理由一次运行只启动一次翻译会话，校验不通过时通途不自动重开。脚本不对翻译过程做细粒度控制；同一类问题反复出现时，修改 skill 或校验脚本。

读

build/masked.tex、各层术语表、skill/translate/、tongtu/validation.py、config.toml 的模式。

写

build/translated.tex、out/<ID>.glossary.json、out/<ID>.notes.json、$TONGTU_HOME/glossary.learned.json、build/sandbox/translate/、logs/translate.jsonl、build/manifests/translate.json。

理由整篇论文在一次会话里翻译，全部译文由这一个会话写出。术语与专名的统一靠同一个上下文：会话先通读全文、定下术语，再逐节写译文，写后面的章节时看得到前面用过的译法。

compile

把占位符换回原文，编译出中文 PDF

做什么
  1. 用 blocks.json 把 build/translated.tex 里的 ⟦BLK-n⟧ 与 ⟦CAP-n⟧ 换回原文块，得到中文全文。行尾注释留下的 % 换回之后，如果它后面到行尾之间还有文字，就在 % 后面补一个换行。前导区在 precompile 已经加入中文排版设置，这里不再改动。
  2. 把中文全文写进 precompile 留下的编译目录，覆盖主文件，用同一条 latexmk 命令编译。
  3. 编译不通过时启动一次修复会话（skill compile_fix），然后重新编译一次，以这次结果为准。
  4. 检查出口判据，通过后拷出 out/<ID>.zh.pdf 与 build/zh.tex。
  5. 用 SyncTeX 文件算出 zh.tex 每个块在 PDF 每页上的矩形，写成 out/<ID>.zh.anchors.json。锚点写不出时只记一条 warning，阶段仍是 ok。
  6. [pdf] crop_margins = true 时，用 Ghostscript 量出每页内容的边界，把页边空白裁掉。只改 CropBox，排版、链接与锚点坐标不变。
状态
ok三条出口判据都满足：编译通过；译文页数与原文基线之比在 0.7 到 1.3 之间；启动过修复会话时，修复后的主文件与修复前写入编译目录的中文全文相比，每个控制序列的出现次数相同（tongtu/validation.py 的控制序列比对）。第三条用来发现修复会话为了让编译通过而删掉正文内容。
compile_failed任何一条不满足。这时不写 out/<ID>.zh.pdf 与 build/zh.tex。
读

build/translated.tex、build/blocks.json、build/manifests/precompile.json、build/sandbox/tex/、skill/compile_fix/、config.toml 的 [pdf] 与模式。

写

out/<ID>.zh.pdf、out/<ID>.zh.anchors.json、build/zh.tex、build/zh.synctex.gz、build/manifests/compile.json；启动过修复会话时另有 logs/compile-fix.jsonl 与 out/<ID>.notes.json 里的条目。

常量

页数比的范围是 [0.7, 1.3]，用来发现整章丢失或整章重复。编译超时 600 秒。裁白边时四边各留 12 pt。

理由换回 % 时补换行。译文只要求与原文逐段对应，换回的结果不能依赖译文的换行位置：会话把占位符之后的文字写在同一行时，不补换行这半行会被 TeX 当成注释丢掉。% 加换行在 TeX 里吃掉换行和下一行行首的空白，含义与原文相同。

理由编译由 compile 阶段负责，翻译会话只负责译文。编译失败时才启动修复会话，两类会话的日志分开，便于从修复日志里找出可以写成规则的共性问题。

产物类
class CompileManifest(Manifest):
    status: "ok" | "compile_failed"
    report: CompileReport | None     # 译文的编译统计；判据不满足时也保留
    baseline: CompileReport | None   # 原文的编译统计，取自 precompile 的 manifest
    fix_session: Session | None      # 启动过修复会话才有

术语表

术语表决定哪些词怎样译、哪些词保留原文。用户写的术语表与已学术语表用同一种格式，三个字段都可以省略：

{
  "terms": { "on-policy distillation": "同策略蒸馏" },
  "do_not_translate": ["token", "KV cache", "RL"],
  "style": "给译者的额外要求，例如称呼与语气"
}

四层，后一层覆盖前一层

层文件谁维护会话能否改动
已学$TONGTU_HOME/glossary.learned.json通途可以按本篇调整
全局$TONGTU_HOME/glossary.json用户不能，必须照用
论文级<工作目录>/glossary.json用户不能，必须照用
命令行--glossary FILE用户不能，必须照用

同一个词出现在多层时，取最高一层的条目。style 取最高一层写出的那一段。translate 只把本篇原文里命中的条目放进会话目录：三层用户术语表的命中条目与 style 合成 glossary.fixed.json，已学术语表的命中条目是 glossary.json 的初始内容。

  • 命中按整词匹配，认单复数（词尾的 s 与 es）。全大写的词区分大小写，其余不区分：LLM 命中 LLMs，不命中 vLLM。
  • 一条术语的原词里含有某个不译词时，译法里必须原样保留它：mixed RL training 写作「混合 RL 训练」。
  • 用户术语表里没有命中本篇的词记进 manifest 的 warnings，方便发现拼错的词。

理由用户写的条目必须照用，已学的条目允许会话按本篇调整。同一个英文词在不同领域有不同译法，已学术语表来自以前的论文，不一定适用于这一篇；用户写的条目是明确的要求。

已学术语表怎样增长

translate 的状态为 ok 时，通途读会话结束时的 glossary.json。其中的每个词，已学术语表里还没有时追加进去，已经有时保持原样。

理由已有的条目不被后来的论文改写。已经译出的论文之间保持同一种译法；要改一个译法，由用户把它写进全局术语表，全局层覆盖已学层。

随 PDF 输出的术语表

out/<ID>.glossary.json 是本篇实际使用的全部条目，每个条目带来源，从中可以直接看出这篇论文新学到了哪些术语。整份已学术语表只在 $TONGTU_HOME 下保留一份。

模式与 agent 会话

模式是一组模型与强度的配置。一次运行里的全部 agent 会话用同一个模式，包括翻译会话和两种修复会话。

模式模型强度用途
fastClaude Sonnetlow初步查看译文，费用最低。
smartClaude Opusmedium准备用中文 PDF 代替原文来读

模式的来源依次是命令行的 --mode、config.toml 的 [modes] default，默认值是 smart。translate 的 manifest 记下使用的模式。想用另一个模式重译一篇已经译完的论文，执行 tongtu run PAPER --mode fast --from translate，新译文覆盖旧译文。

会话怎样启动

模型调用层在 tongtu/model/，只有一个入口：在一个目录里启动一次 agent 会话。它不依赖具体产品，运行时由 agentrun 适配。

  1. 把仓库里的 skill/<名字>/ 拷进会话目录的 .skills/<名字>/。skill 有三个：translate、precompile_fix、compile_fix。
  2. 经 agentrun 启动会话：会话目录是工作目录，沙箱开启，带 --no-subagents，模型、强度与时限取自模式。提示词是固定的一句话：读 skill，按它做，只在当前目录里读写。
  3. agentrun 输出的事件逐行写进日志，同时解析出当前动作，交给命令行显示在进度行上。
  4. 返回会话的结束方式。调用方不采用会话自己的结论，总是自己复验结果：translate 重跑校验，precompile 与 compile 重新编译。
class Session(BaseModel):            # 各阶段 manifest 共用
    stop_reason: "finished" | "timeout" | "error"
    model: str                       # "claude-code/claude-opus-5-5"
    effort: str | None
    duration_seconds: float
    usage: Usage | None              # 运行时没有报告用量时为 null

class Usage(BaseModel):
    turns: int                       # agentrun 报告的模型请求次数
    input_tokens: int
    output_tokens: int
    cache_read_tokens: int
    cache_write_tokens: int
    cost_usd: float | None           # 只有 claude-code 有值，取自它原始输出里的费用
    thinking_tokens: int | None      # output_tokens 当中用于思考的部分，只有 claude-code 有值

thinking_tokens 包含在 output_tokens 之内，不另外计费。它与 cost_usd 一样只有 claude-code 有值，取自 claude-code 原始输出的 result 行。agentrun 的结束事件没有这两项数据，所以暂时从原始输出读取。

会话记下的问题

每次 agent 会话结束前，按 skill 的要求在会话目录写一个 notes.json，逐条记下这次遇到的问题、当时的处理办法和预期的解决方法。没有遇到问题时写空列表。会话结束后，通途读这个文件，给每条加上会话的名字，写进 out/<ID>.notes.json，然后删掉会话目录里的那一份。一个会话的条目与它的工作成果同存亡：precompile 与 compile 每次运行都从头做，开始时先去掉自己的修复会话以前写进去的条目；translate 的条目在会话目录被清空时（--from 或 stage translate）去掉，直接采用已有译文时保留，接着已有译文再启动会话时新条目追加在已有条目之后。

通途只收集这些条目。notes.json 读不出来或格式不对时记一条 warning，阶段的状态不受影响。条目不参加判定，也不触发后续动作；之后由人或别的工具读这个文件，决定怎样补充 skill、规则或校验脚本。

class NotesFile(BaseModel):          # out/<ID>.notes.json
    notes: list[Note]

class Note(BaseModel):
    session: "translate" | "precompile_fix" | "compile_fix"   # 由通途填写
    where: str                       # 位置：文件名与行号，或一段原文
    problem: str                     # 遇到了什么问题
    resolution: str                  # 这次会话怎样处理的
    suggestion: str                  # 预期的解决方法：改 skill、规则或校验脚本的哪一处；没有时为空串

供其他程序读取的输出

其他程序通过四种输出读取通途的结果：tongtu status --json、out/<ID>.meta.json、out/<ID>.glossary.json、out/<ID>.notes.json。这四种格式可以修改，修改时读它们的程序一起改。仓库内的 Raycast 插件另外读 logs/<会话>.jsonl，显示会话最近的动作；这个文件是 agentrun 的事件格式。

out/<ID>.meta.json

内容来自 arXiv API 的同一次响应，是所选版本的信息。题目与摘要里的换行压成一个空格。

class PaperMeta(BaseModel):
    arxiv_id: str              # "2412.19437"，不带版本号
    version: int               # 2
    title: str
    authors: list[str]         # 按论文上的顺序
    abstract: str
    primary_category: str      # "cs.CL"
    categories: list[str]
    published: datetime        # 第一个版本的提交时间，UTC
    updated: datetime          # 这个版本的提交时间，UTC
    comment: str | None
    journal_ref: str | None
    doi: str | None
    abs_url: str               # https://arxiv.org/abs/2412.19437v2
    pdf_url: str               # https://arxiv.org/pdf/2412.19437v2

tongtu status PAPER --json

读一次当前状态，向 stdout 输出一个 JSON 对象后立即退出，此外不输出任何文字。需要持续更新的程序按自己的间隔重复调用。工作目录已经确定但还不存在时照常输出，五个阶段都是 absent，退出 0。PAPER 是不带版本号的编号、本地又没有它带版本号的工作目录时，不输出 JSON，错误信息写到 stderr，退出 1，见论文编号与版本。PAPER 不合法时退出 2，错误信息写到 stderr。

class PaperStatus(BaseModel):
    workdir: Path                               # 绝对路径
    arxiv_id: str | None                        # 不带版本号；本地目录时为 null
    version: int | None
    running: bool                               # 运行标记存在，且其中的进程还活着
    pid: int | None
    started_at: datetime | None                 # 运行中时取运行标记里的开始时间，UTC
    mode: str | None                            # 运行中取运行标记，否则取 translate 的 manifest
    stages: list[StageState]                    # 五个阶段，按顺序
    pdf: Path | None                            # 以下四项在文件存在时给出绝对路径
    meta: Path | None
    glossary: Path | None
    notes: Path | None

class StageState(BaseModel):
    name: str
    status: str                                 # manifest 的 status；没有 manifest 时为 "absent"
    outputs_present: bool
    message: str
    warnings: list[str]
    manifest: Path | None

翻译会话运行期间，status 给出 running、开始时间和各阶段的状态，正在运行的是第一个状态为 absent 的阶段。其他程序据此显示「翻译中」与已用时间。会话当前的动作只显示在终端的进度行上。

运行标记

run 与 stage 开始运行阶段前写 <工作目录>/running.json，结束时删除。正常结束、阶段失败、程序异常、Ctrl-C 与 SIGTERM 都在退出前删除它。status 读这个文件，再检查其中的进程是否还在；文件不存在、读不出或进程已经不在时，running 为 false。

class RunMarker(BaseModel):
    pid: PositiveInt
    started_at: datetime       # UTC
    command: "run" | "stage"
    mode: str
