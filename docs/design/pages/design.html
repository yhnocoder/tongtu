通途设计

六个阶段

tongtu run 依次运行六个阶段。每个阶段读上一个阶段的产物，写出自己的产物和一份 manifest。只有 translate 每次都启动 agent 会话；reconstruct 只在重建结果核对不通过时、precompile 与 compile 只在展开或编译失败时各启动一次修复会话。

  1. 1fetch查询版本与论文信息，下载并解包源码；没有 TeX 源码时取 PDF规则
  2. 2reconstruct只有 PDF 时，从 PDF 重建出英文 LaTeX 源码并核对规则；失败时一次修复会话
  3. 3precompile展开成单文件，加入中文排版设置，确认原文能编译规则；失败时一次修复会话
  4. 4mask把公式、图表、代码等不翻译的部分换成占位符规则
  5. 5translate一次会话译出全文，会话外重跑校验agent 会话
  6. 6compile把占位符换回原文，编译中文 PDF规则；失败时一次修复会话

一次成功的运行在 out/ 下写出五个文件，文件名都带论文编号与版本号：

文件内容写出的阶段
<ID>.zh.pdf中文 PDFcompile
<ID>.zh.anchors.json译文每个块在 PDF 上的位置，供阅读器在原文与译文之间按块对照compile
<ID>.meta.json论文信息：题目、作者、摘要、分类、版本、日期fetch
<ID>.glossary.json本篇实际使用的术语表translate
<ID>.notes.json各次 agent 会话记下的问题、处理办法与预期的解决方法，供之后补充 skill 与规则启动过会话的阶段

设计遵守四条原则：

  • 翻译的依据是 LaTeX 源码。有 e-print 源码时翻译源码；只有 PDF 时，先按规则从 PDF 重建出 LaTeX 源码，规则核对不通过时由修复会话补救，核对通过后按同一条流程翻译。通途不在 PDF 页面上直接替换文字。编译能否通过由机器检查。
  • 翻译由 agent 完成，结果是否正确以校验脚本为准。脚本不对翻译过程做细粒度控制。要提高译文质量，就修改提供给模型的信息，即 skill 与术语表。
  • 能用规则处理的问题由规则处理：编译问题由 precompile 的前导区改写规则在编译之前处理，PDF 由 reconstruct 的规则重建。修复会话只在按规则处理之后展开、编译或核对仍然失败时启动，每个阶段最多一次。同一类修复在多篇论文的修复日志里重复出现时，把它写成规则。
  • 论文工作目录不在仓库内。

理由只支持 xelatex 一个引擎。中文排版用 xeCJK；precompile 与 compile 用同一个引擎、同一份前导区，两次编译的差别只剩正文文字，compile 出错时原因只可能在译文。

命令行

tongtu run      PAPER [--mode fast|smart] [--latest] [--from STAGE] [--glossary FILE]... [--workdir DIR] [--dev]
tongtu stage    STAGE PAPER [--mode fast|smart] [--glossary FILE]... [--workdir DIR] [--dev]
tongtu status   PAPER [--json] [--workdir DIR] [--dev]
tongtu list     [--json] [--dev]
tongtu stop     PAPER [--workdir DIR] [--dev]
tongtu info     PAPER [--json] [--refresh] [--zh] [--dev]
tongtu validate SRC DST [--glossary FILE]...
tongtu doctor
tongtu config   [list [--json] | set KEY VALUE [KEY VALUE ...] | open] [--dev]
tongtu          --version

PAPER 是 arXiv 编号、arXiv 链接、本地源码目录或本地 PDF 文件（文件存在且以 %PDF- 开头）。STAGE 取 fetch、reconstruct、precompile、mask、translate、compile 之一。终端输出、manifest 的 message 与 warnings 一律用英文。

选项

选项适用命令作用
--mode fast|smartrun、stage本次运行的 agent 会话用哪个模式，不给时取 config.toml 的 [modes] default。见模式与 agent 会话。
--latestrun向 arXiv 查询最新版本并使用它。见论文编号与版本。
--from STAGErun从这个阶段起重跑，先删掉它及其下游的旧产物。
--glossary FILErun、stage、validate本次运行追加的术语表，可以给多个，靠后的优先。
--workdir DIRrun、stage、status、stop直接指定论文工作目录，代替按 PAPER 推出的默认位置。目录里已有 fetch 的 manifest 时，PAPER 必须是同一篇论文：编号相同，比较时把旧式编号的斜杠换成下划线，所以 hep-th/9901001v1 与目录名 hep-th_9901001v1 都被接受；或者 manifest 记的是本地源码目录，PAPER 是同一个目录，或者是这个目录的名字。PAPER 不带版本号时取 manifest 里的版本；PAPER 写明的版本或 --latest 查到的版本与 manifest 不同时，命令报用法错误，退出码 2。
--devrun、stage、status、list、stop、info、config等于 TONGTU_HOME=~/.tongtu-dev。

run

每个阶段结束后终端输出一行结果，阶段的 message 与 warnings 各占一行，缩进在结果行下方。阶段运行时显示一行进度，只在终端是 tty 时刷新。translate 的进度行显示耗时和会话当前的动作，例如正在读原文、正在写哪个文件、正在运行检查。

示例输出为示意

$ tongtu run 2412.19437 workdir ~/.tongtu/papers/2412.19437v2 mode smart claude-code/claude-opus-5-5 medium stage status summary elapsed ✓ fetch ok v2, tar.gz, 14 tex files 0:00:03 ✓ reconstruct ok source input 0:00:00 ✓ precompile ok 66 pages 0:00:41 ✓ mask ok 183 blocks masked 0:00:00 ✓ translate ok 164 paragraphs, 31 new terms 0:09:55 ✓ compile ok 56 pages, baseline 66 0:00:47

reconstruct 的摘要在有 TeX 源码时是 source input；从 PDF 重建过时写重建结果的页数、单词召回率与阅读顺序，启动过修复会话时加 fixed，例如 16 pages, recall 0.999, order 0.997, fixed。translate 的摘要在有保留英文的段落时写出段数，例如 77 paragraphs, 2 kept in English, 16 new terms；没有时不写这一项。

情形行为退出码
全部阶段成功写出 out/ 下的五个文件。0
某个阶段失败停在出错的阶段，终端输出原因与 manifest 路径。处理后再执行一次同样的命令，从这个阶段接着跑，前面的阶段不重做。1
运行被打断再执行一次，从中断的阶段接着跑。非 0
六个阶段都已完成不做任何事，提示用 --from。0
参数不合法PAPER 无法识别，--latest 与带版本号的编号同时出现，或者 --workdir 里已有的论文与 PAPER 不一致。2

通途不检测输入是否变化。不给 --from 就沿用旧产物。改了输入之后，按下表选择起点：

改了什么从哪个阶段起重跑
src/ 里的源码，或 config.toml 的 [fonts]--from precompile
tongtu/data/environments.json--from mask
任何一层术语表、skill/translate/，或者想换一个模式重译--from translate
config.toml 的 [pdf]--from compile

其余命令

  • stage STAGE PAPER 只运行一个阶段。它先删掉本阶段的旧产物再运行，不改动其他阶段的产物。上游产物不存在时拒绝执行，退出 2。
  • status PAPER 只读，列出每个阶段的状态、产物是否存在和 manifest 路径。它不联网。--json 的格式见供其他程序读取的输出。
  • list 只读，列出 $TONGTU_HOME/papers/ 下的论文，每篇一行，列出目录名、状态、所在阶段和题目，按最近更新的时间从新到旧排列。它不联网，退出 0。哪些目录会被列出、各列怎样取值，见tongtu list --json。
  • stop PAPER 结束正在运行这篇论文的 run 或 stage，按与 status 相同的规则解析工作目录。运行标记无效时输出「<目录名> is not running」，退出 0。否则向运行标记里的进程发 SIGTERM，每 0.1 秒检查一次运行标记，最多等 STOP_WAIT_SECONDS = 10 秒；标记失效后输出「stopped <目录名>」，退出 0；超时仍有效时把目录名与 pid 写到 stderr，退出 1。发信号时进程已经不存在，按已停止处理。进程属于其他用户、无权发信号时，把目录名与 pid 写到 stderr，退出 1。tongtu 收到 SIGTERM 时的处理见运行标记，所以直接用 kill 结束 tongtu 进程与 stop 的效果相同。
  • info PAPER 显示一篇 arXiv 论文的信息，不建立工作目录。PAPER 是 arXiv 编号或链接，带不带版本号都可以；给的是本地源码目录时是用法错误，退出 2。论文信息的来源依次是工作目录里的 out/<ID>.meta.json（只在带版本号时）、arXiv 查询缓存、arXiv，规则见arXiv 查询缓存；--refresh 跳过前两者，直接访问 arXiv 并更新缓存。输出每行一个字段，依次是 paper、title、authors、category（主分类，其余分类放在括号里）、published、updated、comment、journal、doi（后三行只在有值时出现）、url、source，空一行后是标题行 abstract 与缩进两格、按终端宽度折行的摘要；论文信息里有中文摘要（abstract_zh）时，再空一行，输出标题行 abstract (zh) 与同样格式的中文摘要。source 是 arXiv、cache, fetched <N> minutes|hours|days ago（不足 1 小时用分钟，不足 1 天用小时，其余用天）或 working directory。arXiv 上没有这篇论文或请求失败时，stderr 输出一行 cannot get info for <编号>: <原因>，退出 1。--json 的格式见tongtu info PAPER --json。

    --zh 在论文信息还没有中文摘要时，调用聊天接口把 abstract 译成中文，成功后按arXiv 查询缓存的规则保存，再输出；已有中文摘要时直接输出，不调用接口。不带 --zh 时不调用接口。翻译没有成功时（abstract.api_key 为空、配置文件加载失败或调用失败），论文信息照常输出，stderr 输出一行 cannot translate the abstract of <编号>v<N>: <原因>，退出码仍是 0；密钥为空时原因里写明要设置 abstract.api_key。--zh 可以与 --refresh、--json、--dev 同时使用。调用方式见摘要翻译。

  • validate SRC DST 对一对掩码文件运行 translate 判定时使用的同一套校验，逐类输出问题，有问题时退出 1。给了 --glossary 才检查术语。手工修改译文后用它确认。
  • doctor 按 TeX、fonts、config、agentrun、modes 五组逐项检查环境：TeX 工具链（xelatex、latexmk、latexpand，xelatex 一行带 TeX Live 年份）；main、sans、mono 三个字体角色实际配置的文件，没有设置的角色标为未设置；config.toml；agentrun；每个模式引用的运行时与模型（相同的组合只运行一次 agentrun doctor）。每项占一行，通过标 ✓，失败标 ✗，未检查或未设置标 -；失败的项在下面逐行列出原因，agentrun doctor 只列出失败的检查。工具链缺失或字体文件不存在时退出 1。config.toml 不存在不算缺失，这时检查默认的模式。工具链齐全时，退出 3 只在配置文件有错或运行时不可用时出现，这时 fetch、precompile、mask 仍然可以运行。TeX 工具链缺失时，这一行给出当前系统的安装命令：macOS 是 MacTeX，Linux 是 install-tl 的 scheme-full。claude-code 与沙箱工具由 agentrun doctor 报告。
  • agentrun 由通途自动安装。doctor 检查运行时之前，以及每次启动 agent 会话之前，通途先在 PATH 里找 agentrun，再找 ~/.local/bin/agentrun，找到就使用，不比较版本。都没有时，从 agentrun 的 GitHub release 下载 1.0.1 版本里与当前系统、架构对应的可执行文件，保存为 ~/.local/bin/agentrun。下载失败或没有对应的文件时，会话以 error 结束，doctor 把 agentrun 记为缺失并退出 3。
  • config 查看和修改 $TONGTU_HOME/config.toml，有四种用法：
    • tongtu config 打开选单，每行是一个配置项及其当前值，最后一行是 exit。选单只处理上、下方向键与回车。在布尔项或模式名（modes.default）上按回车，列出可选的值供选择；在其余项上按回车，提示输入新值，提示里显示旧值，直接回车表示不改。输入框里没有旧值的文本，不能在旧值上原地修改，只能输入完整的新值。abstract.api_key 例外：提示里不显示旧值，输入不回显，直接回车或只输入空白表示不改；选单不能清除密钥，清除用 tongtu config set abstract.api_key ''。标准输入不是终端时退出 2。
    • tongtu config list 每行列出一个配置项及其当前值。配置文件不存在时列出默认值，不写文件。--json 改为输出一个 JSON 对象，格式见tongtu config list --json。
    • tongtu config set KEY VALUE [KEY VALUE ...] 修改一项或多项。KEY 是 list 列出的键，例如 modes.fast.model。VALUE 先按 TOML 的值解析，解析失败时当作字符串；空字符串表示清除这个可选字段。abstract.api_key 的值不经过 TOML 解析，一律按原文当作字符串，空字符串清除密钥。各组按顺序应用到同一份配置上，全部通过后写一次文件，每个改动的键输出一行「键 = 新值」。参数个数为 0 或奇数、任何一组的键不存在或值不合法时退出 2，不写文件。
    • tongtu config open 输出配置文件的路径并打开它。环境变量 EDITOR 非空时用它打开，否则用系统默认的程序。

    配置文件不存在时，tongtu config 与 open 先写出一份包含全部默认值的文件；set 在默认值上修改，修改成功时写出文件。校验失败时每条错误输出一行，格式是「键: 原因」。配置文件存在但加载失败时，config、list、set 输出错误并退出 1。config 与 set 每次修改都整份重写文件，文件里原有的注释不保留。

论文编号与版本

arXiv 的一篇论文有多个版本，各版本的源码可以不同。通途把「论文编号加版本号」当作一篇论文的标识，记作 <ID>，例如 2412.19437v2。工作目录名与 out/ 下的文件名都用它，所以同一篇论文的不同版本各有一个工作目录，互不覆盖。

命令里的写法使用哪个版本
2412.19437v2v2。
2412.19437本地已有这篇论文带版本号的工作目录时，用其中版本号最大的一个，不联网。本地没有时，run 与 stage fetch 向 arXiv 查询最新版本并使用它，其余命令报错，见下文。
2412.19437 --latest向 arXiv 查询最新版本。本地没有这个版本时新建工作目录从头运行；已有时沿用它。
2412.19437v2 --latest用法错误，退出 2。
arXiv 链接取链接里的编号，带版本号与不带版本号分别按上面的规则处理。
本地源码目录没有版本号，也不写论文信息。工作目录名取源码目录的名字。
本地 PDF 文件没有版本号，不联网，也不写论文信息。工作目录名取文件名去掉 .pdf 后的部分。

查询最新版本时（不带版本号且本地没有工作目录），通途先读 1 天内的 arXiv 查询缓存，缓存无效时才访问 arXiv；--latest 不用缓存，总是访问 arXiv 并更新缓存。缓存的规则见arXiv 查询缓存。

版本要靠查询才能确定时，查询发生在建立工作目录之前，查询结果随后交给 fetch 写论文信息，一次运行只请求一次。这次查询失败时版本无法确定，run 把原因输出到终端并退出 1，不建立工作目录，也不写 manifest。版本已经确定时（命令里写明，或取自本地的目录名），API 请求由 fetch 发出，失败记为 fetch 的 download_failed。status 与 fetch 以外的 stage 不联网，遇到不带版本号的编号又没有 --workdir 时，只按本地已有的带版本号的工作目录解析。本地没有这样的目录时，命令把编号与 papers/ 的路径写到 stderr，提示先运行 tongtu run <编号>，退出 1。v0.1 留下的不带版本号的目录不被识别。

选定的版本没有 TeX 源码时，fetch 取这个版本的 PDF，由 reconstruct 从 PDF 重建源码，见fetch。通途不自动改用别的版本。

理由读者需要确切知道自己读的是哪个版本。版本只在两种情况下确定：命令里写明，或者由通途查询后写进目录名、文件名和论文信息。

arXiv 查询缓存

info、run 与 fetch 阶段用同一套规则取论文信息，结果来源记为 arxiv、cache 或 workdir：

  • 带版本号：这个版本的工作目录里有 out/<ID>.meta.json 时读它；否则读缓存；否则访问 arXiv 并写缓存。
  • 不带版本号：缓存有效时读缓存；否则访问 arXiv 并写缓存。
  • 要求刷新（info --refresh、run --latest）：跳过前两步，直接访问 arXiv 并写缓存。

缓存文件是 $TONGTU_HOME/cache/arxiv/<键>.json。不带版本号的查询，键是规范化后的编号（编号里的 / 换成 _，例如 2611.15404、hep-th_9901001）；带版本号的查询，键是 <编号>v<N>。一次不带版本号的查询访问 arXiv 后，同时写不带版本号和带版本号两个条目。不带版本号的条目在 fetched_at 之后 LATEST_CACHE_SECONDS = 86400 秒内有效，因为哪个版本是最新的会变；带版本号的条目不过期，因为这个版本的题目、摘要与正文不再变；arXiv 的 comment、journal_ref、doi 可以在不出新版本的情况下更新，这三项要更新时用 tongtu info --refresh。缓存文件读不出或校验不通过时按不存在处理。通途不清理缓存。

中文摘要 abstract_zh 属于一个确定的版本。info --zh 把它写进带版本号的条目（条目不存在时新建）；这个版本的工作目录里有 out/<ID>.meta.json 时，同时写回那个文件。三种来源返回的论文信息，abstract_zh 都按它的版本重新取：先取工作目录的 meta.json，没有再取带版本号的条目。访问 arXiv 后重写缓存条目时保留已有的 abstract_zh，所以 --refresh 与 --latest 不清除它；fetch 阶段写出的 meta.json 也带上已有的中文摘要。fetch 阶段本身不调用聊天接口。

    fetched_at: AwareDatetime  # 访问 arXiv 的时间，UTC；不带时区时校验不通过
    meta: PaperMeta

fetch

确定版本，取论文信息，把源码放进 src/，没有源码时取 PDF

做什么
  1. 向 arXiv API 请求论文信息（https://export.arxiv.org/api/query?id_list=<编号>），得到版本号与论文信息，写出 out/<ID>.meta.json。响应是 429 或 503 时等待后重试，最多重试 ARXIV_RETRIES = 4 次：响应带 Retry-After 头且是非负整数秒时，等这么多秒再加 0 到 ARXIV_RETRY_AFTER_EXTRA_SECONDS = 5 之间的随机秒数；否则取 ARXIV_RETRY_WAIT_SECONDS = (10, 30, 60, 120) 中对应的秒数，乘以 ARXIV_RETRY_JITTER = (0.5, 1.5) 范围内的随机系数。每次等待前在终端提示一行，秒数取整显示。加随机是为了让同时运行的几篇错开重试。arXiv 对频繁请求限流，过一会儿就恢复。其他状态码与网络错误立即报错；重试用完仍是 429 或 503 时报错，消息里写明已重试的次数。
  2. 下载这个版本的源码包（https://export.arxiv.org/e-print/<ID>），原始字节写进 build/e-print.bin。
  3. 按文件头判断格式并解包到 src/。格式可以是 tar.gz、tar、gz、单个 tex 或 PDF。tar 里的链接与设备文件不解包。
  4. 判断有没有 TeX 源码。没有 TeX 源码的条件是：下载到的是 PDF（或 gz 解压后是 PDF）；全部 .tex 的字符数少于 1000；源码里有 \includepdf 时少于 5000。没有 TeX 源码时 route 记为 "pdf"，清空 src/，原文 PDF 写到 build/original.pdf：e-print 本身是 PDF 时直接用这份字节，否则下载 https://export.arxiv.org/pdf/<ID>。状态仍是 ok，加一条 warning 写明判定的原因。
  5. PAPER 是本地目录时不联网，把目录内容拷进 src/，不写论文信息。目录里没有 TeX 源码时状态是 empty，message 提示把 PDF 文件作为 PAPER。
  6. PAPER 是本地 PDF 文件时不联网，把文件拷到 build/original.pdf，kind 是 local_pdf，route 是 "pdf"，不写论文信息。

任何非 ok 的状态都把 src/ 清空，只保留 build/e-print.bin 供排查。论文信息文件 out/<ID>.meta.json 在 API 请求成功后已经写出，也保留。

source_missing指定的本地目录不存在；指定的本地 PDF 文件读不出或不以 %PDF- 开头。

reconstruct

只有 PDF 时，从 PDF 重建出英文 LaTeX 源码

做什么

fetch 的 route 是 "tex" 时不做任何事，写 ok，rebuilt 为 false。route 是 "pdf" 时，在重建目录 build/sandbox/reconstruct/ 里依次做：

  1. 规则重建：把 build/original.pdf 拷进重建目录，写出 main.tex、crops/<编号>.pdf（每个截图一个文件）与 regions.json。正文文字、标题、列表、脚注、目录、图注写成 LaTeX；图、表、算法、行间公式、参考文献、作者区从原 PDF 截取矢量区域插入，截取时用两遍 redaction 去掉区域外的内容，区域内的大号数学字形保留；行内公式截成小图，写成 \im{编号}{下沉量}{提示}。提示是这段截图在原文文字层里的字符，只给修复会话参考，不排版。
  2. 编译：与 precompile 用同一条 latexmk 命令。
  3. 核对，见下文。全部通过时跳到第 5 步。
  4. 编译或核对不通过时，在重建目录里启动一次修复会话（skill reconstruct_fix），会话结束后重新编译、重新核对，以这次结果为准。整个阶段只启动一次修复会话。
  5. 打包：所有截图合进一个 crops.pdf，\includegraphics{crops/x.pdf} 改成 {\includegraphics[page=N]{crops.pdf}}，\im 改为按编号取页。保存时去掉重复资源并压缩（garbage=4、deflate，图片重新编码）。打包后再编译一次，页数必须与打包前相同。
  6. 交付：清空 src/，把 main.tex 与 crops.pdf 拷进去。之后的 precompile 把它当普通源码处理。

fetch 的 manifest 是 ok、route 是 "tex"，而 reconstruct 的 manifest 不存在时，run、status 与 list 都把 reconstruct 当作已完成，status 里它的状态是 ok、manifest 为 null。

理由加入 reconstruct 之前跑完的工作目录没有这份 manifest。不这样判定，run 会从 reconstruct 起重跑下游各阶段，整篇重译。

理由PDF 先变成 LaTeX，翻译流程就不区分源码来自 e-print 还是重建，PDF 论文得到同一套校验，不需要第二套翻译流程。

理由打包。每个截图单独一个 PDF 时，一篇报告有上千个文件、十几 MB；合并后去掉重复的字体与资源，中文 PDF 的体积相应减小。外层的花括号避免与 \twocolumn[…] 的可选参数冲突。

理由修复会话只处理规则出错的论文。会话成本高、结果不稳定，日志用来发现可以写成规则的共性问题。会话结束后阶段自己重新编译、重新核对，不采用会话的结论。

核对

以下各项全部满足才算通过：

项目条件
编译有 PDF，页数大于 0。
单词召回率与精确率都不低于 RECALL_MIN = 0.98、PRECISION_MIN = 0.98。
缺字编译日志里的 Missing character 为 0。
阅读顺序不低于 ORDER_MIN = 0.99。
页数比重建页数除以原文页数在 PAGE_RATIO_RANGE = (0.85, 1.20) 之内。

单词召回率与精确率：两份 PDF 各自取文字，拆开连字，行尾的「字母-换行字母」合并为一个词，取所有至少 3 个字母的英文词，转成小写后计数。召回率是多重集交集除以原文词数，精确率是交集除以重建词数。截图里的文字层也计入，截图保留了原文的文字层，所以截错位置会表现为重复或缺失。

阅读顺序：从原文取词时去掉截图区域里的词，以及图注、脚注、页眉页脚与标题区所在的行。从重建结果取词前，重新编译一份去掉图注、脚注、页眉页脚，并用 graphicx 的 draft 选项不嵌入截图的版本。两边都取连续 ORDER_GRAM_WORDS = 6 个词的片段，只保留在两边各出现一次、且在原文全文（包括截图区域）里也只出现一次的片段。按原文顺序排列这些片段在重建结果中的位置，求最长递增子序列。分数是子序列长度除以片段数；没有片段时为 1。去掉图注的那次编译没有产出 PDF 时，阅读顺序也记为 1，并加一条 warning。

截图丢字（不参加判定，只记录）：对每个 \im 截图，比较它的文字层与提示里的字符（NFKC 规范化，去掉空白，按多重集比较）。截图缺了提示里的字符时记一处，写进 crop_lost_glyphs 并加一条 warning。召回率、准确率与阅读顺序只比较三个字母以上的英文单词，截图里缺了根号、上下标这类符号时，这几项看不出来。例如 Computer Modern 的根号挂在基线下方，裁切范围按字体框计算时会把它裁掉。

理由0.98 是试验中正确重建的论文都能达到、而段落错位或漏截时会跌破的值。阅读顺序 0.99 与页数比 0.85–1.20 由用户确认；超出这个页数比时，几乎都是规则把一块内容截错或重复排了。

状态
ok有 TeX 源码（rebuilt 为 false），或者重建结果核对通过并已交付到 src/。
no_text_layer原文 PDF 打不开，或者全文取不到一个英文词。扫描版 PDF 不支持。

precompile

把原文变成一份带中文排版设置、能编译通过的单文件

做什么
  1. 选主文件：src/ 里带 \documentclass 的 .tex。
  2. 用 latexpand 把 \input 与 \include 展开成单文件，有 .bbl 时一并内联。写在其他命令花括号参数里的 \input（例如 \resizebox{…}{!}{\input{fig}}）不展开，原样留给 TeX 在编译时读文件，每处在 manifest 里记一条 warning；裸分组与环境体里的照常展开。

    理由参数里的 \input 不展开。TeX 在执行到这条命令时才读文件；把文件内容内联进参数之后，内容按参数的方式读入，换行变成空格，依赖换行的内容（例如 pgfplots 的内联表格）读不出来，standalone 子文档的导言区也会进入主文件。这类文件里的文字不进入翻译，实际出现的都是图。

  3. 处理注释：整行注释整行删掉；行尾注释删掉文字，只留 %，因为行尾的 % 决定换行处是否留空白。代码环境与 \verb 里的 % 是正文，不改动。
  4. 前导区里取值确定的条件开关只保留生效的分支。
  5. 按 tongtu/preamble.py 的规则改写前导区里只适用于 pdflatex 的写法，再加入 xeCJK 与中文字体设置。行距是 \linespread{1.4}。文档类是 acmart 时，注入块在行距之后把 \ACM@origbaselinestretch 设为新的 \baselinestretch，因为 acmart 在文末检查行距是否被改过，不一致就报错停止编译。注入块为 xelatex 下未定义的 pdfTeX 专有命令（\pdfglyphtounicode、\pdfsuppressptexinfo、\DeclareUnicodeCharacter）提供替身，只在命令未定义时定义，覆盖作者自带的宏包。
  6. 搭编译目录 build/sandbox/tex/：src/ 的完整拷贝，主文件换成展开后的单文件，文件名不变。在其中用 latexmk 编译，通过后记下页数等计数作为基线，PDF 拷出为 build/precompile.pdf。
  7. 展开时缺文件，或者编译不通过时，启动一次修复会话（skill precompile_fix），然后重新展开或编译一次，以这次结果为准。整个阶段只启动一次修复会话。
状态
ok编译退出码为 0，PDF 非空，日志解析出的页数大于 0。

读

mask

把不翻译的部分换成占位符

做什么
  1. 判定每个 LaTeX 环境是否翻译：文内用 \newtheorem 一类命令定义的环境算正文，其余查 tongtu/data/environments.json，查不到的不翻译。
  2. 把不翻译的部分逐块换成 ⟦BLK-n⟧，原文存进 blocks.json。
  3. 把块里需要翻译的文字抽出来：图表的 caption 与写在前导区里的摘要，各换成 ⟦CAP-n⟧，压成单行放在正文里，和正文一起翻译。代码块的 caption 不抽。抽出的文字里的行内公式截图 \im{编号}{下沉量}{提示} 整体换成一个 ⟦BLK-n⟧（类别 math），留在 CAP 行里；正文、脚注与章节标题里的 \im 同样整体遮盖。

    理由\im 的提示是截图在原文文字层里的字符，不排版，只供重建与识别参考；翻译它没有用处，还会让它与截图对不上，并可能破坏其中的花括号与命令。

  4. 往返自检：用 blocks.json 把 masked.tex 还原，结果必须与 precompile.tex 逐字符相同。

translate

一次会话译出全文，会话外重跑校验

做什么
  1. 合并术语表，取出本篇命中的条目。规则见术语表。
  2. 搭会话目录 build/sandbox/translate/。
  3. 经 agentrun 启动一次会话，模型与强度取自本次运行的模式。会话读 .skills/translate/SKILL.md，在目录里写出 zh.tex，并运行 check.py 自查。
  4. 会话结束后，通途在会话目录之外重跑校验：用仓库里的校验脚本，比对 build/masked.tex 与会话写出的 zh.tex。
  5. 校验通过时，把 zh.tex 拷为 build/translated.tex，写出 out/<ID>.glossary.json，把本篇新定的术语并入已学术语表。

校验

校验脚本逐段比对原文与译文，报告五类问题。会话里的 check.py 与通途在会话外运行的是同一套比对。

类别检查什么
结构段落数相同；每段的占位符、控制序列的数量、花括号与 $ 的配对与原文一致。每个 ⟦CAP-n⟧ 位于行首，所在行除原文这一行已有的占位符外没有其他占位符，含 CAP 的段落行数与原文相同：compile 换回图表标题时取走 CAP 所在的整行。不含 CAP 的段落不检查行数。
公式每段的行内公式与原文逐个相同。
章节名三级章节命令的标题与原文逐字相同。
未译一段译文不含中文，却有 6 个以上小写字母开头的英文单词。只含人名、机构名的段落因此不算未译。带保留英文标记的段落不做这项检查。
术语原文命中某条术语的段落，译文里出现对应的译法；不译词按大小写原样保留。原文里紧贴单个连字符的出现不算原文有这个不译词：rank 不译时，只有 low-rank 的段落不要求译文保留 rank。不译词本身含连字符时（KV-cache）照常匹配。\label、\ref、\cite 一类命令参数里的词不计。章节标题不参加未译与术语两项检查。

按内容应当保留原文的段落（模型的原始输出、论文分析的英文例句、逐字引用的原文），由会话在该段落里单独写一行标记，声明这段有意保留英文：

% tongtu: keep-english: <理由>

标记行属于所在的段落，与段落其他行之间没有空行，位置不限；行首允许空白。理由不能为空。校验先从段落里去掉标记行，再做结构、公式、章节名、术语各项检查，因此标记行不算多出的 %。带标记的段落不做未译检查，不计入 paragraphs_translated，记进 manifest 的 kept；源段落本来不需要翻译时同样记入。理由为空时报一条结构问题。标记是 LaTeX 注释，随 zh.tex 原样进入 compile，不产生输出。每个保留英文的段落另记一条 warning，写明它在 zh.tex 里的起始行与理由，终端随其他 warning 一起显示；check.py 的输出同样逐段列出。

理由有些段落按内容应保留原文，检查必须给 agent 一个可以通过、并且让用户看得见的方式。标记写在段落里而不记行号，因为重跑、续跑时段落会被重新检查，行号会随编辑变化，段落本身不会。

会话外的校验使用 build/masked.tex、用户术语表的原始文件，以及会话结束时的 glossary.json。会话改动 en.tex、glossary.fixed.json 或 check.py 都不影响判定。

理由判定放在会话之外。会话目录整体可写，会话自己报告的「检查通过」无法核对；在会话外用原始输入重跑同一套比对，结果只取决于译文本身。

compile

把占位符换回原文，编译出中文 PDF

做什么
  1. 用 blocks.json 把 build/translated.tex 里的 ⟦BLK-n⟧ 与 ⟦CAP-n⟧ 换回原文块，得到中文全文。行尾注释留下的 % 换回之后，如果它后面到行尾之间还有文字，就在 % 后面补一个换行。前导区在 precompile 已经加入中文排版设置，这里不再改动。
  2. 把中文全文写进 precompile 留下的编译目录，覆盖主文件，用同一条 latexmk 命令编译。
  3. 编译不通过时启动一次修复会话（skill compile_fix），然后重新编译一次，以这次结果为准。
  4. 检查出口判据，通过后拷出 out/<ID>.zh.pdf 与 build/zh.tex。
  5. 用 SyncTeX 文件算出 zh.tex 每个块在 PDF 每页上的矩形，写成 out/<ID>.zh.anchors.json。锚点写不出时只记一条 warning，阶段仍是 ok。
  6. [pdf] crop_margins = true 时，用 Ghostscript 量出每页内容的边界，把页边空白裁掉。只改 CropBox，排版、链接与锚点坐标不变。
状态
ok三条出口判据都满足：编译通过；译文页数与原文基线之比在 0.7 到 1.3 之间；启动过修复会话时，修复后的主文件与修复前写入编译目录的中文全文相比，每个控制序列的出现次数相同（tongtu/validation.py 的控制序列比对）。第三条用来发现修复会话为了让编译通过而删掉正文内容。
compile_failed任何一条不满足。这时不写 out/<ID>.zh.pdf 与 build/zh.tex。

常量

页数比的范围是 [0.7, 1.3]，用来发现整章丢失或整章重复。编译超时 600 秒。裁白边时四边各留 12 pt。

理由换回 % 时补换行。译文只要求与原文逐段对应，换回的结果不能依赖译文的换行位置：会话把占位符之后的文字写在同一行时，不补换行这半行会被 TeX 当成注释丢掉。% 加换行在 TeX 里吃掉换行和下一行行首的空白，含义与原文相同。

理由编译由 compile 阶段负责，翻译会话只负责译文。编译失败时才启动修复会话，两类会话的日志分开，便于从修复日志里找出可以写成规则的共性问题。

术语表

术语表决定哪些词怎样译、哪些词保留原文。用户写的术语表与已学术语表用同一种格式，三个字段都可以省略：

{
  "terms": { "on-policy distillation": "同策略蒸馏" },
  "do_not_translate": ["token", "KV cache", "RL"],
  "style": "给译者的额外要求，例如称呼与语气"
}

两个词条去掉大小写与连字符的差别之后，一个等于另一个，或者等于另一个加 s 或 es，就算同一个词：KV cache 与 kv-caches 是同一个词，plan 与 plane 不是。同一个文件里，同一个词的两条记录不同时，这个文件格式不对；两条都是不译词、只是拼写不同时（seq2seq 与 Seq2Seq）两条都保留，因为不译词按大小写原样匹配，两种写法各自有效。同一个词出现在多层时，取最高一层的条目。style 取最高一层写出的那一段。translate 只把本篇原文里命中的条目放进会话目录：三层用户术语表的命中条目与 style 合成 glossary.fixed.json，已学术语表的命中条目是 glossary.json 的初始内容。

  • 命中按整词匹配，认单复数（词尾的 s 与 es）。全大写的词区分大小写，其余不区分：LLM 命中 LLMs，不命中 vLLM。
  • 一条术语的原词里含有某个不译词时，译法里必须原样保留它：mixed RL training 写作「混合 RL 训练」。原词里紧贴单个连字符的出现不算含有这个不译词，因此 rank 不译时，low-rank 可以译作「低秩」。
  • 用户术语表里没有命中本篇的词记进 manifest 的 warnings，方便发现拼错的词。论文级与命令行的术语表每个未命中的词记一条；全局术语表收的是各篇通用的词，大部分不会出现在某一篇里，所以整个文件只记一条，写明共有多少条、其中多少条本篇没有出现，全部出现时不记。

理由用户写的条目必须照用，已学的条目允许会话按本篇调整。同一个英文词在不同领域有不同译法，已学术语表来自以前的论文，不一定适用于这一篇；用户写的条目是明确的要求。

已学术语表怎样增长

translate 的状态为 ok 时，通途读会话结束时的 glossary.json。其中的每个词，已学术语表里还没有时追加进去，已经有时保持原样。

理由已有的条目不被后来的论文改写。已经译出的论文之间保持同一种译法；要改一个译法，由用户把它写进全局术语表，全局层覆盖已学层。

会话怎样启动

模型调用层在 tongtu/model/，只有一个入口：在一个目录里启动一次 agent 会话。它不依赖具体产品，运行时由 agentrun 适配。

  1. 把仓库里的 skill/<名字>/ 拷进会话目录的 .skills/<名字>/。skill 有四个：translate、reconstruct_fix、precompile_fix、compile_fix。
  2. 经 agentrun 启动会话：会话目录是工作目录，沙箱开启，带 --no-subagents，模型、强度与时限取自模式。提示词是固定的一句话：读 skill，按它做，只在当前目录里读写。
  3. agentrun 输出的事件逐行写进日志，同时解析出当前动作，交给命令行显示在进度行上。
  4. 返回会话的结束方式。调用方不采用会话自己的结论，总是自己复验结果：translate 重跑校验，reconstruct 重新编译并核对，precompile 与 compile 重新编译。

会话的 PATH 最前面是一个只放 python3 的目录。translate、precompile_fix 与 compile_fix 的 python3 是指向基础解释器（sys.base_prefix）的符号链接。reconstruct_fix 的 python3 是一个 exec 到运行通途的解释器（sys.executable）的 shell 脚本，因为会话里的脚本要 import pymupdf 与 tongtu，基础解释器里没有这两个包。

理由reconstruct_fix 的 python3 用 shell 脚本，不用符号链接。符号链接会让解释器找不到 venv 的 pyvenv.cfg，导入不到 venv 里的包。

    turns: int                       # agentrun 报告的模型请求次数
    input_tokens: int
    output_tokens: int
    cache_read_tokens: int
    cache_write_tokens: int
    cost_usd: float | None           # 只有 claude-code 有值，取自它原始输出里的费用

thinking_tokens 包含在 output_tokens 之内，不另外计费。它与 cost_usd 一样只有 claude-code 有值，取自 claude-code 原始输出的 result 行。agentrun 的结束事件没有这两项数据，所以暂时从原始输出读取。

摘要翻译

tongtu info --zh 的摘要翻译是 agent 会话之外唯一的模型调用：它直接请求 config.toml 的 [abstract] 指定的 OpenAI 兼容聊天接口（POST <base_url>/chat/completions），一条 system 消息是写在 tongtu/model/chat.py 里的提示词，一条 user 消息是英文摘要。理由是启动一次 agent 会话对一段摘要来说太慢。请求关闭 DeepSeek 的思考模式（"thinking": {"type": "disabled"}）以缩短耗时，这个参数对其他兼容服务是否有效不作保证。超时 ABSTRACT_TIMEOUT_SECONDS = 60，ABSTRACT_TEMPERATURE = 0.2。没有密钥、密钥含空白、控制字符或非 ASCII 字符（不发请求）、网络错误、非 2xx 与响应里取不到文本都是预期内的失败，由 info 报告；其他异常同样只让翻译失败，原因只写异常的类型名。密钥不写进任何日志、错误信息或输出：错误信息里的接口只写主机名，网络错误只写异常的类型名，因为 httpx 的异常文本可能带请求头，base_url 也可能带用户信息。标题不翻译。

会话记下的问题

每次 agent 会话结束前，按 skill 的要求在会话目录写一个 notes.json，逐条记下这次遇到的问题、当时的处理办法和预期的解决方法。没有遇到问题时写空列表。会话结束后，通途读这个文件，给每条加上会话的名字，写进 out/<ID>.notes.json，然后删掉会话目录里的那一份。一个会话的条目与它的工作成果同存亡：precompile 与 compile 每次运行都从头做，开始时先去掉自己的修复会话以前写进去的条目；translate 的条目在会话目录被清空时（--from 或 stage translate）去掉，直接采用已有译文时保留，接着已有译文再启动会话时新条目追加在已有条目之后。

通途只收集这些条目。notes.json 读不出来或格式不对时记一条 warning，阶段的状态不受影响。条目不参加判定，也不触发后续动作；之后由人或别的工具读这个文件，决定怎样补充 skill、规则或校验脚本。

tongtu status PAPER --json

status --json 与 list --json 分工如下：list 回答有哪些论文、各自处于什么状态，只给列表界面需要的概要；status 给出一篇论文的全部详情，包括各阶段的明细、页数、耗时与费用、会话最近的动作。两者的内容不重复，查看单篇论文时调用 status。

读一次当前状态，向 stdout 输出一个 JSON 对象后立即退出，此外不输出任何文字。需要持续更新的程序按自己的间隔重复调用。工作目录已经确定但还不存在时照常输出，六个阶段都是 absent，退出 0。PAPER 是不带版本号的编号、本地又没有它带版本号的工作目录时，不输出 JSON，错误信息写到 stderr，退出 1，见论文编号与版本。PAPER 不合法时退出 2，错误信息写到 stderr。

class PaperState(StrEnum):
    RUNNING = "running"
    OK = "ok"
    FAILED = "failed"
    INTERRUPTED = "interrupted"

state 与 stage 按下表推导，status 与 list 用同一套规则：

state条件stage
running运行标记有效。第一个 manifest 不存在或状态不是 ok 的阶段。
interrupted没有运行，按阶段顺序遇到的第一个非 ok 阶段没有 manifest。这个阶段。
failed没有运行，按阶段顺序遇到的第一个非 ok 阶段有 manifest，状态不是 ok。失败的阶段。
ok没有运行，六个阶段的 manifest 都是 ok。null

manifest 里取不到的字段为 null，不报错。recent_actions 取 stage 对应的会话日志：reconstruct 是 logs/reconstruct-fix.jsonl，precompile 是 logs/precompile-fix.jsonl，translate 是 logs/translate.jsonl，compile 是 logs/compile-fix.jsonl，其余阶段没有会话日志。日志逐行按 JSON 解析，取 type 为 "tool" 且 summary 是字符串的事件，保留最后 RECENT_ACTIONS = 8 条的 summary；解析不了的行跳过，文件不存在时为空列表。

翻译会话运行期间，status 给出 running、开始时间、正在运行的阶段和会话最近的动作。其他程序据此显示「翻译中」、已用时间与当前动作。

运行标记

run 与 stage 开始运行阶段前写 <工作目录>/running.json，结束时删除。正常结束、阶段失败、程序异常、Ctrl-C 与 SIGTERM 都在退出前删除它。status、list 与 stop 读这个文件，再检查其中的进程是否还在，并用 ps -o lstart=（LC_ALL=C）取这个进程的启动时间。运行标记有效要求两条：进程存在，且启动时间不晚于 started_at 加 MARKER_CLOCK_SLACK_SECONDS = 2 秒。文件不存在、读不出、进程已经不在、取不到启动时间或启动时间晚于这个界限时，运行标记无效，running 为 false。

检查启动时间的理由：tongtu 被 SIGKILL 或机器重启后 running.json 留在目录里，其中的 pid 之后可能分给别的进程。写标记的进程一定在写标记之前启动，复用这个 pid 的进程一定在之后启动，所以只比较 pid 会让 status 误报运行中，并让 stop 结束一个无关的进程。ps 的启动时间只精确到秒，因此留 2 秒的余量。

收到 SIGTERM 时，tongtu 先向当前运行中的子进程（agentrun、latexmk、latexpand）各自的进程组发 SIGTERM，再删除运行标记并退出。这些子进程在独立的进程组里启动，tongtu 退出时不会随之结束；不转发信号的话，被停止的论文在后台继续运行 agent 会话，消耗 token，并且会与下一次运行同时写同一个工作目录。

class RunMarker(BaseModel):
    pid: PositiveInt
    started_at: datetime       # UTC
    command: "run" | "stage"
    mode: str

run 与 stage 在写运行标记的同一处写 <工作目录>/last_run.json，记下这次运行的开始时间、命令与模式。每次运行覆盖它，运行结束不删除，--from 的清理也不删除。它让在 translate 及之前中断或失败的论文也能查到上次所用的模式。读不出或校验不通过时按不存在处理。

class RunRecord(BaseModel):
    started_at: datetime       # UTC，与同一次运行的运行标记相同
    command: "run" | "stage"
    mode: str

status 的 mode 按顺序取：有效运行标记的模式；translate manifest 的模式；last_run.json 的模式；都没有时为 null。translate manifest 排在运行记录之前，因为它是产出当前译文的那次翻译所用的模式，之后只重新编译不改变它。
