远程运行命令

命令行只有两条路径：本机原生运行，或调用某个 server 的 REST 接口（前缀 /v1）。示例输出为示意。没有 hosts.toml 时，命令行与现在相同。

01

在哪跑：--on

取值位置谁执行
native本机原生本机 tongtu 进程
hosts.toml 里的名字某个 server，例如 remote（服务器）、local（Mac 上 compose 起的测试 server）那个 server 起论文容器。server 由 compose 启动，命令行不启动也不停止它

不写 --on 时用 hosts.toml 的 default，没有就是 native。native 是保留名。server 连不上时退出 2，提示里带上它的 url。

--dev 是 TONGTU_HOME=~/.tongtu-dev 的简写，换掉整套配置与论文，每次手写。不写时用 ~/.tongtu，新用户直接 uv run tongtu run ID 即可。

hosts.toml

# ~/.tongtu/hosts.toml：release 版与 Raycast 用
default = "remote"               # 不写则 native

[remote]
url   = "https://tongtu.example.com"      # Cloudflare Tunnel 的域名
token = "…"                      # 与服务器 /root/.tongtu/hosts.toml 的 serve_token 相同

# ~/.tongtu-dev/hosts.toml：开发与本机测试用，不设 default
serve_token = "…"                # Mac 上的测试 server 读这一项

[local]
url   = "http://127.0.0.1:8787"
token = "…"                      # 与上面的 serve_token 相同
02

命令在两条路径上的可用性

命令nativeserver（local 或服务器）
run可用可用，PAPER 只能是 arXiv 编号
stage可用退出 2，提示改用 run --from
status、logs、doctor可用可用
stop、pull退出 2（原生运行用 Ctrl-C；文件本来就在本机）可用

选项之间没有互斥。--glossary 文件由 Mac 读取，内容放进请求体。--workdir 只用于 native。

03

SYNOPSIS

tongtu run     PAPER [--from STAGE] [现有选项] [--on WHERE] [--dev]
tongtu stage   STAGE PAPER [现有选项] [--dev]                 只用于 native
tongtu status  [PAPER] [--json] [--since DATE] [--on WHERE] [--dev]
tongtu logs    PAPER [-f] [--on WHERE] [--dev]
tongtu stop    PAPER [--on WHERE] [--dev]
tongtu pull    PAPER [--on WHERE] [--dev]
tongtu doctor  [--on WHERE] [--dev]
tongtu setup   [--dev]
tongtu serve                                                  只在 server 容器里运行

现有选项里的 --ask-model、--ask-effort、--work-model、--work-effort 这个阶段删除，模型只在 config.toml 里配置；setup 的 -i 删除。新增命令：logs、stop、pull、serve。新增选项：--on、--dev、--json、--since、-f。status 的 PAPER 改为可选。

04

COMMANDS

run PAPER
情况行为
native与现在相同，另外写 logs/run.log 与 run.pid。Ctrl-C 中断运行。
serverPOST /runs 后每 2 秒取一次 run.log 的新增部分，显示与原生相同。Ctrl-C 或断线只停止跟随，运行继续。跟随到结束时自动下载到本机 $TONGTU_HOME/papers/ID：成功取 out/，失败取整个目录。
这篇已经在跑退出 2，提示 logs -f 或 stop。
status [PAPER] [--json]
情况行为
给 PAPER与现在相同的阶段表，第一行多出运行状态：running、done、failed、interrupted。
不给 PAPER列出最近两天更新过的论文：编号、运行状态、停在哪个阶段、更新时间，按更新时间倒序。--since DATE 改起点。
--json同样内容输出 JSON，结构与 GET /papers 相同。Raycast 读它。
server读 server 上的论文，不看本机的。
logs PAPER [-f]
情况行为
不加 -f输出 run.log，历次运行之间有抬头行。
-f从最近一次运行的开头输出，跟随到结束，退出码与那次运行相同。断线后从已读到的偏移接着取，不重复输出。
-f 且不在运行输出最近一次运行后立即退出。

logs -f 结束时不自动下载，需要时用 pull。

stop PAPER
停止这篇论文的容器，状态变为 interrupted。再次 run 从中断的阶段接着跑。
pull PAPER
规则与 run 结束时的自动下载相同：done 取 out/，其余取整个目录。覆盖下载到的文件，不删除本机多出的文件。
doctor
情况检查
native与现在相同，加上三种运行时的登录状态与旧路径提示。
server本机检查 url 与 token 能连通，再取 GET /health：server 版本、Docker、镜像、codex 主凭据剩余时间、Claude token、pi 配置。local 另查本机 Docker 是否可用。
serve
在 server 容器里启动 REST 服务，见设计第 06 节。不手动执行。
stage STAGE PAPER
只用于 native，与现在相同。

没有 shell 命令。进现场排查用 docker exec 进 server 容器，命令写在设计第 06 节。

05

中断与断线

发生了什么nativeserver
跟随时按 Ctrl-C中断运行只停止跟随，运行继续，提示 logs -f 与 stop
合盖、断网运行随 Mac 休眠暂停服务器上的运行继续；Mac 测试 server 随 Mac 休眠暂停
服务器重启、容器 OOM不适用状态为 interrupted，再 run 接着跑。server 设了自动重启
server 升级重启不适用正在跑的论文不受影响；跟随中的客户端下一次请求失败就重试
codex token 在运行中途过期codex 自己刷新那次运行 failed，run --from 接着跑
06

EXIT STATUS

码含义
0与现在相同。跟随 server 上的运行时，是那次运行的退出码。
1与现在相同。
2与现在相同，另加：命令不能用于这个位置、这篇已经在跑、server 连不上或 token 不对、Docker 不可用、凭据不齐。
07

EXAMPLES

默认位置是 remote：提交后跟随，成功后自动下载 PDF。

$ tongtu run 2412.19437 on remote · image 0.2.0 · container tongtu-2412.19437 stage status summary elapsed ✓ fetch ok tar.gz, 14 tex files 0:00:02 … ✓ compile ok 12 pages, baseline 12 0:00:47 downloaded out/ → ~/.tongtu/papers/2412.19437/out/2412.19437.zh.pdf

提交后合上电脑出门，回来再接上。

$ tongtu run 2512.02556 --glossary ~/terms/moe.json on remote … ✓ survey ok 29 chunks, 46 terms 0:00:13 connection lost; the run continues on remote follow again: tongtu logs 2512.02556 -f · stop: tongtu stop 2512.02556 （两小时后） $ tongtu status paper run stage updated 2412.19437 done compile 2026-10-01 14:02 2512.02556 done compile 2026-10-01 16:48 $ tongtu pull 2512.02556 downloaded out/ → ~/.tongtu/papers/2512.02556/out/2512.02556.zh.pdf

失败后：看日志，进 server 容器复现，从失败的阶段重跑。

$ tongtu logs 2501.00003 … ✗ precompile precompile_failed 0:03:10 fix session exhausted; latexmk exited with code 12 $ ssh remote_vps docker exec -it -w /root/.tongtu/papers/2501.00003 tongtu-server bash root@tongtu-server:~/.tongtu/papers/2501.00003# latexmk -norc -xelatex build/sandbox/tex/main.tex … root@tongtu-server:~/.tongtu/papers/2501.00003# exit $ tongtu run 2501.00003 --from precompile

发版前在 Mac 上用 Docker 测试：工作树的代码构建在 release 的 env 层之上，数据进 ~/.tongtu-dev。

$ docker compose up -d --build … $ uv run tongtu run 2002.05202 --dev --on local on local · image tongtu:local · container tongtu-2002.05202 … $ docker compose down

Mac 测试 server 没有启动。

$ uv run tongtu run 2002.05202 --dev --on local cannot reach local (http://127.0.0.1:8787) $ echo $? 2

设了默认位置，临时在本机原生跑一篇。

$ tongtu run 2002.05202 --on native workdir ~/.tongtu/papers/2002.05202 …

命令不能用于这个位置。

$ tongtu stage translate 2002.05202 stage runs only natively; on remote use: tongtu run 2002.05202 --from translate $ echo $? 2
