模型调用层

tongtu/model/。流水线里每一处调用模型都经过这一层，只有两个函数：ask 做单次问答（survey 提议术语、translate 的 API 模式逐 chunk 翻译），work 在一棵目录树里启动一次 agent 会话（precompile / compile 的修复、review、translate 的 Agent 模式）。服务商、运行时与各角色的默认模型都在 models.toml。各阶段见 pipeline.html，命令行见 cli.html。

概览

models.toml 的三张表，以及 ask 与 work 各走哪条路。

  • ask 走上面一条路：角色经 provider 指向服务商，用官方 SDK 直接调用它的 API。
  • work 走下面一条路：角色经 runtime 指向运行时，运行时是一条命令模板；运行时可选地经 provider 再指向服务商，work 把服务商的地址与密钥填进命令。

Provider

服务商：一个 API 前缀 + 一个密钥 + 哪个模型走哪种接口。

字段

字段含义
base_url接口前缀的根，chat / responses / messages 都在它下面的 /v1/...
api_key直接写密钥，或留空改用 api_key_env
api_key_env存放密钥的环境变量名
api整个服务商的接口种类，一种接口时不必逐模型列
models[provider.<name>.models] 表：哪个模型走哪种接口

密钥解析

  • 先用 api_key；为空再读 api_key_env 指定的环境变量。两者都拿不到密钥时报错（provider_key）。
  • 密钥写在文件里时，文件权限 0600。

接口判定

  • models 表里有这个模型就用它的接口；没有就用 api；两者都没有就报错（model_api）。
  • 取值只能是 chat / responses / messages，其他值报错。

三种接口，各用官方 SDK

接口API / SDKsystem强度schema
chatOpenAI chat/completions，openai SDKsystem messagereasoning_effortresponse_format
responsesOpenAI responses，openai SDKinstructionsreasoning.effort不支持
messagesAnthropic Messages，anthropic SDKsystemthinking.budget_tokens 档位表（low 1024 / medium 2048 / high 4096）不支持
  • schema：只有 chat 接口支持；另两个接口给了 schema 以 error 返回。
  • messages 接口的 max_tokens：32768。
  • 超时与重试：SDK 超时 300 秒（ASK_TIMEOUT_SECONDS），自动重试 1 次。

谁引用 provider

  • 角色的 provider 字段：API 模式，经 ask。见 Role 卡。
  • 运行时的 provider 字段：一个运行时条目对应一个「工具 × 服务商」组合，work 据此把 {base_url} 与 {api_key} 填进命令模板与 env 表。密钥经 env 表进入子进程环境，不出现在命令行参数里。见 Runtime 卡。

相关命令

  • --ask-model PROVIDER/MODEL：本次换一个服务商与模型做 API 直调，覆盖全部 ask 类角色。
  • tongtu doctor：只检查 [roles] 引用到的服务商与运行时，以及这些运行时条目引用的服务商；服务商检查的是密钥。
  • tongtu setup -i：写出 models.toml 模板，逐个询问要启用的服务商并填入密钥。

Runtime

运行时：一条命令模板。

命令模板

  • Claude Code 与 Codex 的 headless 模式都是「cwd + stdin 进 prompt + 几个参数 + 退出码」，差别只在命令行怎么拼和 skill 放在哪里，因此命令写在配置里。
  • work 的步骤：拷 skill → 拼命令 → 在新进程组里运行 → 超时杀掉整个进程组 → stdout 逐行写入 trace → 按退出码与是否超时给出 stop_reason。

字段

字段含义
command命令模板；{model} {effort} {max_turns} {tmp_dir} 由 work 填入，{tmp_dir} 是 work 为本次会话建的临时目录，会话结束即删
skill_pathskill 目录拷到会话目录的哪里，例如 Claude Code 放 .claude/skills/<role>/
eventsstdout 事件流的格式，stream-json / codex-json；不写则不解析
auth"codex"：用 codex login 的登录凭据，见下「默认运行时 codex」
provider可选，指向 [provider.*]，见 Provider 卡的「谁引用 provider」
env进入子进程环境的表，{api_key} 经它传入

进度行显示当前动作

  • 运行时条目写了 events，work 写 trace 的同时逐行解析出当前动作（工具名加首要参数，例如 Bash: latexmk -xelatex flat.tex），经 report 回调交给调用方。
  • 不写 events 或某行解析不出就不回报；events 取了未知值在加载配置时报错。
  • 解析只用于显示，不影响会话。

默认运行时 codex

  • 默认运行时是 codex，模型 astra、强度 light；这两个别名的解析见 Role 卡。
  • codex 条目保证：写范围限定在会话目录与 work 在其中建的会话临时目录（TMPDIR 指向它，会话结束后删除），断网，不用登录 shell。
  • Codex 没有 max_turns，只用 timeout_seconds 限时。
  • runtime.auth = "codex" 时 work 建一个独立的临时 CODEX_HOME，只链接已有的 auth.json，不加载用户配置、rules、插件与自动 skills 指令；需要先执行 codex login；认证文件不进会话目录与日志。

运行时与服务商的组合

  • 一个运行时条目对应一个「工具 × 服务商」组合，由条目的 provider 字段指定；填入方式见 Provider 卡的「谁引用 provider」。

Role

角色：[roles] 里每个角色用哪个服务商或运行时、哪个模型、什么强度。

字段

字段含义
provider / runtime二选一：provider 走 ask，runtime 走 work。roles.translate 写 provider（API 模式，经 ask）或 runtime（Agent 模式，经 work）二者之一；两种模式的流程见 translate 卡
model模型名
effort强度
timeout_seconds必填
max_turns只在命令模板引用 {max_turns} 时必填
chunk_tokens / chunk_merge_tokens分块配置，写在 roles.translate，对两种模式通用，由 survey 读取，见 survey 卡

别名

  • 模型 astra、强度 light 在调用时解析为 gpt-6-astra、low。
  • 这两个别名由 resolve_role 替换，对所有角色生效，ask 与 work 都解析。

命令行覆盖

  • --ask-model / --ask-effort 覆盖全部 API 直调（ask）类角色。
  • --work-model / --work-effort 覆盖全部 agent 会话（work）类角色。

ask

单次问答，无状态。

ask(role, system, messages, *,
    schema=None, log_path, model=None, effort=None) -> AskOutcome
→ AskOutcome(status: "ok"|"error", text, detail, model)
参数含义
role"translate" | "survey_terms" | …：角色名，在 models.toml 的 [roles] 查到服务商 / 模型 / 强度
system系统提示词
messages[(role, content), …]：第一次只有一条 user；重试续上 assistant + user
schemaJSON Schema，要结构化输出时给；接口的支持情况见 Provider 卡
log_path本次调用的 JSON 日志写到这里
model「服务商/模型」，None 用角色配置；--ask-model 的原字符串
effort同 model，None 用角色配置
AskOutcome.model实际解析的「服务商/模型」；解析失败时为空串

行为

  • 日志：每次调用把请求要素、正文、usage、耗时写成一个 JSON 日志到 log_path。
  • 失败：以返回值表示，不抛异常；写日志失败也算 error。
  • schema 回退：chat 接口的 schema 被服务端以 response_format 拒绝时，退回 json_object 并把 schema 写进 system，日志记 json_object_fallback。
  • messages 接口的强度：只认 low / medium / high，其余以 error 返回。

work

在一棵目录树里启动一次多轮会话。

work(role, workdir, *, trace_path,
     model=None, effort=None, report=None, prompt=None) -> WorkOutcome
→ WorkOutcome(stop_reason: "finished"|"timeout"|"error", detail, model)
参数含义
role"precompile_fix" | "compile_fix" | "review" | "translate"
workdir会话的 cwd，也是工具可写的范围；读取不受限制
trace_path会话的 stdout 逐行写到这里
model「运行时/模型」，None 用角色配置；--work-model 的原字符串
effort同 model
report每解析出一条动作调一次，参数是一行文本；None 不回报。见 Runtime 卡的「进度行」
prompt会话的任务说明，None 用默认 prompt；translate 的 Agent 模式用它指定输入与输出文件
WorkOutcome.model实际解析的「运行时/模型」；解析失败时为空串

默认从角色 skill 文件读取任务

  • 拷贝：work 先把仓库里 skill/<role>/ 整个目录拷进会话目录。
  • 位置：由运行时条目的 skill_path 决定。
  • 叠加：拷贝用 dirs_exist_ok 叠加，不清空目的地。
  • 默认 prompt：「读 skill，按它做；会话目录是当前目录这棵树」。
  • 覆盖：调用方可以用 prompt 参数覆盖。
  • skill 目录里的工具：除了 SKILL.md 还放 agent 要用的工具。review 阶段把 tongtu/validation.py（只依赖标准库，带 main）以 validate.py 拷进会话目录的 skill 目录，agent 运行的是这个文件，不是 tongtu。

stop_reason

  • stop_reason 不含 budget_exhausted：调用方总是自己复验结果，轮数耗尽与其他错误的处理方式相同。
  • max_turns 仍作为参数传给运行时，不从结果里读回。

会话的约束

agent 会话能做什么、不能做什么，以及只认两种运行时的原因。

  1. Bash 不做前缀放行
    • 沙箱内的命令一律放行，沙箱不可用时会话直接失败，角色级放行清单起不了作用。
    • 正确性由调用方在会话目录外重跑校验。
    • Claude Code 运行时另外经 --disallowedTools 禁止编辑 skill 目录，agent 改不了 validate.py，也不能用 > 重定向覆盖它。
    • 默认的 Codex 运行时没有这条限制，会话目录整体可写，validate.py 被改也不影响判定，因为校验在会话目录外重跑。
  2. 操作系统沙箱
    • 运行时自带，不自己写。
    • latexmk -e、xelatex -shell-escape、.latexmkrc 都能执行任意代码，前缀放行拦不住，只能靠沙箱把写范围限制在会话目录、断网。
    • 嵌套容器（例如云端会话）里设环境变量 TONGTU_NESTED_SANDBOX=1，work 给带 sandbox 表的运行时合入 enableWeakerNestedSandbox = true。
  3. 嵌套检查
    • 子进程环境加 TONGTU_DISABLE=1，tongtu 入口看到它立刻以退出码 2 退出。
    • 它只给会话里的 tongtu run 一个明确失败，不防有意绕过；有意绕过需要写会话目录之外的工作目录根、需要出网，第 2 条会让它在第一个阶段失败。
  4. 会话隔离
    • 不加载用户的 hooks / MCP / 插件。
    • 子进程 PATH 收成固定清单（TeX bin 与系统 bin），最前面加一个只含 python3 符号链接的目录，指向 tongtu 自身的基础解释器（sys.base_prefix）。
    • 只链接这一个文件，不把基础解释器的 bin 目录放进 PATH，会话就拿不到装在那里的 tongtu。

只认两种运行时

  • 运行时只认 Claude Code 与 Codex。
  • Codex 不用 .codex/rules 做放行，因为 decision="allow" 的规则会在沙箱外执行；只靠沙箱 -s workspace-write -c approval_policy="never" 把写范围限制在会话目录。
  • opencode 作为运行时没有沙箱，在它有沙箱之前不作为运行时。

models.toml

放在配置目录。完整模板在 tongtu/model/config.py，由 tongtu setup 写出；没有 tongtu config 子命令，文件手动修改。

下面是说明格式用的最小示例，三张表与上面各卡对照。

# 服务商：一个 API 前缀 + 一个密钥 + 哪个模型走哪种接口
# （api 取 chat / responses / messages）
[provider.opencode]
# 接口前缀的根，chat / responses / messages 都在它下面的 /v1/...
base_url    = "https://opencode.ai/zen/go"
# 直接写密钥，或留空改用下面的环境变量
api_key     = ""
api_key_env = "OPENCODE_API_KEY"

[provider.opencode.models]
"deepseek-v4-pro" = "chat"
"deepseek-v4-flash" = "chat"
"gpt-5.6-luna" = "responses"
"qwen3.8-max" = "messages"

[provider.anthropic]
base_url    = "https://api.anthropic.com"
api_key     = ""
api_key_env = "ANTHROPIC_API_KEY"
api         = "messages"          # 整个服务商一种接口时不必逐模型列

# 会话运行时：一条命令模板，{model} {effort} {max_turns} {tmp_dir} 由 work 填入；
# {tmp_dir} 是 work 为本次会话建的临时目录，会话结束即删
[runtime.codex]
auth       = "codex"                     # 用 codex login 的登录凭据
skill_path = ".codex/skills/{role}"      # skill 目录拷到会话目录的哪里
# stdout 事件流的格式，进度行据此解析当前动作；不写则不解析
events     = "codex-json"
command = ["codex", "exec", "--json", "--skip-git-repo-check", "--ephemeral",
           "--ignore-user-config", "--ignore-rules",
           "-s", "workspace-write", "-c", 'approval_policy="never"', …,
           "-m", "{model}", "-c", 'model_reasoning_effort="{effort}"']

# 中文字体，字段含义与取值见 pipeline.html 的 fonts 卡
[fonts]
main = "LXGWWenKai-Light.ttf"

# 角色：翻译写 runtime（Agent）或 provider（API），恰好一个；分块量对两者通用
[roles]
survey_terms   = { provider = "opencode", model = "deepseek-v4-flash", effort = "low" }
translate      = { runtime = "codex", model = "astra", effort = "light", timeout_seconds = 1800,
                   chunk_tokens = 20000, chunk_merge_tokens = 12000 }
review         = { runtime = "codex", model = "astra", effort = "light", timeout_seconds = 3600 }
precompile_fix = { runtime = "codex", model = "astra", effort = "light", timeout_seconds = 1800 }
compile_fix    = { runtime = "codex", model = "astra", effort = "light", timeout_seconds = 1800 }
